# 맛보기 리포트 (운영자 요청 2026-10-16)

> **2026-10-16 방향 변경(taste-v2)**: 맛보기 리포트는 "절반만 공개 + 잠긴 질문 목록"이 아니라 **사주를 읽고 응답으로 나타나는 모습을 풀어 주는 완결된 짧은 글**이 되었다. 네 부분은 **내 성향과 지나온 모습 · 일에서는 · 가까운 관계에서는 · 지금 나에게 필요한 한 가지**이고(지시문 `taste-v2-prompt-0.1`),
> 아래 본문 중 "나는 이런 사람 · 연애 · 일과 돈 · 마음" · "잠긴 목록(`locked.ts`)" · "절반쯤만 공개"는 **taste-v1(이전 방식)** 설명이다. 이미 taste-v1로 받은 글은 저장된 그대로 읽는다(새 글은 한 계정에 한 번이라 다시 받을 수 없다).
> v2의 규칙: 연애는 정확히 3문장 150~300자(무료 샘플의 범위) · 실제 연애의 진행 · 어울리는 사람 · 시기 · 결혼 · 썸 · 고백은 쓰지 않음 · **해 볼 행동은 action 한 곳에서만 한 가지(시점 · 기간 없이)** · 응답 읽어 주기("~라고 답했어요") · 풀이마다 붙는 한계 경고 · **"구매 후 · 심층 리포트에서" 같은 구매 예고 문장 금지** · "~했던 때가 있었을 거예요"는 섹션마다 한 번. 구매 안내는 결과 화면 아래 한곳이다.
> 자세한 설명 · 예시 · 하지 못한 것은 `docs/saju-voice-direction.md`. **v2 지시문으로 실제 AI 글은 아직 한 번도 읽어 보지 못했다(검증되지 않음)** — 대리 작성기가 쓴 서윤 예시 한 편이 첫 시도에 검사를 통과했을 뿐이다.

무료 분석(검사)을 마친 **로그인 회원**이 [맛보기 리포트 받기]를 누르면 AI가 **사주 계산에서 읽은 문구와 내가 직접 고른 실제 응답**을 엮어 짧은 글(나는 이런 사람 · 연애 · 일과 돈 · 마음)을 **한 번만** 써 준다. 구현됨 · **DB 17번 변경이 있어야 동작한다**(없으면 결과 화면에 "준비 중"으로 보이고 다른 화면은 그대로다).

운영자 요청의 뜻: 무료 리포트 · 연애 방이 "테스트 답을 다시 말해 주는 한 줄"이어서 성의 없어 보인다 → *사주아이처럼 자세하게 풀되 50%만 열고 핵심은 유료 리포트에서, 사주만이 아니라 실제 응답 문항도 넣어 예상해서 쓰기, B안(AI가 쓰는 글) · 로그인해야 가능 · 한 계정당 1번.*

## 사용자가 보는 것

| 위치 | 동작 |
| --- | --- |
| 결과 화면(`/results/[id]`) 무료 미리보기 위의 "맛보기 리포트" 구역 | 아직 받지 않았으면 소개 + **[맛보기 리포트 받기]**. 누르면 "미유가 쓰고 있어요…"가 보이고 글이 도착한다(수십 초 걸릴 수 있다). 받은 뒤에는 한 줄 총평 + 네 부분(나는 이런 사람 · 연애 · 일과 돈 · 마음) + **잠긴 목록**(심층 리포트가 답하는 질문) + 구매 버튼 |
| 채팅방 "나를 알아보기" · 연애 방 · 일 · 돈 풀이 | 맛보기 리포트를 받았다면 "나는 어떤 사람?" · "가까운 관계" · "일과 돈" 풀이가 코드 문장 대신 **이 글**을 쓴다(`talk-free.ts`의 `taste`). 잠긴 자리는 여전히 질문뿐이다 |
| 다른 결과에서 이미 받았다면 | "맛보기 리포트는 한 계정에 한 번만 받을 수 있어요" 안내 |
| 심층 리포트를 이미 받은 결과 | 맛보기 대신 안내만("심층 리포트에서 전체 풀이를 볼 수 있어요") |
| AI가 연결돼 있지 않거나 DB 17번 전 | "맛보기 리포트는 아직 준비 중이에요" |

## 무엇을 쓰고 무엇을 쓰지 않나

- **쓰는 것**: 사주에서 읽은 점 + 응답에서 읽은 반응 + 둘이 만나는 지점, 조건형("~일 수 있어요") 해요체, 사람마다 다른 눈길을 끄는 한 줄 제목. **연애 부분은 정확히 3문장 · 150자 이상 · 300자 이하**(운영자 요청 "간단 요약 3줄 150자 이상").
- **쓰지 않는 것(유료 핵심 — `validate.ts`가 검사로 막는다)**: 실제 연애가 어떻게 진행될지 · 나에게 어울리는 사람 · 연애운이 강해지는 시기 · 해 볼 행동 · 결혼 · 썸 · 고백 · 점수 · 퍼센트 · 나이 · 사주 용어 · 설문 말투("문항에서 …라고 답했어요") · 합쇼체. 이 항목들은 잠긴 목록에 질문으로만 나온다(`locked.ts`).
- 길이(한도는 `lib/report/taste/plan.ts` 한 곳): 나는 이런 사람 4~5문장 · 300~560자 / 일과 돈 · 마음 3~4문장 · 170~340자 / 한 줄 총평 8~40자 / 제목 6~30자. 최대 출력 4,000토큰 · 호출 75초 · 전체 150초.
- 근거는 **무료 미리보기가 이미 사용자에게 보여 준 문구**(`talk-free.ts`의 `tasteProfile`)와 **사용자가 직접 고른 뚜렷한 응답**(`tasteAnswersOf` — 보통(3)은 빼고 뚜렷한 답부터 최대 16개)뿐이다. **이름 · 생년월일 원문은 AI에 보내지 않는다.** 점수 숫자도 보내지 않는다.

## 한 계정당 1번 · 동시 요청 · 실패

- 표 `taste_reports`는 **회원 한 명당 한 줄**(`user_id`가 기본 키)이라 한 번만 받는 규칙을 DB가 지킨다.
- 예약 → 쓰기 → 저장: `reserve_taste_report`가 같은 회원의 요청을 한 번에 하나씩 처리하고(동시에 8번 눌러도 1번만 예약, 나머지는 "쓰는 중"), 예약은 5분 안에서만 유효하다(서버가 죽어 남은 예약은 영원히 잠기지 않는다).
- **글을 만들지 못했다면(호출 실패 · 검사에 걸림 · 저장 실패) 예약을 풀어 받은 것으로 세지 않는다.** 검사를 통과한 글만 저장한다(잘못된 글을 보이지 않는다). 검사에 걸리면 이유를 알려 **한 번** 고쳐 쓰게 한다.
- 두 번째 요청은 AI를 부르지 않고 저장된 글을 그대로 돌려준다.
- 하루 AI 예산(`AI_DAILY_BUDGET_KRW`)에 닿으면 새 맛보기만 멈춘다(이미 결제한 리포트는 영향 없다).

## 비용 · 승인 (어림 — 실제로 재지 않았다)

- 한 번의 호출: 지시문 약 2,600자 + 사용자 메시지 약 1,800자(입력 어림 4,400토큰) + 출력 1,300~2,000토큰. 후보 모델의 공식 가격(입력 $2 · 출력 $10 / 100만 토큰, `lib/config/ai-candidates.ts`)과 코드의 기본 환율(1달러 1,600원)로 어림하면 **한 번에 약 35~50원, 최대 출력 · 고쳐 쓰기 1번까지 가면 약 160원**이다. 한국어 토큰 수는 글자 수로 센 어림이고 생각 토큰은 포함하지 않았다.
- 실제 호출은 **운영자가 `.env.local`(또는 Vercel 환경변수)에 승인 금액 · 호출 수 · 기간을 직접 적은 공통 승인(5,000원 · 60회 · 7일 상한)** 안에서만 일어나고, 호출마다 승인 가드(`server/chat.ts`의 `guardedAnthropicModel`)가 확인한다 — 리포트 생성 · 채팅과 **한 장부**다. 호출 기록(`ai_usage`)에는 토큰 수와 비용 어림만 남고 글 내용은 없다.
- 맛보기 한 명이 평생 한 번이므로 회원 수 × 위 비용이 상한이다.

## 확인한 것 · 못 한 것

- **확인한 것**: 모의 AI로 전체 흐름(저장 · 두 번째 요청에 AI 미호출 · 동시 요청 · 실패 시 풀기 · 다른 결과에서 이미 받음 · 예산 · 표 없음), 글 검사(연애 3문장 150자 이상 · 유료 핵심 금지), 맛보기 방의 잠금(잠긴 필드 미노출), DB(실제 Postgres 임시 환경: 동시 8번 1회 예약 · 만료 이어받기 · 본인만 읽기 · 브라우저 쓰기 · 함수 호출 거부 · 32KB 제한 · 탈퇴 때 삭제)를 시험했다.
- **못 한 것**: ① **실제 AI가 쓴 글을 한 번도 읽어 보지 못했다(검증되지 않음)** — 지시문 `taste-v1-prompt-0.1`이 "테스트 답을 다시 말해 주는 글"이 아니라 사주 · 응답을 엮은 글을 쓰는지, 검사를 통과하는지(고쳐 쓰기가 자주 필요한지), 유료 핵심을 새지 않는지는 운영자가 직접 받아 읽어 봐야 안다 ② 실제 Supabase에서 DB 17번을 아직 적용하지 않았다 ③ 응답 근거는 개발용 문항(`dev-example`)이라 "응답에서 읽은 반응"의 질이 문항에 묶여 있다 ④ 사주 문구는 전통 해석을 단순화한 규칙이며 전문가 검토 전이다.

## 운영자가 할 일

1. SQL Editor에서 17번 파일(`supabase/migrations/20261027000000_taste_reports.sql`)을 한 번 실행하고 `check-migrations.sql`에서 17번이 **적용됨**인지 본다([`update-guide.md`](./update-guide.md)). 이 파일은 표 · 함수만 **더하고** 탈퇴 함수에 맛보기 삭제 한 단계를 더한다 — 기존 데이터는 바뀌지 않는다.
2. 실제 AI 연결(`AI_PROVIDER=anthropic` + `ANTHROPIC_API_KEY` + 승인 값)이 이미 되어 있으면 결과 화면에 [맛보기 리포트 받기]가 켜진다. 없으면 "준비 중"으로 보인다.
3. 다시 시험하고 싶을 때(본인 계정만): SQL Editor에서 `delete from public.taste_reports where user_id = '<내 회원 번호>';` — 지우면 다시 한 번 받을 수 있다(회원 번호는 `/my` 또는 `/admin`의 주문 목록에서 확인). 다른 사람의 줄은 지우지 않는다.
4. 받은 글을 읽고 확인할 것: ① 사주 이야기와 내 응답 이야기가 둘 다 들어 있는지 ② 연애 부분이 3문장 · 150자 이상인지 ③ 실제 연애의 진행 · 어울리는 사람 · 시기를 미리 말하지 않았는지 ④ 모든 사람에게 붙을 법한 말로만 되어 있지 않은지.

## 실제 생성 확인 방법 (운영자 요청 2026-10-16 — 이번 한 단계는 맛보기의 실제 생성 확인이 우선이다)

**이 범위는 "무료 맛보기"에만 적용한다.** 연애 부분 3문장, 결혼 · 썸 · 고백 · 연애운이 강해지는 시기 · 해 볼 행동을 쓰지 않는다는 조건은 이 맛보기의 범위이고, 연애 상담방 · 심층 리포트의 연애 풀이에 같은 금지를 확대하지 않는다(검사 `lib/report/taste/validate.ts`는 맛보기 글에만 쓴다).

**이미 코드와 테스트로 확인한 것**(모의 AI, 실제 AI 아님): 저장된 글은 새로고침 · 다시 열기에서 같은 결과로 돌아온다(두 번째 요청은 AI를 부르지 않는다) · 호출 실패 · 검사 실패는 예약을 풀어 받은 것으로 세지 않는다 · 한 계정 1번 · 동시 요청 · 호출마다 사용 기록(모델 이름 · 입력 · 출력 토큰 · 비용 어림 · 결과 · 오류 번호 — 글 · 이름 · 응답은 없다).

**실제 AI로 받아 본 뒤 확인할 것**(아직 하지 못했다 — 운영자가 받아 보면 된다):
1. 연애 부분이 3문장이고 150자 이상인지, 결혼 · 썸 · 고백 이야기와 연애의 실제 진행 · 어울리는 사람 · 시기 · 해 볼 행동이 없는지.
2. 새로고침하거나 결과 화면을 다시 열어도 같은 글이 나오는지(다른 글이 나오면 문제다).
3. 일부러 실패한 경우(예: 승인 금액이 모자란 상태)에도 버튼이 다시 눌리고 "받은 것"으로 세지 않는지.
4. SQL Editor에서 읽기 전용 `supabase/check-taste-usage.sql`을 실행해 호출 하나하나의 **모델 이름 · 입력 · 출력 토큰 · 결과**(ok · invalid=검사에 걸려 고쳐 쓴 것), **재시도(한 번 받기에 호출이 2번이면 한 번 고쳐 쓴 것)**, **저장된 건수 대비 총 생성비**를 본다. 비용은 토큰 수 × 가격표의 어림이고 실제 청구는 Anthropic 콘솔 사용량이 기준이다.

**비용을 읽을 때 주의**: 이 숫자는 **맛보기 한 건의 생성비**일 뿐이다. 심층 리포트 한 건과 채팅 질문 한 번의 원가는 따로 재야 하고(`check-chat-usage.sql`은 리포트 · 맛보기 · 채팅을 나눠 센다), 무료 분석만 받고 구매하지 않는 사람의 맛보기 비용을 구매 한 건에 나눠 얹는 계산도 따로 한다(예: 맛보기 100명 중 5명이 구매하면 구매 한 건당 맛보기 비용은 20배다 — 어림 계산이며 실제 비율은 운영하며 확인).
