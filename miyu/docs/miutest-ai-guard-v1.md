# miutest(테스트 사이트)의 실제 AI 가드 점검과 최소 비활성안 — 2026-10-19

> 운영자 읽기 전용 확인(2026-10-19, 값 · 비밀키는 열지 않음): Vercel 프로젝트 `miutest`(https://miutest.vercel.app, 운영자가 **테스트용 사이트**로 확인)의 환경변수 목록에
> `ANTHROPIC_API_KEY`(Production), `AI_PROVIDER` · `AI_CHAT_PROVIDER` · `AI_APPROVED_KRW` · `AI_APPROVED_CALLS` · `AI_APPROVED_FROM` · `AI_APPROVED_THROUGH`(Production + Preview)가 **이미 등록**돼 있다.
> 그래서 "테스트 사이트니까 실제 AI는 0"이라고 가정하지 않는다. 이 문서는 **코드가 실제로 막는 것 / 막지 못하는 것**을 정리하고, 외부 흐름 QA(로그인 · 생성 · 채팅 · 결제)를 하기 **전에** 필요한 최소 비활성안을 제시한다.
> **이 세션은 값을 읽지 않았고, 키를 지우거나 노출하지 않았으며, 승인 금액 · 호출 수 · 기간을 바꾸지 않았고, 외부 설정을 하나도 바꾸지 않았다.** 아래 비활성안은 운영자가 결정해서 직접 하는 것이다. 추가 AI 호출 금지는 그대로다.

## 1. 코드가 실제 AI 호출을 막는 조건 (모두 코드로 확인)

실제 호출이 일어나려면 **아래가 전부** 참이어야 한다. 하나라도 거짓이면 제공사에 요청이 나가지 않는다.

| # | 조건 | 어디서 | 이 사이트에서 |
| --- | --- | --- | --- |
| 1 | 배포 환경이 **Preview가 아니다**(`VERCEL_ENV`가 `preview`이면 `anthropic`은 무조건 `invalid`) | `lib/config/preview-guard.ts` · `server/env.ts`의 `aiConfig` · `chatAiConfig` | **Preview 범위에 등록된 AI 값은 아무 효과가 없다.** 위험은 **Production 배포(= 작업 브랜치 push로 만들어진 배포)** 에만 있다 |
| 2 | 리포트 · 궁합 · 재생성: `AI_PROVIDER=anthropic` / 채팅 · 맛보기: `AI_CHAT_PROVIDER=anthropic` | `server/env.ts` · `server/chat.ts` · `server/taste.ts` | **값을 아직 모른다** — 이 두 값이 비어 있거나 `anthropic`이 아니면 호출은 0이다 |
| 3 | `ANTHROPIC_API_KEY`가 비어 있지 않다 | `lib/report/ai/live-config.ts` | 이름은 등록돼 있다(Production) |
| 4 | `AI_APPROVED_KRW` · `CALLS` · `FROM` · `THROUGH` **네 값이 모두** 있고 코드 상한 안이다 — **≤ 5,000원 · ≤ 60회 · 기간 ≤ 7일** | `resolveLiveApproval` · `LIVE_TEST_LIMITS`(`lib/config/ai-candidates.ts`) | 이름은 등록돼 있다. 값이 상한을 넘으면 연결되지 않는다 |
| 5 | **호출마다**: 오늘(한국 날짜)이 `FROM ~ THROUGH` 안이다 | `withChatApproval`(`lib/report/chat/approval.ts`) | **`THROUGH`가 오늘(2026-10-19)보다 앞이면 호출은 막힌다.** 아직 모른다 |
| 6 | **호출마다**: (지금까지 쓴 금액 + 이번 호출의 최악 비용) ≤ 승인 금액, 호출 수 < 승인 호출 수. 지금까지의 사용은 **연결된 DB의 `ai_usage`** 에서 센다(읽지 못하면 호출하지 않는다) | `server/live-ai.ts`의 `loadSpend` · `tallyUsage` | ⚠ **연결된 DB가 이전 호출 기록이 없는 새 DB면 "쓴 금액 0"에서 다시 시작한다**(2026-10-15 승인 장부는 운영자 PC의 로컬 DB에 있었다). 상한 자체(≤ 5,000원 · 60회)는 그대로지만 이전 사용액이 합산되지 않는다 |
| 7 | 보조: `AI_MOCK_URL`(`mock-local`) · `AI_BASE_URL`은 **127.0.0.1 / localhost만** | `server/env.ts` · `live-config.ts` | Vercel 서버에는 로컬 주소가 없어서 가짜 AI는 쓸 수 없다 |

**코드가 막지 못하는 것**: 2~6이 모두 참이면(= 운영자가 `anthropic` + 유효한 승인 값을 등록했고 오늘이 승인 기간 안이면) **로그인한 누구나 호출을 일으킬 수 있다.** 별도의 "이 사이트에서는 실제 AI 금지" 스위치는 현재 코드에 없다.

## 2. 이 사이트에서 실제 AI를 부를 수 있는 경로

(조건 1~6이 모두 참일 때)

| 경로 | 누가 · 무엇이 일으키나 | 비고 |
| --- | --- | --- |
| 채팅 자유 질문 | 무료 결과가 있는 로그인 회원이 입력창에 질문(방마다 무료 질문 2~3번) | **돈을 내지 않아도 가능** — 공개 주소면 가입한 누구나 |
| 맛보기 리포트 | 로그인 회원이 [맛보기 리포트 받기](한 계정 한 번) | 채팅과 같은 설정(`AI_CHAT_PROVIDER`) |
| 개인 심층 · 사주 궁합 · 리포트 궁합 생성 | 테스트 결제(토스 테스트 키)를 마친 주문 | 결제 시작은 `MIYU_TEST_OPEN_SALES`가 켜져 있을 때 궁합도 가능 |
| 생성 실패 뒤 다시 만들기 · 고쳐 쓰기 | 고객의 [다시 만들기] · 자동 고쳐 쓰기 1회 | 호출 수에 포함 |
| 정기 점검(Production, 하루 한 번) | `/api/cron/reconcile` → `drainQueuedReports`가 **대기 중인 리포트**를 이어서 만든다 | 사용자 동작 없이도 호출될 수 있다 |
| 관리자 [리포트 다시 만들기] | `/admin` 운영자 | |

호출 한 건의 최악 예약액은 약 650~700원이고 승인 금액이 5,000원이면 최악 기준으로 7건 안팎까지 가드가 허용한다(실제 호출 비용은 이보다 적다 — 지금까지 잰 한 건은 약 280~320원).

## 3. 모르는 것 (운영자 확인 · 키 · 비밀 값은 열지 않아도 된다)

아래는 **비밀이 아닌 값**이다(키는 열 필요 없음). 운영자가 Vercel 화면에서 이름 옆의 값만 읽어 알려 주면 위험의 크기가 정해진다.

1. `AI_PROVIDER`와 `AI_CHAT_PROVIDER`가 `anthropic`인가, 비어 있는가 (Production).
2. `AI_APPROVED_FROM` · `AI_APPROVED_THROUGH` — **오늘(2026-10-19)이 기간 안인가.** 기간 밖이면 코드가 막는다.
3. `AI_APPROVED_KRW` · `CALLS`가 코드 상한(5,000원 · 60회) 이하인가.
4. miutest가 붙은 Supabase가 이전 사용 기록이 있는 DB인가, 새 DB인가(6번 조건).
5. Deployment Protection(주소를 아는 사람이 로그인 없이 열 수 있는가).

## 4. 외부 흐름 QA 전 — 최소 비활성안

원칙: **승인 금액 · 호출 수 · 기간 · 키는 건드리지 않는다.** 실제 AI를 켜는 스위치(provider)만 닫는다.

| 안 | 하는 일 | 효과 | 되돌리기 | 비고 |
| --- | --- | --- | --- | --- |
| **A. 권장 — Production의 `AI_PROVIDER` · `AI_CHAT_PROVIDER`를 비운다** | Vercel → miutest → Settings → Environment Variables에서 **이 두 개의 Production 값만** 빈 값으로(또는 이 두 개만 삭제). 키 · 승인 값 4개는 그대로. 저장 뒤 **다시 배포해야 반영**(이미 만든 배포에는 반영되지 않는다) | 리포트 · 궁합은 개발용 규칙 생성기(비용 0, 글에 모의/개발용 표시), 채팅 · 맛보기는 "준비 중" — **호출 경로 전부 0** | 같은 화면에서 이전 값(`anthropic`)을 다시 입력하고 재배포 | Preview 값은 이미 효과가 없어서 둘 필요 없음(조건 1). **궁합 2종의 결제 · 생성은 AI가 연결되지 않으면 `ai-not-connected`로 막힌다**(`pwa-and-staging-plan-v1.md` 6-5 — 외부 QA에서 궁합 결제 흐름은 시험되지 않는다) |
| B. 승인 기간(`AI_APPROVED_THROUGH`)을 지난 날짜로 | 값 하나 변경 | 5번 조건이 거짓이 되어 호출 0 | 날짜 되돌림 | **승인 값을 건드리지 않는다는 지시와 부딪혀서 권하지 않는다** |
| C. 키를 지우거나 비운다 | `ANTHROPIC_API_KEY` 삭제 | 3번 조건 거짓 | 키를 다시 넣어야 함 | **키를 삭제하지 않는다는 지시와 부딪혀서 하지 않는다** |
| D. 코드로 "기본 닫힘" 스위치 신설 | 실제 AI는 `AI_LIVE_ENABLED=yes`를 **따로** 적은 환경에서만 호출하게 `aiConfig` · `chatAiConfig`에 한 조건을 더한다. 현재 miutest에는 이 값이 없으므로 **다음 자동 배포부터 provider · 승인 값이 있어도 호출 0** | 환경변수를 하나도 바꾸지 않고 안전 쪽이 기본이 된다 | 값을 적으면 다시 열림 | **코드 변경이라 승인이 필요**하다. 운영자 PC(`.env.local`)에서 앱으로 실제 AI를 쓰려면 이 값을 한 줄 더 적어야 한다(스크립트 방식 시험 `run-own-story` 등은 이 스위치와 무관). 이 세션은 승인 전에 구현하지 않았다 |
| E. 접근 제한 | Deployment Protection(All Deployments + Vercel Authentication) | 낯선 사람이 가입 · 질문으로 호출을 일으키는 길을 막는다(운영자 본인의 QA에는 효과 없음) | 설정 되돌림 | A와 함께 쓰면 좋다. 보호가 켜지면 폰에서 Vercel 로그인이 필요하다(`pwa-and-staging-plan-v1.md` 6-3) |
| F. (보조) `/admin`에 AI 연결 상태 한 줄(읽기 전용) | 관리자 화면 "배포 정보"에 `리포트 AI: 개발용 / 모의 / 실제(승인 기간 …)` · `채팅 AI: …`만 표시(키 · 값 없음) | 호출 없이 현재 상태를 눈으로 확인 | 코드 되돌림 | 지금은 production에서 `/setup`이 막혀 있고 `/admin`에 AI 상태가 없어서 값을 열지 않고는 확인할 방법이 없다. **코드 변경이라 승인 전에는 하지 않았다** |

**권고 순서**: ① 운영자가 3장의 값 1~5를 알려 준다 → ② A를 적용하고(필요하면 E) 재배포 → ③ 아래 5장으로 "호출 0"을 **호출 없이** 확인 → ④ 외부 흐름 QA. 장기적으로는 D(+F)를 승인받아 "환경변수를 잘못 넣어도 기본은 닫힘"으로 만드는 것을 권한다.

## 5. 호출 없이 "실제 AI가 꺼졌다"를 확인하는 방법

- **채팅**: 무료 결과가 있는 계정으로 상담방을 열었을 때 입력창이 **"자유롭게 질문하기 · 준비 중"으로 잠겨 있으면** 채팅 AI는 연결되지 않은 것이다(질문을 보내지 않는다). 입력창이 열려 있으면 연결된 것이다 — **그 상태에서 질문을 보내지 않는다.**
- **리포트 생성기**: 확인하려면 주문이 필요해서(결제 → 생성) 호출 위험이 있다. A를 적용했다면 개발용 생성기라 호출은 0이고, 생성된 리포트의 생성기 이름(`/admin/report/<주문번호>`)이 개발용으로 찍힌다. **A를 적용하기 전에는 결제 · 생성 흐름을 시험하지 않는다.**
- **맛보기 리포트 버튼**은 채팅과 같은 설정을 쓴다 — 채팅이 잠겨 있으면 맛보기도 호출되지 않는다.
- 값을 열지 않고 상태를 한 번에 보려면 4장 F가 필요하다(승인 전).

## 6. 외부 흐름 QA 전 체크리스트

- [ ] 3장 값 1~5를 운영자가 확인해 알려 줬다(키는 열지 않았다). → 1번은 8장에서 확인됨(둘 다 비움), 2~4번은 값을 받지 못했다(미확인).
- [x] A(또는 운영자가 정한 다른 안)를 적용하고 **재배포**했다 — 8장(운영자 보고, 이 세션이 확인한 것은 아님).
- [ ] 5장의 방법으로 채팅 입력창이 "준비 중"임을 확인했다(질문 전송 없이).
- [ ] 외부 Supabase를 쓰는 QA는 **DB의 용도 · 연결 격리가 확인되기 전까지 보류**(운영자 결정) — 로컬 모의 QA만 진행한다.
- [ ] 궁합 2종의 결제 · 공동 열람은 AI 연결이 없으면 시험되지 않는다는 것을 알고 있다(`pwa-and-staging-plan-v1.md` 6-5).

## 7. 로컬 모의 QA에는 영향이 없다

로컬 QA는 가짜 AI 서버(`AI_PROVIDER=mock-local`, 127.0.0.1)만 쓴다. 이 서버는 코드가 로컬 주소만 받게 막고 있어서 실제 Anthropic으로 나가지 않으며, 이 세션에서 **실제 AI 호출은 0회**다(승인 6/6 · 누적 4,314.89원 그대로).

- **아닌 것**: 공개 도메인에서 생성 · 채팅 · 결제를 실제로 시험한 결과가 아니다(그런 호출 · DB 접근 0). AI 제공사에 실제로 접속이 일어나지 않는지를 네트워크로 확인한 것도 아니다.
- 이후 푸시도 이 설정을 바꾸지 않는다(provider 값은 코드가 아니라 Vercel 설정이다). **외부 DB migration 적용 · AI 재활성화 · 실결제 · 승인 값 변경은 승인되지 않았다.** 신규 궁합 기능의 실제 유료 품질은 확인할 수 없다(`compat-relationship-v1.md`).
- 남은 위험(4장 E 관련): 보호가 All Deployments가 아니라 Standard라서 stable domain은 누구나 열 수 있다. AI가 꺼져 있으므로 낯선 사람이 AI 비용을 일으키는 길은 닫혀 있지만, 가입 · 분석 저장이 **어느 Supabase에 쌓이는지는 아직 확인하지 못했다**(외부 DB 용도 · 격리 미확인 — 외부 DB를 쓰는 QA는 계속 보류).
