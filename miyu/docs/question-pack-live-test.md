# 질문 3개 묶음 — 실제 환경에서 끝까지 확인하기 (운영자가 한 단계씩)

- 작성: 2026-10-15 · 대상: **질문 3개 묶음 2,500원(부가세 포함, 낱개 없음)**의 결제 → 첫 답변 → 잔여 2회 → 새로고침 · 재로그인 → 실패 시 미차감 → 취소 · 환불 → 중복 클릭 · 동시 질문.
- **가짜 환경에서는 이미 확인했다**(가짜 결제 · 가짜 AI · 임시 DB — 아래 7장). 그것은 **실제 환경의 확인이 아니다.** 이 문서는 운영자님의 **실제 Supabase + 토스 테스트 키 + 카카오 로그인**에서 같은 것을 확인하는 순서다.
- **돈이 나가는 단계는 없다.** 토스 **테스트 키**(`test_…`)의 결제는 실제로 청구되지 않는다. **실제 결제(`PAYMENTS_LIVE_MODE=true` + live 키)는 이 문서에서 하지 않는다** — 11장의 별도 확인 뒤에만, 운영자 승인 후에 한다.
- **키 · 비밀값은 대화에 붙여넣지 않는다.** 아래 값은 모두 `.env.local`(메모장)에 직접 적는다. 값이 필요한 곳에는 "어디에 적는지"만 안내한다.
- 막히면 **그 단계에서 멈추고** 화면(또는 오류번호 `ERR-…`)을 알려 주세요. 계속 눌러 보지 마세요.

## 1. 무료 질문 쓰기 (결제 전 상태 만들기)

1. 시험 계정으로 로그인 → 무료 분석을 끝낸다(연애 방이 무료로 열린다).
2. 연애 상담방에서 **무료 질문 2번**을 쓴다. 두 번째 답이 도착하면 "무료 질문을 모두 썼어요" 안내창이 뜬다.
3. 확인: 안내창에 **가격 · 글자 수 문장이 없고** "질문 3개 구매" 버튼 이야기가 있다. [질문 이어가기]를 누르면 안내창이 닫힌다.

## 2. 결제 이동 화면 (화살표가 아니라 구매 버튼)

1. 입력창 아래에 **[질문 3개 구매 · 2,500원]** 버튼과 그 아래 "구매 후 작성한 질문에 바로 답변하며 1회가 사용돼요 / 남은 2회는 이어서 쓸 수 있어요"가 보인다. **보내기 화살표는 없다.**
2. 질문을 적기 전에는 구매 버튼이 눌리지 않는다. 질문을 적으면 켜진다.
3. 질문을 적고 키보드 **Enter**를 눌러 본다 → **결제 화면으로 가지 않고** 구매 버튼으로 초점만 옮겨진다.
4. 마음이 많이 힘든 글(예: "자살하고 싶다")을 적고 구매 버튼을 눌러 본다 → **결제 화면으로 가지 않고** 상담전화 안내가 대화에 나온다(주문이 만들어지지 않는다). *(안내 번호 109 · 119는 운영자가 출시 전에 직접 확인)*
5. 확인 SQL(읽기만): `supabase\check-cash.sql` — 아직 "충전"이 없어야 한다.

## 3. 결제 승인 → 첫 답변 → 잔여 2회

1. 평범한 질문을 적고 **구매 버튼을 한 번만** 누른다 → 결제 화면. "유료 질문 3개 · 2,500원 · 부가세 포함 · 1개씩 결제하는 방법은 없어요"가 보인다.
2. 토스 **테스트 결제창**에서 테스트 카드로 결제한다(토스 개발자센터의 테스트 카드 안내를 따른다 — 실제 청구 없음).
3. 결제를 마치면 **채팅방으로 돌아와 방금 적은 질문에 자동으로 답**이 온다.
4. 확인:
   - 입력창 안내가 **"결제해 둔 질문 2개가 남아 있어요"**, 보내기 화살표가 다시 보이고 구매 버튼은 없다.
   - MY → **"결제해 둔 질문 2개"**, 결제내역에 "유료 질문 3개 · 2,500원 · 결제 완료 · 테스트 결제".
   - `supabase\check-cash.sql`: 충전 1건(9) · 사용 1건(−3) · 이상 징후 없음.

## 4. 새로고침 · 재로그인 후에도 유지

1. 같은 브라우저에서 새로고침(F5) → 입력창 안내가 여전히 **2개**, 대화가 그대로 이어져 있다.
2. **다른 브라우저(시크릿 창)**에서 같은 계정으로 로그인 → MY에 "결제해 둔 질문 2개", 채팅방 입력창이 **2개**로 보이고 앞의 대화가 보인다.
3. 로그아웃 → 다시 로그인 → 같은 결과.

## 5. 실패 시 미차감 (돈 없이 확인하는 방법)

실제 AI가 일부러 실패하게 만들기는 어렵다. 대신 **승인 가드를 이용**한다(가드가 막으면 Anthropic에 요청 자체가 나가지 않아 **비용이 없고**, 질문은 "답을 받지 못한 것"으로 처리된다).

1. 개발 서버를 끄고(`Ctrl + C`) `.env.local`의 **`AI_APPROVED_CALLS`를 지금까지 쓴 호출 수와 같거나 작은 값**으로 적는다(몇 번 썼는지는 `supabase\check-chat-usage.sql`로 읽기만 해서 센다). 서버를 다시 켠다.
2. 채팅방에서 질문을 보낸다 → "이번에는 답을 만들지 못했어요"가 나오고 **쓴 글이 입력창에 돌아온다.**
3. 확인: 입력창 안내가 **여전히 "결제해 둔 질문 2개"**, MY도 2개, `check-cash.sql`의 사용 건수가 늘지 않았다(되돌림이 있으면 "질문 복구"가 한 줄 보이고 잔액은 그대로).
4. `AI_APPROVED_CALLS`를 원래 값으로 되돌리고 서버를 다시 켠다 → 같은 질문을 다시 보내면 **새 결제 없이** 답이 온다(잔여 2 → 1).

## 6. 중복 클릭 · 중복 결제 · 동시에 질문 두 개

1. **결제 시작 두 번 누르기**: 남은 질문이 0개인 상태(묶음의 질문 3개를 모두 쓴 뒤)에서 질문을 적고 **구매 버튼을 빠르게 두 번** 누른다 → 결제 화면으로 가고, MY 결제내역에 **새 주문이 하나만** 생긴다(대기 주문은 하나).
2. **같은 승인 주소 다시 열기**: 결제를 마친 뒤 브라우저 주소 표시줄의 `…/payments/success?...` 주소를 다시 열어 본다(뒤로 가기도 해 본다) → 질문이 늘지 않는다. `check-cash.sql`의 충전은 여전히 1건.
3. **동시에 질문 두 개**: 남은 질문이 1개인 상태에서, 같은 방을 **두 브라우저 창**에서 열고 서로 다른 질문을 적은 뒤 두 창에서 **거의 동시에** 보낸다 → 한쪽만 답을 받고, 다른 쪽은 "질문 3개에 2,500원이에요…"로 구매를 안내받는다. 잔여는 0, 사용 기록은 한 건만 늘었다.
   - *알아 둘 한계*: 두 창이 서로의 대화를 덮어쓸 수 있어 한쪽 창의 대화 표시가 사라져 보일 수 있다(질문 · 결제 장부는 정확하다). 무료 질문은 **서버가 여러 대로 나뉜 상태에서 동시에 도착하면 1개 더 나갈 수 있다**(결제한 질문은 DB가 정확히 막는다).

## 7. 결제 취소 · 환불

### 7-1. 결제창에서 취소
1. 질문을 적고 구매 → 토스 결제창에서 **취소(닫기)**.
2. 확인: 채팅방으로 돌아오면 **"결제를 마치지 못해서 질문은 보내지 않았어요. 적어 두신 질문은 그대로 두었어요."**, 쓴 글이 입력창에 있다. MY 결제내역은 "결제 취소"이고 청구되지 않는다.

### 7-2. 결제 완료 후 환불 — **전액 취소만 확인한다**
**부분 취소는 하지 마세요.** 지금 미유는 부분 취소를 장부에 반영하지 못한다(정책 확정 뒤 구현 — [`question-pack-policy-proposal.md`](./question-pack-policy-proposal.md) 5장 R1). 부분 취소를 하면 `UNEXPECTED_PARTIAL_CANCELED` 이상 징후만 남고 질문은 그대로 쓸 수 있다.

1. 토스페이먼츠 개발자센터(테스트 모드) → 결제 내역 → 이번 시험 결제를 **전액 취소**한다. *(미유는 환불을 실행하지 않는다 — 운영자가 토스에서 한다.)*
2. 로컬 개발 주소에는 웹훅이 오지 않으므로(웹훅은 배포 뒤 등록), 미유에 반영하려면 `/admin`에서 그 주문을 찾아 **[결제사와 대조해 맞추기]**를 누른다.
3. 확인:
   - 주문이 **"환불 완료"**로 바뀌고 MY 결제내역에도 그렇게 보인다.
   - 남은 질문이 **회수**된다: MY의 "결제해 둔 질문" 영역이 사라지고, 채팅방 입력창은 다시 **구매 버튼** 모드.
   - 이미 쓴 질문 몫은 "모자란 몫"으로 기록된다. `check-cash.sql`의 이상 징후 줄에 "결제 취소 때 이미 써서 회수하지 못한 …"이 나오는 것은 **정상**이다(전액 환불을 받았지만 쓴 질문 값은 되찾지 못한다는 기록).
   - 같은 대조를 다시 눌러도 회수가 한 번만 일어난다.
4. 환불 뒤 **다시 구매**해 본다 → 새 묶음이 들어오고 이전 주문은 "환불 완료"로 그대로 남는다.

## 8. 시험이 끝났을 때

- `.env.local`에서 AI 승인 값(`AI_PROVIDER` · `AI_CHAT_PROVIDER` · `AI_APPROVED_*`)을 지운다([`update-guide.md`](./update-guide.md) 8번 8단계).
- 시험 계정의 남은 질문은 7-2처럼 전액 취소하거나, 질문에 모두 쓰면 된다(탈퇴는 남은 질문이 있으면 막혀 있다 — 임시).
- 결과를 알려 줄 때는 **각 단계의 "확인" 줄에 ○ / ✕**와 막힌 화면(또는 오류번호)만 알려 주면 된다. 키 · 결제 정보는 필요 없다.

## 9. 이 시험으로도 확인되지 않는 것

- **실제 결제(live 키)**: 테스트 키는 카드사 · 정산 · 수수료 · 취소 가능 기간 · 영수증을 실제와 똑같이 보여 주지 않는다.
- **웹훅**: 로컬에서는 오지 않는다. 배포 뒤 토스 개발자센터에 `…/api/webhooks/toss`를 등록하고 취소 알림이 오는지 따로 확인해야 한다.
- **인앱 브라우저(카카오톡 안 브라우저 등)**에서의 결제창 이동 · 복귀.
- **여러 서버에서의 동시 질문**(6장 한계), 오래 쓴 뒤의 성능.
- **환불 신청 · 유효기간 · 탈퇴 흐름**: 정책 확정 전이라 만들지 않았다.

## 10. 합격 기준 (실결제를 열기 전 필수)

모두 ○여야 한다. 하나라도 ✕면 실결제를 열지 않는다.

| # | 항목 |
| --- | --- |
| 1 | 구매 버튼으로만 결제 화면에 간다(화살표 · Enter로는 가지 않는다) |
| 2 | 결제 승인 → 적은 질문에 바로 답 → 잔여 2개 |
| 3 | 새로고침 · 다른 브라우저 재로그인 후에도 잔여 2개 · 대화 유지 |

| 5 | 구매 버튼 두 번 → 주문 하나 · 같은 승인 주소를 다시 열어도 질문이 늘지 않는다 |
| 6 | 동시에 질문 두 개 → 잔여 음수 없음 · 차감 한 번 |
| 7 | 결제창 취소 → 글이 입력창에 돌아오고 청구되지 않는다 |
| 8 | 전액 환불 → "환불 완료" · 남은 질문 회수 · 같은 대조를 반복해도 한 번만 |
| 9 | `check-cash.sql` 이상 징후가 **취소 때 쓴 몫**(정상) 외에는 없다 |
| 10 | **정책 확정**(환불 · 유효기간 · 탈퇴 · 연락처) + 약관의 "출시 전 확정" 문구가 모두 사라졌다 — [`question-pack-policy-proposal.md`](./question-pack-policy-proposal.md) |
| 11 | 법적 검토(선불 성격 · 청약철회 · 표시 문구)를 받았다 — 이 문서로는 확인되지 않는다 |

**1~9는 이 문서로 확인할 수 있고, 10 · 11은 운영자 결정과 전문가 확인이라 이 시험으로 대신할 수 없다.**

## 11. 실결제 소액 확인 (별도 승인 뒤에만 — 지금 하지 않는다)

10장의 합격 기준을 모두 통과한 뒤, 운영자가 직접 **live 키 · `PAYMENTS_LIVE_MODE=true`**로 바꾸고 본인 카드로 2,500원을 결제해 보는 단계다. **클로드는 이 설정을 켜지 않는다.** 하게 되면: 결제 → 답변 → 잔여 확인 → **토스 관리자에서 전액 취소** → 미유에서 환불 반영까지 한 번 해 보고, 끝나면 live 설정을 그대로 유지할지(공개 배포) 되돌릴지는 운영자가 정한다.
