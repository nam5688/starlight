# 장면 질문 — 실제 AI 시험 승인안 (2026-10-16)

**상태: 제안. 유료 호출은 한 번도 하지 않았고, 이 문서의 승인 전에는 하지 않는다.** 아래 비용은 이전 실제 호출 기록과 승인 가드의 계산에서 나온 **어림**이며 직접 재 본 값이 아니다.

## 1. 먼저 확인한 것: 7건은 무엇으로 썼나

7건(X Y Z W H V R)은 **운영 경로가 아니다.** 시험용 대리 작성기(AI 하위 작업자)가 제품 지시문과 같은 근거 목록으로 쓴 글이다. 자세한 비교표는 `docs/scenario-answer-use-check.md` 7장.

| 다른 점 | 영향 |
| --- | --- |
| 실제 서비스 모델 · 생각 강도 · 최대 출력 · 시간 제한이 아니다 | 실제 AI의 실패율 · 비용 · 시간은 모른다 |
| 형식 오류를 내가 따로 돌려 이유를 전달했고 고쳐 쓰기도 X · W 두 번, Y 세 번 | 운영은 한 번만 고쳐 쓰고 반복 표현은 그대로 받아들인다 |
| 응답 사용 검사는 7건을 쓸 때 없었다 | 이제 `extraChecks`로 켤 수 있다(기본은 없음) |
| Z · V는 바탕 글에서 바뀐 곳만 고쳐 쓰게 했다 | **운영에는 없는 방식**이다(운영은 매번 처음부터 쓴다) |

그래서 **운영 경로로 다시 시험**한다. 운영 경로 = `/dev/scenario`의 [실제 AI로 새로 쓰기](운영 리포트와 같은 생성기 `liveReportGenerator` · 같은 승인 가드 · 같은 형식 검사 · 고쳐 쓰기 한 번 + 근거를 장면 질문 근거로 바꿔 끼움 + 응답 사용 검사). 코드는 연결되어 있고 **닫혀 있다**(열려면 아래 3장).

## 2. 승인 요청안 (운영자가 고른다)

입력 묶음 4개: **A+X**(서윤 + 기준 응답) · **A+Y**(서윤 + 다른 응답) · **B+X**(다른 사주 P01 + 기준 응답) · **A+부분**(서윤 + 거의 없었어요 · 선택지 없음 · 미응답이 섞인 응답, H).

| 안 | 생성 | 호출 수 | 어림 비용 | 승인 가드가 잡는 최악 | 범위 |
| --- | --- | --- | --- | --- | --- |
| **1단계(권장)** | 묶음 4개 × 1회 = **4건** | 최소 4 · 어림 4~8 · 상한 10 | 약 1,400~1,600원(건당 340~400원 어림), 고쳐 쓰기가 모두 한 번씩 들어가면 약 2,800원 | 8회 × 541원 = **4,330원** | 사람이 읽고 검사 결과와 대조 |
| 12건 한 번에(제안하신 안) | 묶음 4개 × 3회 = **12건** | 최소 12 · 어림 12~24 · 상한 26 | 약 4,100~4,800원, 모두 고쳐 쓰기면 약 8,400원 | 24회 × 541원 = **12,990원** | 같은 입력의 독립 반복 비교 |

- **12건은 한 번에 승인할 수 없다.** 코드의 승인 상한이 5,000원 · 60회 · 7일(`LIVE_TEST_LIMITS`)이고 가드는 호출 전에 최악 비용(한 번 약 541원)을 미리 잡아 남은 금액이 그 아래면 호출하지 않는다 — 5,000원이면 한 번에 9회까지만 보장된다. 상한을 올리는 것은 코드 변경이라 운영자 결정이다.
- **권장**: 1단계 4건(승인 5,000원 · 10회 · 3일)을 먼저 하고, 결과를 읽은 뒤 2단계(묶음 4개 × 2회 더 = 8건)를 **따로** 승인한다. 2단계는 어림 2,700~3,200원이지만 최악 계산 때문에 4건씩 둘로 나누거나 상한을 올려야 한다.
- 건당 비용의 근거: 이전 실제 호출에서 리포트 한 건이 약 305~333원(고쳐 쓰기 1회 포함)이었다. 이번에는 지시문 0.11과 장면 근거(약 4,400자)가 더해져 입력이 약 10~20% 길다고 어림했다(입력 어림 28,000자 ≈ 21,000토큰, 직접 잰 값 아님). 환율 1,600원 · 여유율 1.1 가정.
- 승인 시작일을 오늘로 적으면 오늘 이전의 사용 기록은 합계에 들어가지 않는다.

## 3. 승인하시면 (운영자가 PowerShell로)

1. `miyu` 폴더의 `.env.local`을 메모장으로 연다(키는 이미 있으면 그대로 두고, **대화에 붙여 넣지 않는다**).
2. 아래 줄을 직접 적거나 고친다(숫자 · 날짜는 승인한 값으로).

```
AI_PROVIDER=anthropic
AI_APPROVED_KRW=5000
AI_APPROVED_CALLS=10
AI_APPROVED_FROM=2026-10-16
AI_APPROVED_THROUGH=2026-10-18
DEV_SCENARIO_LIVE=yes
```

3. `npm run dev` → `http://localhost:3000/dev/scenario`. [실제 AI로 새로 쓰기]가 열려 있다. 누르면 한 번 더 확인한다.
4. 시험이 끝나면 `DEV_SCENARIO_LIVE=yes`를 지운다(다른 일반 리포트 생성에는 영향이 없지만 이 화면의 실제 호출을 닫는다).
5. 사용 기록은 토큰 수와 비용 어림만 남는다(글은 남지 않는다). 읽기 전용 `supabase/check-chat-usage.sql`로 호출 수 · 비용을 확인한다.

## 4. 무엇을 보고 판단하나 (글자 겹침은 쓰지 않는다)

글자 겹침은 같은 입력을 독립으로 다시 써도 0.00~0.10이라 "응답이 바꾼 차이"를 가르지 못한다(비교 문서 발견 7). 판단은 해석과 근거로 한다.

1. **지어내지 않았나(통과 · 실패)** — 코드 검사(ECHO · INVENTED · UNCITED) + 의미 검토(의미 검토 호출은 비용이라 별도 승인, 지금은 사람이 읽는다). 한 건이라도 실패면 지시문 · 검사를 고치고 다시 한다.
2. **같은 입력의 독립 생성끼리** — 주제 블록마다 ① 어느 장면 근거를 썼나(`sceneCitations`) ② 중심이 된 사주 근거 ③ 붙이면 안 되는 해석이 나왔나 ④ "부담이 어디에 쌓인다 · 어떤 조건에서 달라진다"는 핵심 결론이 같은가 — 사람이 표로 비교한다.
3. **입력이 달라졌을 때** — A+X와 A+Y에서 응답이 달라진 구분의 풀이가 달라졌나, A+X와 B+X에서 사주 쪽 중심이 달라졌나.
4. **A+부분** — 읽지 못한 구분의 장면 행동을 사실처럼 쓴 곳이 0건인가, "자료 없음" 문장이 0건인가.
5. **새로 알게 해 주나(별도 기준)** — 제목이 풀이의 결론인가, 답을 나열 · 요약한 제목은 없는가, 얼버무린 양자택일은 없는가.

부분만 고쳐 쓰는 시험(Z · V 방식)은 운영에 없는 방식이라 **처음부터 쓰는 시험과 따로** 한다. 운영이 "응답을 바꾸면 리포트를 새로 쓴다"로 정해지면 필요 없다.

## 5. 이 시험이 알려 주지 못하는 것

- 실제 사람이 글에서 "내 이야기"로 느끼는지(인지 인터뷰 전).
- 12건은 가상 인물 2명 · 응답 조합 몇 개다.
- 의미 검토 판정의 일치도.
- 사주 해석 규칙은 전문가 검토 전이다.
