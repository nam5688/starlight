# 미유 성향 질문 출처 점검 (2026-10-15)

운영자 요청: 현재 자체 문항 · 채점 · 해석에 TCI 등 기존 검사의 문항이나 **구조**를 그대로 가져온 부분이 있는지 출처를 점검하고, 단순히 이름을 바꾸지 말고, 이용 허락이 불분명한 자료는 제외하고, 미유가 알아볼 **생활 행동**을 기준으로 독립적인 문항과 채점 근거를 설계해 개발 기록을 남긴다.

이 문서는 **법률 판단이 아니다.** 법에 걸린다고 확인된 것도, 걸리지 않는다고 확인된 것도 없다. 아래는 코드와 문서를 읽고 센 사실이다.

## 1. 기준 (운영자가 정리한 것)

- 자체 기질 · 성격 검사를 만드는 것 자체가 금지는 아니다. 핵심은 **독립적으로 개발했는지, 기존 검사를 가져왔는지**다.
- "자체 개발"이라는 이름만 붙이거나 문장만 바꾼다고 해결되지 않는다. "진단이 아닙니다" 문구도 무단 이용을 해결하지 않는다.
- TCI 문항 · 채점표 · 규준 · 해석 문장을 복사하거나 변형하지 않는다. 외부 척도는 이용 허락을 확인한다. 공개 자료라고 전부 상업적으로 쓸 수 있는 것은 아니다.
- 실제로 확인한 범위만 안내한다. 검증 전에는 공식 검사 · 임상 진단 · 정확도 보장을 말하지 않는다.

## 2. 무엇을 어떻게 점검했나

| 점검 | 한 일 |
| --- | --- |
| 저장소 안의 외부 자료 | 외부 검사의 문항 · 번역문 · 채점표 · 응답 데이터가 들어 있는 폴더 · 파일이 있는지 찾았다(`external-data/`는 없고, `pilot-data/`에는 AI 비교 결과만 있다. 두 폴더는 저장소에 올라가지 않는다). 코드에서 TCI · Cloninger · ECR · MBTI 낱말이 나오는 곳을 모두 열어 "가져오지 않았다"는 설명 · 비교 · 금지 표현인지 읽었다 |
| 문항 문장 | 화면에 연결된 22문항, 초안 0.1 · 0.2의 30문항, 보강 후보 9문항, 심화 초안 36문항의 문장을 읽었다 |
| 영역 · 방향의 구성 | 영역을 어떤 틀로 나눴는지(방향 수 · 묶음 · 이름의 뜻)를 기존 이론과 견주어 읽었다 |
| 채점 · 해석 | 점수 환산 · 읽는 규칙 · 대표 경향 이름이 외부 채점표 · 유형 이름을 쓰는지 읽었다 |
| 데이터 | `docs/data-sources.md`의 이용 조건 확인 기록과 대조했다 |

**하지 못한 점검**: 공식 검사의 문항 원문을 가지고 있지 않아 문장을 하나씩 **대조하지 못했다.** 그래서 "닮은 문장이 없다"는 것은 확인한 사실이 아니라, 저장소에 원문이 없고 문장을 직접 썼다는 개발 과정에 대한 설명일 뿐이다. 문항 초안은 AI 도구(Claude)의 도움으로 썼는데, AI가 학습한 자료와 닮은 표현이 섞였는지는 확인할 방법이 없다.

## 3. 점검 결과

### 3-1. 문항 문장 · 응답 형식 · 채점표 · 규준 · 데이터

| 항목 | 결과 |
| --- | --- |
| 문항 문장 | 외부 검사 문항을 복사하거나 문구만 바꾼 흔적은 **찾지 못했다**(원문과 대조하지는 못했다 — 위). 직접 쓴 문장이다 |
| 응답 형식 | 5단계 동의 척도(화면 22문항) · 장면 + 선택지 4개(초안) — 일반적인 형식이며 특정 검사의 형식을 가져온 것이 아니다 |
| 채점표 · 규준 | 외부 채점표 · 규준을 쓰지 않았다. 점수는 응답을 0~100으로 옮긴 값이고(정문항 · 반대 방향 문항, 가운데에서 20 이상이면 뚜렷한 방향) 백분위 · 정확도가 아니다 |
| 해석 문장 · 유형 이름 | 대표 경향 4유형 이름(안정지향형 · 확인추구형 · 거리유지형 · 탐색지향형)과 12유형 설계안 이름은 미유가 직접 지었다. MBTI 16유형 이름 · 네 글자 코드 · TCI의 유형 이름을 쓰지 않는다(이번에 화면의 네 글자 코드 · 유형론 용어도 없앴다) |
| 외부 데이터 | IPIP-NEO는 하위 영역 **이름**만 개발 문서의 개념 비교에 인용했고(`assessment-ipip-review.md`) 문항 문구는 쓰지 않았다. OpenPsychometrics 응답 데이터는 이용 조건 문구가 없어 내려받지 않았다 |

### 3-2. 구조: **닮았다** — 이름을 바꿔 해결되는 문제가 아니다

문장은 직접 썼지만, 영역을 **나눈 틀**이 기존 이론의 틀과 닮아 있다. 숨기지 않고 적는다.

| 미유의 구성 | 닮은 기존 틀(일반적으로 알려진 연구 · 검사 구조) | 어디에 있나 | 점검 |
| --- | --- | --- | --- |
| 화면의 "평소 행동 방식" 4방향(에너지를 채우는 방식 · 정보를 받아들이는 방식 · 판단하는 기준 · 생활을 꾸리는 방식) | 널리 알려진 성격 유형론의 네 쌍 | `modules/mbti.ts` (id는 `mbti` — 저장된 기록과 맞추려고 그대로 둔 내부 이름) | 이전에 "MBTI 성향" 이름과 `E/I` 같은 글자 코드, 외향 · 내향 · 감각 · 직관 · 사고 · 감정 · 판단 · 인식 용어를 썼다 → **이번에 이름 · 코드 · 용어를 없앴다.** 4방향 구성 자체는 남아 있다 |
| 화면의 "기질" 4방향(새로움 · 신중함 · 타인 반응 민감도 · 지속성) | 기질을 네 가지로 나누는 기존 모델(자극 추구 · 위험 회피 · 보상 의존 · 인내력) — 이름 · 순서 · 뜻이 대응한다 | `modules/temperament.ts` | 이름만 쉬운 말로 바꾼 것이라 **독립이 아니다.** 개발용 예시로만 두고 교체 대상이다 |
| 화면의 "관계(애착)" 2방향(관계 불안 · 거리 두기) | 성인 애착 연구의 두 차원(불안 · 회피) | `modules/relationship.ts` | 대응한다. 교체 대상 |
| 초안 0.2의 13관점(기질 5 · 성격 4 · 가까운 관계 4) | 기질 · 성격으로 나누고 관계를 따로 두는 구성 | `drafts/situational-draft.ts` | 대응한다. 화면에 연결하지 않았다 |
| 12유형 설계안의 7방향(새로움 · 대비 · 반응 민감 · 지속 · 방향 · 협력 · 의미) | 기질 4 + 성격 3으로 나누는 모델의 구성(의미 · 이유 중시는 자기초월 쪽에 가깝다) | `tendency-v2.ts` | 대응한다. 화면에 연결하지 않았다 |
| 심화 설계안의 7영역 25항목 | 같은 7방향의 세부 항목 | `drafts/deep-design.ts` | 대응한다("자기초월은 이번 설계에서 뺀다"는 문장 자체가 기존 모델의 구성을 의식한 흔적이다). 화면에 연결하지 않았다 |

정리: **문장 · 채점표 · 규준 · 유형 이름은 가져오지 않았지만, 방향을 나눈 구성은 기존 이론과 닮았다.** 이 닮음이 문제가 되는지는 판단하지 않았고 판단할 수도 없다(법률 판단). 다만 "자체 개발"이라는 이름 · 문구로 독립이 되지 않는다는 운영자의 기준에 비추어, 닮은 구성은 **독립 설계로 교체**하고 그때까지 개발용 예시로만 둔다.

## 4. 이번에 한 일

| 일 | 내용 |
| --- | --- |
| 이름 · 코드 정리 | 화면의 "MBTI 성향" → "평소 행동 방식", 네 글자 코드(`E/I` 등) · 유형론 용어 제거, 문항 정의에서 `lowCode`/`highCode` 삭제. 본인이 입력한 MBTI는 참고값으로 따로 보관하고 이번 응답과 비교하거나 유형으로 바꾸지 않는다 |
| 사실과 다른 안내 바로잡기 | 홈의 "상황형 질문에 직접 답한 내용"은 화면의 22문항에는 맞지 않아(동의 척도 문항이다) "미유가 직접 만든 질문"으로 고쳤다 |
| 표시 | 검사 화면에 "미유 성향 질문 · 개발용 예시"를 표시하고 안내 페이지로 가는 링크를 둔다 |
| 공개 페이지 | `/assessment-basis` "미유 성향 질문은 어떻게 만들었나요?" — 어떤 성향을 보는지 · 어떻게 개발했는지 · 참고 자료와 이용 허락 범위 · 확인한 것과 못 한 것 · 검사 버전과 수정일. **하지 않은 전문가 검토 · 검증은 했다고 쓰지 않았다.** 문항별 기록은 공개하지 않고 `assessment-item-records.md`(내부)에 둔다 |
| 개발 기록 | `lib/assessment/provenance.ts`(문항별 기록 · 공개 요약) + 테스트 — 화면에 연결된 문항마다 기록이 있는지, 하지 않은 확인을 했다고 쓰지 않았는지 막는다. 문항을 쓸 당시의 메모는 없어서 기록은 2026-10-15에 문장을 보고 다시 정리한 것이라고 적었다 |
| 독립 설계 초안 | `lib/assessment/drafts/life-behavior-v1.ts` · `assessment-life-behavior-v1.md` — 이론의 틀이 아니라 생활 장면 12개(계획이 바뀔 때 · 시작하는 방식 · 마무리하는 방식 · 갈등에서 의견을 말할 때 등)에서 영역을 정하고, 지난 한두 달 행동의 빈도를 묻고, 문항마다 채점 방향과 이유를 적었다. **화면에는 연결하지 않았다** |
| 구조가 닮은 초안에 표시 | `tendency-v2.ts` · `situational-draft.ts` · `deep-design.ts`의 머리말에 "구성이 기존 이론과 닮았고 교체 대상"이라고 적었다 |

## 5. 제외한 것 · 보류한 것

| 자료 | 처리 |
| --- | --- |

| IPIP-NEO 문항 문구 · 한국어 번역본 | 쓰지 않았다(공식 안내 원문을 열람하지 못했고 번역본은 번역자 권리가 따로 있을 수 있다). 하위 영역 이름만 개념 비교에 인용 |
| OpenPsychometrics 응답 데이터 | 이용 조건 문구가 없어 내려받지 않았다 |
| 독립 설계와 앞선 초안의 **일상 주제 겹침** | 갈등 · 거절 · 마음 표현 · 갈등 뒤 회복 · 혼자 시간 · 연락 확인 · 새로운 시도 등은 같은 일상 주제를 다룬다(표는 `assessment-life-behavior-v1.md` 6장). 문장 · 응답 형식 · 채점표는 새로 썼으나, 주제 겹침 자체는 숨기지 않는다 |

## 6. 검사 저작권 전문가에게 물을 것 (운영자 확인 · 미유는 답하지 않는다)

운영자 요청: TCI와 매우 비슷한 검사를 만들 계획이라면 제작 전에 검사 저작권을 다루는 전문가에게 **구체적인 설계안**을 검토받는 것이 좋다. 설계안은 이 문서 + `assessment-life-behavior-v1.md`(영역 · 문항 · 채점 규칙) + `assessment-item-records.md`(지금 화면 문항의 기록)이다.

1. 방향을 나눈 구성이 기존 검사와 닮은 것이 문제가 되는가 — 지금 화면의 구성(4 · 4 · 2)과 독립 설계(생활 장면 12개)를 각각.
2. 영역 이름에 "기질 · 성격 · 애착"이라는 일반 낱말을 쓰는 것, "MBTI"라는 말로 사용자가 입력한 값을 표시하는 것의 상표 범위.
3. 문항 문장이 공식 검사 문항과 닮았는지 대조하는 방법(원문 열람 방법 · 대조 범위).
4. 초안을 AI 도구의 도움으로 쓴 사실을 개발 기록에 어떻게 남기고 관리할지.
5. 공개 페이지(`/assessment-basis`)의 문구가 적절한지 — 미유는 이 페이지가 법적 안전을 보장한다고 쓰지 않았다.

## 7. 남은 결정 · 다음 단계

- 화면의 22문항은 **독립 설계로 바꾸기 전까지 개발용 예시**이며 정식 검사로 쓰지 않는다 (`docs/launch-checklist.md` 미완료 항목).
- 순서: 독립 설계 문항 → 시범 인터뷰(문항이 의도한 뜻으로 읽히는지) → 전문가 검토(운영자) → 화면 교체 · 개발 기록과 공개 페이지 갱신.
- 시뮬레이션 숫자를 맞추려고 문항을 고치지 않는다. 신뢰도 · 타당도 · 정확도는 확인하지 못했다.
