# 실제 AI 시험 실행 안내 (A안 · 운영자 PC에서 한 건씩) — 2026-10-17

> **이 문서는 운영자가 승인한 A안(`real-ai-approval-proposal.md`의 선택지 A)을 실제로 돌리는 순서다.** 클라우드 세션(Claude Code)에는 `ANTHROPIC_API_KEY`가 없고 키를 대화에 받지도 않는다 — 실제 호출은 **운영자 PC에서 운영자가 `.env.local`에 키를 직접 적고** 아래 명령으로 한다. 호출 전에는 코드(승인 가드)가 모델 · 승인 총액 · 호출 수 · 한 번 상한을 다시 확인하고, 어기면 **제공사에 요청을 보내지 않고** 멈춘다.

## 1. ⚠ 실행 전에 풀어야 할 것 — 상한이 최악 비용보다 미세하게 낮다 (운영자 확인 대기)

호출 없는 드라이런(`--execute` 없이)이 **지금 코드에서** 보여 준 것:

| 시험 | 운영자가 승인한 1회 상한 | 지금 입력으로 센 "재작성까지 가는 최악" | 드라이런 결과 |
| --- | --- | --- | --- |
| ① 개인 | 1,234.03원 | 1,234.03원을 **0.01원 미만으로** 넘음(표시는 1,234.03원) | **실행 거절**("상한을 넘습니다") |
| ② 사주 궁합 | 635원 | 634.99원 | 통과 |
| ③ 리포트 궁합 | 680원 | **680.15원**(0.15원 초과) | **실행 거절** |

- 이 숫자는 첫 응답과 고쳐 쓰기 응답이 **둘 다 출력 상한(24,000토큰급)까지 가는** 경우를 가드 기준으로 예약한 값이라 실제 사용액과 다르다(지난 실측: 호출 2회 371원). 총액 한도(남은 3,532원)와 1회 상한은 호출마다 가드가 따로 지키므로 **실제로 초과 지출이 생길 수 있는 경로는 없다.**
- 그러나 승인 지시("개별 상한을 넘기지 마 · 예산 초과가 예상되면 호출 전에 중단하고 다시 승인")를 **내가 숫자를 임의로 고쳐 풀지 않았다.** 운영자가 아래 두 값을 확인하면 코드의 `runCeilingKrw`만 바꾼다(총 6,000원 · 호출 수 · 범위는 그대로).
  - ① 개인 1회 상한 **1,234.04원**, ③ 리포트 궁합 1회 상한 **680.15원**(② 사주 궁합은 635원 그대로).

## 2. 코드 받기 (운영자 PC · PowerShell)

```powershell
cd <미유 저장소 폴더>
git fetch origin
git checkout claude/miyu-claude-code-setup-klw8ms   # 또는 운영자가 정한 브랜치
git pull
cd miyu
npm install
```

- `.env.local`에 **`ANTHROPIC_API_KEY=` 한 줄만** 직접 적는다(키를 채팅 · 화면 · 문서에 붙이지 않는다). 다른 승인 값(`AI_APPROVED_*`)은 이 스크립트에는 필요 없다 — 승인 값은 코드가 쥐고 있다.
- 호출 없이 먼저 확인(키 없어도 된다): 아래 각 명령에서 `--execute …` 부분만 빼고 실행 → "호출하지 않았습니다"가 나오면 정상이다.

## 3. 실행 순서 (한 건씩 · `--already-spent-krw`는 매번 누적액으로 올린다)

날짜 `2026-10-17`은 승인한 날이다(승인일이 오늘 기준 7일 안이어야 시작된다).

### ① 개인 심층 story-v1 재시험 (P01)

```powershell
node --env-file=.env.local scripts/run-ai-compare.ts --stage story-p01 --variant story-v1 --only A --persona P01 --already-spent-krw 2468 --execute --approved-cap-krw 6000 --approved-on 2026-10-17
```

- 끝나면 화면에 "쓴 비용"이 나온다. **다음 명령의 `--already-spent-krw`는 2468 + 이번에 쓴 금액(올림)** 이다. (예: 330원을 썼다면 2798)
- 결과 읽기: `npm run dev` → `http://localhost:3000/dev/compare` (저장된 글을 실제 미유 리포트 화면으로). 검사에 걸려 저장되지 않은 글은 결과 폴더 `failed/`의 JSON — 새 호출 없이 `node scripts/review-saved-draft.ts <failed 폴더의 json> --persona P01 --render`로 읽는 순서로 풀어 볼 수 있다.

### ② 사주 궁합 (가상 쌍 C1)

```powershell
node --env-file=.env.local scripts/run-compat-live.ts --stage compat-saju-p1 --already-spent-krw <2468 + ①에서 쓴 금액> --execute --approved-cap-krw 6000 --approved-on 2026-10-17
```

### ③ 리포트 궁합 (가상 인물 P01 · P02)

## 4. 글 전문을 읽는 방법 (자동 검사 통과 ≠ 합격)

| 무엇 | 어떻게 |
| --- | --- |
| **실제 서비스 화면 그대로 읽기(②③)** | `npm run dev` → `http://localhost:3000/dev/live` — 결과 목록 → 글 전문. 검사에 걸려 저장되지 않은 결과도 **모델이 돌려준 원문**을 그대로 볼 수 있다(이 PC에서만 열린다) |
| 사람이 읽는 글 파일 | 결과 폴더(`pilot-data/ai-compare/<단계>-<시각>/`)의 `readable.md` · `attempts/round1.txt`(첫 응답 원문) · `round2.txt`(고쳐 쓴 글) |
| **읽기 전 수치(②③)** | `node scripts/review-live-result.ts pilot-data/ai-compare/<폴더>` — 반복 구절 · 영역별 새 정보량 · 근거 사용 · 입력받지 않은 사건 단정 · 응답 재진술 · A님/B님 행동의 겹침 · 제품 검사 결과를 표로 |
| 개인 리포트(①) 수치 | `node scripts/review-saved-draft.ts …` (반복 · 용어 쓰임 · 검사 재실행 · 읽는 순서로 풀어 쓰기) |
| 평가 기준 | [`real-ai-evaluation-rubric.md`](./real-ai-evaluation-rubric.md) — 일곱 가지를 코드 지표와 사람이 읽는 평가로 나눠 적고, **합격은 운영자가 글을 읽고 정한다** |

## 5. 보고 · 다음 단계

- 한 건이 끝날 때마다 **채팅에 붙이는 것**: `cost-and-checks.json` · 글 전문(`readable.md`, 검사에 걸렸다면 `attempts/round*.txt`) · `review-live-result.ts` 표. **키는 필요 없다(붙이지 않는다).**
- 내가(클라우드 세션) 받으면: 글 전문 평가(일곱 가지) → 반복 · 근거 오류 정리 → 지시문 · 검사 수정안(실제 글을 본 뒤의 수정은 **사후 수정**이라고 기록하고 새 글이 통과한다는 증거로 쓰지 않는다) → **다음 건으로 가기 전에 운영자 확인**.
- 한 건이 **형식 검사에 걸려 저장되지 않아도** 쓴 돈은 장부에 올라간다(누적액에 더한다). 같은 승인으로 같은 건을 다시 돌리지 않는다 — 코드(`runsApproved`/`runsDone`)가 막는다. 재시험이 필요하면 운영자가 새로 승인한다.
- 예산: 세 건 최악 합계 2,549원(상한 합) < 추가 지출 상한 3,532원. 실제 사용은 평소 약 600원대로 어림하지만 **재지 않은 값**이다 — 첫 실측 뒤에 갱신한다.

## 6. 하지 않는 것

- 운영 DB · 실결제 · 공개 배포 · 실제 보상 지급은 이 시험과 무관하다(별도 승인).
- 키 · 승인 값을 이 문서 · 채팅 · 저장소에 적지 않는다.
- 실제 AI 시험 결과가 통과하기 전에는 판매 스위치(`SAJU_COMPAT.saleOpen` · `PAIR_COMPAT.saleOpen`)를 열지 않고, 개인 리포트의 story-v1 판매도 권하지 않는다(`REPORT_GENERATION.format`을 `"reading-v1"`로 한 줄 되돌리는 경로가 남아 있다).
