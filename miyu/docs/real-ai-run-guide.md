## 0-1. 문체 통일 뒤 1회 상한 재승인 — 해결됨 (운영자 2026-10-17 저녁)

미유 문체 통일(`docs/voice-guide.md`)로 사주 궁합(0.3 → 0.4) · 리포트 궁합(0.1 → 0.2) 지시문이 길어져 드라이런이 재작성까지 가는 최악 비용을 승인한 상한보다 크게 센 일이 있었다(사주 궁합 656.29원 > 635원 · 리포트 궁합 701.37원 > 680.15원, 코드가 `--execute`를 거절). **운영자가 같은 날 상한을 다시 승인했다.**

| 시험 | 새 1회 상한(승인) | 지금 센 최악(재작성 포함) | 드라이런 |
| --- | --- | --- | --- |
| ② 사주 궁합 | **656.30원** | 656.29원 | 통과 |
| ③ 리포트 궁합 | **701.40원** | 701.37원 | 통과 |
| 개인 심층(본인 입력 story-7) | 1,234.04원(그대로) | 호출 1회만(재작성 없음) | 해당 없음 |

- **누적 총예산 6,000원은 그대로**이고 이미 쓴 금액과 앞으로 쓸 금액을 합산해 관리한다(`--already-spent-krw`에 누적액을 매번 올려 적는다). 각 상품 최대 2회 호출 · 총액 초과 예상 시 실행 전 중단은 코드 가드가 지킨다.
- **운영자가 글 전문을 읽기 전에는 다음 시험을 자동으로 진행하지 않는다**(운영자 지시). 이번 순서는 개인 심층(본인 입력) 1건만이고, 사주 궁합 · 리포트 궁합은 그 글을 읽은 뒤 운영자가 정한다.
- 이 값은 지시문 길이에 묶여 있어 **지시문을 더 바꾸면 최악 비용이 달라져 다시 확인이 필요하다.** 지금 하지 않은 것: 실제 호출.

## 1. 1회 상한 확인 — 해결됨 (운영자 2026-10-17)

드라이런(`--execute` 없이)이 처음 보인 것: 재작성까지 가는 최악 비용이 **개인은 상한 1,234.03원을 0.01원 미만으로, 리포트 궁합은 상한 680원을 0.15원 넘어** 코드가 호출 전에 거절했다(사주 궁합은 634.99원으로 통과). 이 숫자는 첫 응답과 고쳐 쓰기 응답이 **둘 다 출력 상한까지 가는** 경우를 가드 기준으로 예약한 값이라 실제 사용액과 다르다(지난 실측: 호출 2회 371원). 승인 지시("개별 상한을 넘기지 마 · 예산 초과가 예상되면 호출 전에 중단하고 다시 승인")대로 숫자를 임의로 고치지 않고 운영자에게 물었고, **운영자가 같은 날 아래 값으로 확인했다**(총 6,000원 · 추가 지출 상한 3,532원 · 호출 최대 2회 · 범위는 그대로).

| 시험 | 1회 상한(확인 후) | 지금 입력으로 센 최악 | 드라이런 |
| --- | --- | --- | --- |
| ① 개인 | **1,234.04원** | 1,234.03원대 | 통과 |
| ② 사주 궁합 | 635원 | 634.99원 | 통과 |
| ③ 리포트 궁합 | **680.15원** | 680.15원 | 통과 |

- 총액 한도(남은 3,532원)와 1회 상한은 호출마다 가드가 따로 지키므로 **초과 지출이 생길 수 있는 경로는 없다.** 입력(지시문 · 근거)이 길어져 최악이 상한을 다시 넘으면 코드가 호출 전에 거절하고 다시 확인을 요청한다.

## 3. 실행 순서 (한 건씩 · `--already-spent-krw`는 매번 누적액으로 올린다)

### ① 개인 심층 story-v1 재시험 (P01)

> **2026-10-17 운영자 지시로 이 재시험은 가상 인물 P01이 아니라 운영자 본인 입력으로 바뀌었다 — 아래 `story-p01` 명령은 이제 "이미 실행했습니다"로 거절되고, 실행은 이 문서 7장(`scripts/run-own-story.ts`)을 쓴다.** (아래 명령은 기록으로 남긴다.)


- 끝나면 화면에 "쓴 비용"이 나온다. **다음 명령의 `--already-spent-krw`는 2468 + 이번에 쓴 금액(올림)** 이다. (예: 330원을 썼다면 2798)

## 5. 보고 · 다음 단계

- 한 건이 끝날 때마다 **채팅에 붙이는 것**: `cost-and-checks.json` · 글 전문(`readable.md`, 검사에 걸렸다면 `attempts/round*.txt`) · `review-live-result.ts` 표. **키는 필요 없다(붙이지 않는다).**
- 내가(클라우드 세션) 받으면: 글 전문 평가(일곱 가지) → 반복 · 근거 오류 정리 → 지시문 · 검사 수정안(실제 글을 본 뒤의 수정은 **사후 수정**이라고 기록하고 새 글이 통과한다는 증거로 쓰지 않는다) → **다음 건으로 가기 전에 운영자 확인**.
- 한 건이 **형식 검사에 걸려 저장되지 않아도** 쓴 돈은 장부에 올라간다(누적액에 더한다). 같은 승인으로 같은 건을 다시 돌리지 않는다 — 코드(`runsApproved`/`runsDone`)가 막는다. 재시험이 필요하면 운영자가 새로 승인한다.
- 예산: 세 건 최악 합계 2,549원(상한 합) < 추가 지출 상한 3,532원. 실제 사용은 평소 약 600원대로 어림하지만 **재지 않은 값**이다 — 첫 실측 뒤에 갱신한다.

## 6. 하지 않는 것

- 운영 DB · 실결제 · 공개 배포 · 실제 보상 지급은 이 시험과 무관하다(별도 승인).
- 키 · 승인 값을 이 문서 · 채팅 · 저장소에 적지 않는다.
- 실제 AI 시험 결과가 통과하기 전에는 판매 스위치(`SAJU_COMPAT.saleOpen` · `PAIR_COMPAT.saleOpen`)를 열지 않고, 개인 리포트의 판매도 권하지 않는다(신규 생성 기본은 7개 대주제 story-7이고 `REPORT_GENERATION.format`을 `"story-v1"` 또는 `"reading-v1"`로 한 줄 되돌리는 경로가 남아 있다).

## 7. 운영자 본인 입력 시험 (story-own · 운영자 지시 2026-10-17)

> 가상 인물 P01 대신 **운영자가 직접 22문항에 답한 입력**으로 같은 story-v1 실제 AI 시험을 한다. 승인은 ①과 같다(모델 · 누적 6,000원 · 1회 상한 1,234.04원) — **같은 승인 한 건을 본인 입력으로 옮긴 것**이라 P01 재시험(`story-p01`)은 막았다.

| 항목 | 내용 |
| --- | --- |
| 입력 | 이 PC의 개발 서버 `/analyze`(기존 22문항 화면 그대로)에서 끝까지 답하면 `miyu/pilot-data/own-input/latest.json`에만 남는다(`.env.local`에 `MIYU_OWN_INPUT_CAPTURE=yes`를 직접 적었을 때만 · 개발 서버만 · Vercel에서는 꺼짐). 운영 DB · 로그 · 외부로 보내지 않는다 |
| 실행 | `scripts/run-own-story.ts` — 드라이런(호출 없음)이 **입력 확인 파일**(`pilot-data/own-input/input-check.md`: 22개 답 · 계산된 경향 · AI가 받는 근거 전체 · 가지 않는 것)을 만든다 |
| 호출 | **첫 응답 1회만.** 형식 검사에 걸려도 자동으로 고쳐 쓰지 않고(재작성 없음) 제공사 오류도 다시 시도하지 않는다. 걸린 글은 그대로 저장한다 |
| 한도 | 호출 전에 코드가 모델 · story-v1 · 이미 쓴 금액(`--already-spent-krw` 필수) · 승인 금액(6,000) · 승인일(7일 이내) · 호출 1회 최악 비용(약 570원대, 상한 1,234.04원 이내)을 확인하고 어기면 호출하지 않는다. 가드가 호출마다 최악 비용을 한 번 더 확인한다 |

| 하지 않는 것 | 재작성 · 다음 시험(사주 궁합 · 리포트 궁합)을 자동으로 하지 않는다. 운영자가 글을 읽고 정한 뒤에만 |

**전송되는 정보(확인 후 실행)**: 이름 · 생년월일 원문 · 지역 · 22문항의 문장과 선택은 가지 않는다. **사주 원국 여덟 글자와 계산 결과, 응답에서 읽은 경향 문장, 입력한 MBTI**는 근거 문장으로 Anthropic에 전송된다 — 본인 정보이므로 입력 확인 파일을 보고 보내도 되는지 운영자가 판단한다.

**확인한 것**: 모의 모델 · 가짜 응답 시험 9개(호출 1회 · 원문 보존 · 가드 거절 · 승인 범위 · 이름 · 생년월일 미전송 · 입력 확인과 실제 요청의 근거 일치) · 브라우저로 `/analyze`에서 22문항에 답하면 파일이 만들어지는 것 · 리허설(모의 글)로 결과 폴더와 `/dev/live` 화면(무료 · 심층 · 실패한 글 원문)이 열리는 것. **확인하지 못한 것**: 실제 AI 호출(클라우드 세션에 키가 없다 — 지난 실제 호출과 같은 연결 코드를 쓴다) · 운영자 PC(Windows)에서의 실행 · 실제 AI 글이 검사를 통과하는지.

**실행 결과(2026-10-17, 운영자 PC · 운영자 본인 입력 · 근거 36개 — 입력 · 글 내용은 개인 정보라 저장소에 적지 않는다)**: 호출 1회(재작성 없음) · **실제 168원**(드라이런 어림 318원 · 최악 565원) · 누적 2,468 → **2,636원**(승인 총액 6,000원, 남은 3,364원) · **형식 검사 불통과 · 저장되지 않음, 원문 전문은 저장**. 걸린 6건은 문단의 문장 수 한도 3곳(5 · 4 · 4문장) · 한 문단 사주 용어 3개 2곳 · 같은 응답 근거(`survey.caution.high`)를 3개 영역이 앞세운 1곳이다(모두 형식 · 규칙 검사이며, 글이 좋은지 나쁜지는 운영자가 전문을 읽고 판단한다 — 아직 읽는 중). 같은 승인으로는 코드가 `--execute`를 거절한다. 재작성 · 다음 시험(사주 궁합 · 리포트 궁합)은 운영자가 글을 읽은 뒤 정한다.

## 8. 7개 대주제(story-7) 본인 입력 시험 (story7-own · 운영자 지시 2026-10-17)

> 운영자가 7개 대주제 구성(나는 어떤 사람일까? · 나의 강점과 약점 · 연애와 애착 · 인간관계와 인연 · 일과 재물 · 앞으로의 운과 변화 · 미유의 종합 조언)을 확정하고 **기존 22문항(28문항 교체를 기다리지 않는다)** 으로 개인 심층 리포트 **실제 AI 1건**만 시험하도록 지시했다. 승인 범위는 7장과 같다 — 모델 claude-sonnet-5-5 · **누적 6,000원(이미 쓴 금액 포함, 지금 남은 약 3,364원)** · **1회 상한 1,234.04원(올리지 않았다)**. 클라우드 세션에는 키가 없어 **호출은 하지 않았고**(드라이런 · 리허설만), 실제 호출은 운영자 PC에서 한다.
