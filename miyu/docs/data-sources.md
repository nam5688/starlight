## 4. 직접 시범 응답이 필요한 부분 (공개 자료로는 확인할 수 없다)

1. 30문항을 사람이 의도한 뜻으로 읽는지 — 시범 인터뷰 5~8명(`assessment-pilot-protocol.md`). 이번 비교가 만든 질문 5개를 `assessment-ipip-review.md` 6장에 추가했다.
2. T2(준비)와 C2(감정 뒤 멈춤)가 같은 습관으로 느껴지는지, T4를 둘로 나눌지 — 시범 응답에서 두 점수의 움직임을 본다.
3. IPIP-NEO에 대응하는 하위 영역이 없는 C4(의미 · 가치)와 R2(가까울수록 혼자 시간)는 인터뷰 설명이 유일한 확인 수단이다.
4. 모자란 관점 8개의 보강 후보 9문항은 인터뷰 결과를 본 뒤에 연결한다.
5. 사주 해석 규칙이 일상에서 맞는지는 공개 자료로 확인할 수 없다 — 명리 전문가 검토와 실제 사용자 반응이 필요하다. 계산이 정확한 것과 해석 · 미래 시기 읽기가 검증된 것은 다르다.

시범 응답을 모으는 방법: 참여자마다 풀어보기 화면의 "검토 내용 복사"로 만든 글을 `miyu/pilot-data/`에 파일 하나로 저장 → `node scripts/summarize-pilot.ts` → `pilot-data/summary.md`. 이 폴더는 저장소에 올라가지 않고, 운영 DB · 분석 도구에 넣지 않는다.

## 5. 자료의 역할 (섞지 않는다)

| 자료 | 역할 | 하지 않는 것 |
| --- | --- | --- |
| 공개 응답 데이터 | 문항 분포 · 관계를 분석해 설계를 검토 | 미유 문항의 검증 데이터로 대체 · 한 사람의 기록처럼 합치기 · 운영 DB에 넣기 |
| 사주 계산 엔진 | 원국 · 절기 · 대운 · 세운을 정해진 기준으로 계산 | 계산이 맞다고 해석 · 미래 예측이 맞다고 말하기 |
| 해석 지식 자료(규칙) | 계산 결과 · 응답을 어떤 조건에서 어떻게 설명할지 정리 | 출처 · 검토 상태 없이 쓰기, 일반 지식을 통계 · 응답 데이터로 취급하기 |
| 사용자 데이터 | 본인 입력 · 검사 응답 · 동의한 상담 기록 | 광고 · 분석 도구로 보내기, 다른 사람 자료와 합치기 |
| AI | 위 자료 중 질문과 관련된 것만 참고해 쉬운 종합 해석을 쓰기 | 수십만 건 원본을 보내기, 없는 영역을 추정해 채우기, 가상 응답을 실제 응답처럼 쓰기 |

## 6. 지킬 것

- 외부 원본 데이터는 운영 회원 DB와 분리한다(저장소의 `external-data/` · `pilot-data/`는 `.gitignore`). 필요하면 분석 결과 · 참고 자료만 쓴다.
- AI 가상 응답은 개발 테스트에만 쓰고 실제 사람의 응답과 구분한다(시범 응답 정리 테스트의 글도 가짜 참여자다).
- 실제 검사 응답이 없는 영역은 AI가 채우지 않고 "자료 없음"으로 처리한다(리포트 예시의 "없음" 표시가 그 방식이다).
- 근거 없이 궁합 성공률 · 이별 확률 · 정확도를 숫자로 만들지 않는다.
- 문항이나 채점이 바뀌면 버전을 구분한다(0.1 동결 · 0.2 초안 · 0.3 제안).
- 해석 규칙을 고치면 `rule-meta.ts`의 조건 · 예외 · 버전도 함께 고친다(`rule-meta.test.ts`가 빠뜨림을 잡는다) 그리고 `node scripts/render-data-docs.ts`로 문서를 다시 만든다.
