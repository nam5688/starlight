# 최신 버전 적용 · 기존 결제 확인 · 알림 연결 (한 단계씩)

운영자 PC(Windows · PowerShell) 기준. **키 값은 이 대화나 문서에 쓰지 않는다** — 설정 파일(`.env.local`)에만 넣는다. 공개 배포와 실결제는 이 안내에 없다 (운영자 확인 전에는 하지 않는다).

## 1. 최신 코드로 옮기기 (ZIP 방식, 기존 설정 · 데이터 보존)

**먼저 알아둘 것:** 코드를 바꿔도 **Supabase의 데이터(회원 · 검사 결과 · 주문 · 리포트)는 그대로**다. 데이터는 코드 폴더가 아니라 Supabase에 있기 때문이다. 코드 폴더에서 바뀌는 것은 `.env.local`(설정)뿐인데, 아래에서 복사해 둔다.

1. 새 ZIP 받기: GitHub 저장소의 `claude/miyu-claude-code-setup-klw8ms` 브랜치 → **Code → Download ZIP** → 새 폴더에 압축 풀기. (`git pull`은 쓰지 않는다)
2. 기존 `miyu` 폴더는 **지우지 말고 이름만 바꿔 둔다** (`miyu-old`). 압축을 푼 새 폴더 안의 `miyu` 폴더가 새 앱이다.
3. 기존 설정 복사 (PowerShell, 새 `miyu` 폴더에서). 경로는 내 폴더에 맞게 바꾼다:

   ```powershell
   Copy-Item ..\..\miyu-old\.env.local .\.env.local
   ```

   (경로가 헷갈리면 파일 탐색기에서 기존 폴더의 `.env.local` 파일을 새 `miyu` 폴더 안으로 복사해도 된다. `.env.local`의 내용은 열어서 다른 곳에 붙여넣지 않는다.)

4. 설치 후 실행:

   ```powershell
   npm.cmd ci
   npm.cmd run dev
   ```

5. http://localhost:3000/setup 을 열어 "Supabase 연결"이 "연결됨"인지 본다.
6. 문제가 없으면 `miyu-old`는 나중에 지운다. 문제가 생기면 `miyu-old`로 되돌아가면 된다 (데이터는 영향 없음).

## 2. DB 변경(SQL) — 이미 적용한 것은 건드리지 않는다

SQL 파일은 `supabase/migrations` 폴더에 번호 순서로 있다. **무조건 다 실행하지 않는다.** 먼저 "어디까지 적용됐는지"를 읽기 전용으로 확인한다.

> **4~10번이 모두 "아직 안 함"이면 — 한 번에 적용하는 통합 파일이 있다 (파일 7개를 하나씩 복사하지 않아도 된다).**
> 이 작업 환경(클라우드)에서는 운영자님의 Supabase에 접속할 수 없다(접속 정보 · 권한이 없고, 키를 대화에 붙여넣지도 않는다). 그래서 직접 적용하지 않고, SQL Editor에서 **한 번만** 실행하는 통합 파일 `supabase/apply-4-to-10.sql`을 만들었다.
>
> 1. 통합 파일을 클립보드에 복사 (새 `miyu` 폴더에서, PowerShell):
>
>    ```powershell
>    Get-Content supabase\apply-4-to-10.sql -Raw -Encoding UTF8 | Set-Clipboard
>    ```
>
> 2. Supabase 대시보드 → **SQL Editor** → **New query** → 붙여넣기(`Ctrl + V`) → **Run** (한 번만).
>    - "위험한 작업" 확인 창이 뜨면: 6번의 "허용값을 넓히는 제약 조건 교체"와 10번 함수 안의 "탈퇴 시 삭제" 문장 때문이다. 이 파일은 기존 데이터를 지우지 않으므로 계속 실행해도 된다.
> 3. 결과: 맨 아래 **결과 표**에서 1~10번이 모두 **적용됨**이면 끝이다.
> 4. **오류가 나면** 오류 문장을 그대로 알려 주세요 (키는 필요 없음). 이 파일은 전체가 하나의 묶음이라 **중간에 실패하면 이 파일이 한 일이 모두 취소**되어 일부만 적용되지 않는다. 시작할 때 조건을 확인해, 1~2번 표가 없거나 4~10번이 하나라도 이미 적용돼 있으면 **아무것도 바꾸지 않고** "시작 조건 불충족"으로 멈춘다 (이미 한 번 실행한 뒤 다시 실행해도 같다).
> 5. 4~10번 중 **일부만** 적용된 상태라면 이 파일을 실행하지 말고, 먼저 읽기 전용 확인 조회 결과 표를 알려 주세요.
>
> 개발 환경의 임시 Postgres 16에서 확인한 것: ① 파일 7개를 하나씩 적용한 DB와 **구조가 완전히 같다** ② 기존 회원 · 검사 · 주문 · 결제 · 리포트 데이터가 그대로다 (주문의 `payment_env` 열만 새로 생기고 기존 주문은 `test`로 채워진다) ③ 다시 실행하면 멈추고 아무것도 바뀌지 않는다 ④ 일부만 적용된 DB · 1~2번이 없는 DB에서는 멈춘다 ⑤ 7번에서 일부러 오류를 내면 앞의 4~6번까지 모두 취소된다. **실제 Supabase(호스팅)에서 실행해 본 것은 아니다.**

아래는 **파일을 하나씩** 확인하며 적용하는 방법이다 (일부만 적용된 상태이거나 통합 파일을 쓰지 않을 때).

1. 확인용 조회를 클립보드에 복사 (이 조회는 아무것도 만들거나 바꾸거나 지우지 않는다):

   ```powershell
   Get-Content supabase\check-migrations.sql -Raw -Encoding UTF8 | Set-Clipboard
   ```

2. Supabase 대시보드 → **SQL Editor** → **New query** → 붙여넣기(`Ctrl + V`) → **Run**.
3. 결과 표의 **상태**를 본다:

| 번호 | 파일 | 하는 일 |
| --- | --- | --- |
| 1 | `20261011000000_init.sql` | 기본 표 6개 + 접근 정책 |
| 2 | `20261012000000_consents.sql` | 가입 동의 기록 |
| 3 | `20261013000000_profile_backfill.sql` | 빠진 프로필 보완 |
| 4 | `20261014000000_payment_env.sql` | 주문에 결제 환경 기록 |
| 5 | `20261015000000_personal_context.sql` | 내 고민 자세히 알려주기 저장 |
| 6 | `20261016000000_ops_events.sql` | 운영 기록 · 결제 기록 출처 확장 |
| 7 | `20261017000000_ai_usage.sql` | AI 호출 기록 |
| 8 | `20261018000000_funnel_feedback.sql` | 방문 단계 · 만족도 · 유입 출처 |
| 9 | `20261019000000_performance.sql` | 하루 AI 비용 합계 함수 · 색인 |
| 10 | `20261020000000_account_withdrawal.sql` | 회원 탈퇴 |
| 11 | `20261021000000_concern_records.sql` | **고민 기록** — 내 고민 반영 리포트 발급에 필요 (새로 추가, 통합 파일 `apply-4-to-10.sql`에는 들어 있지 않으니 이 파일만 따로 실행) |

   - **적용됨** → 그대로 둔다 (다시 실행하지 않는다).
   - **아직 안 함** → 그 번호의 파일만, **번호 순서대로** 한 번씩 실행한다 (아래 4번).
   - **일부만** → 실행하지 말고 **결과 표를 그대로** 알려 주세요 (키는 필요 없음). 임의로 다시 실행하지 않는다.
4. 실행 방법 (파일 하나씩): 번호 하나를 클립보드에 복사 → SQL Editor에서 **New query** → 붙여넣기 → **Run** → `Success`를 확인한 뒤 다음 번호.

   ```powershell
   Get-Content supabase\migrations\20261020000000_account_withdrawal.sql -Raw -Encoding UTF8 | Set-Clipboard
   ```

   (위 줄의 파일 이름만 해당 번호의 파일로 바꾼다.)
5. 다시 확인용 조회를 실행해 해당 번호가 **적용됨**이 되었는지 본다.

- 모든 SQL 파일은 "더하기만" 한다. 기존 회원 · 검사 · 주문 · 결제 데이터를 지우거나 초기화하지 않는다.
- 12번(대화 서버 저장 · 자유 질문 횟수)은 11번 뒤에 새 파일 하나만 적용한다 — `supabase/migrations/20261022000000_talk_rooms.sql`을 SQL Editor에서 실행 → 확인 조회에서 12번이 **적용됨**인지 본다. 12번 전에는 대화가 이 기기 브라우저에만 남고 자유 질문은 열리지 않는다. 표 두 개와 함수를 **더하기만** 하며 기존 데이터는 바뀌지 않는다.
- 13번(결제한 질문 장부 — 예전 이름 미유캐시)과 14번(채팅 요약 저장)도 같은 방식으로 **번호 순서대로, 코드를 먼저 올린 뒤** 새 파일 하나씩만 적용한다 — `supabase/migrations/20261023000000_miyu_cash.sql`, 그다음 `supabase/migrations/20261024000000_chat_summaries.sql`을 SQL Editor에서 실행 → 확인 조회에서 해당 번호가 **적용됨**인지 본다. 둘 다 표 · 열 · 함수를 **더하기만** 하고(탈퇴 함수는 같은 이름으로 다시 정의해 캐시 잔액 확인 · 채팅 요약 삭제를 더한다) 기존 데이터는 바뀌지 않는다. 13번 전에는 충전이 막혀 "충전을 준비하고 있어요"로 보이고(돈을 받고 캐시가 안 들어가는 일이 없게), 14번 전에는 [저장하기]가 "준비 중"으로 막히며 저장하지 않고 끝내기와 대화 · 질문은 그대로 된다.
- **16번**(`supabase/migrations/20261026000000_question_packs.sql`)은 **질문 묶음별 장부 · 부분 환불 반영 · 무료 질문 한도의 DB 보장**을 더한다(15번 다음에 같은 방식으로 한 번 실행하고 확인 조회에서 16번이 **적용됨**인지 본다). 표 · 열 · 함수를 더하고 13번의 장부 검사 조건 몇 개를 넓혀 다시 만들 뿐 기존 데이터는 바뀌지 않으며, **실행만으로 누구의 질문도 늘거나 줄지 않는다.** 16번 전에도 앱은 그대로 동작하지만 부분 환불은 자동 반영되지 않고(운영자에게 알림) 무료 질문 한도는 예전 방식이다. 첫 확인 절차는 [`question-pack-live-test.md`](./question-pack-live-test.md).
- **17번**(`supabase/migrations/20261027000000_taste_reports.sql`)은 **맛보기 리포트(무료 · 로그인한 회원 · 한 계정당 1번)**를 더한다(16번 다음에 같은 방식으로 한 번 실행하고 확인 조회에서 17번이 **적용됨**인지 본다). 표 `taste_reports` · 함수 세 개를 더하고 탈퇴 함수에 맛보기 리포트 삭제 한 단계를 더할 뿐 기존 데이터는 바뀌지 않으며 **실행만으로 누구에게도 맛보기 리포트가 생기지 않는다.** 17번 전에도 앱은 그대로 동작하고 결과 화면의 맛보기 구역만 "준비 중"으로 보인다. 설명 · 다시 시험하는 방법은 [`taste-report.md`](./taste-report.md).
- **18번**(`supabase/migrations/20261028000000_invites.sql`)은 **초대 링크와 초대 할인(심층 리포트 9,900 → 5,900원)**을 더한다(17번 다음에 같은 방식으로 한 번 실행하고 확인 조회에서 18번이 **적용됨**인지 본다). 표 `invites` · `invite_discounts`와 함수 둘을 더하고 탈퇴 함수에 초대 링크 삭제 한 단계를 더할 뿐 기존 데이터는 바뀌지 않으며 **실행만으로 누구의 가격도 바뀌지 않는다.** 18번 전에도 앱은 그대로 동작하고(친구 초대 구역이 보이지 않고 초대 링크는 "지금은 확인할 수 없어요"로 닫혀 있으며 결제는 정가) 적용한 뒤에 링크가 열린다. 설명 · 확인 SQL은 [`compat-proposal.md`](./compat-proposal.md) 7 · `supabase/check-invites.sql`.
- **15번**(`supabase/migrations/20261025000000_admin_credit_question.sql`)은 **운영자 수동 질문 반영**(결제는 됐는데 질문이 안 들어간 주문을 결제사 확인 뒤 `/admin`에서 질문 넣기) 전용 함수 하나를 더한다. 같은 방식으로 SQL Editor에서 한 번 실행하고 확인 조회에서 15번이 **적용됨**인지 본다. 표 · 데이터는 바뀌지 않고, 실행만으로는 아무 회원의 질문도 늘지 않으며, 15번 전에는 `/admin`의 [결제사 확인 후 질문 넣기]만 "15번을 먼저 실행하세요"로 막힌다(다른 기능은 그대로). 설명은 [`question-payment.md`](./question-payment.md) 5-1 · [`runbook.md`](./runbook.md) 2장.
- 6~11번이 없어도 결제 · 리포트 · MY는 동작한다 (운영 기록 · 비용 기록 · 방문 기록 · 탈퇴 · 고민 반영 리포트 발급만 해당 번호 전에는 안 된다. 11번 전에는 고민 기록소에서 고민을 적고 저장하는 것은 되지만, 새 리포트 발급은 "준비 중"으로 막히고 결제도 시작되지 않는다).
- 11번 파일은 표 하나와 함수를 **더하기만** 한다 (탈퇴 함수는 같은 이름으로 다시 정의해 "고민 기록 삭제"를 더한다 — 이미 적용한 10번 파일은 고치지 않았다). 기존 회원 · 검사 · 주문 · 결제 · 리포트 데이터는 바뀌지 않는다.

## 3. 기존 테스트 주문 확인 — 새 결제를 반복하기 전에

전에 테스트 결제 후 리포트는 열렸지만 결제내역이 안 보였다. **다시 결제하지 말고** 먼저 그 주문이 어디까지 기록됐는지 읽기 전용으로 확인한다. 주문 · 결제 상태를 손으로 "결제 완료"로 바꾸는 방법은 없고, 만들지도 않는다 (결제사의 실제 기록만 기준).

### 3-1. 내 DB에 어떻게 기록됐나 (읽기 전용)

1. 클립보드에 복사 → SQL Editor에서 실행:

   ```powershell
   Get-Content supabase\check-payments.sql -Raw -Encoding UTF8 | Set-Clipboard
   ```

2. 최근 주문 30건이 나온다. **판정** 열을 본다:

| 판정 | 뜻 | 다음 행동 |
| --- | --- | --- |
| 정상 (결제 완료 · 승인 기록 있음 · 리포트 있음) | 우리 DB 기준으로 결제와 리포트가 맞다. 그런데 MY에서 안 보였다면 **화면 문제** | MY → 결제내역이 최신 코드에서 보이는지 확인(이 버전에서 MY에 결제내역이 있다). 그래도 안 보이면 주문번호를 알려 주세요 |
| 확인 필요: 결제 완료인데 승인 기록이 없음 | 예전 코드가 만든 주문일 수 있다 (승인 기록 표가 생기기 전) | 3-2의 결제사 재확인 |
| 진행 중이거나 결제 확인 중 / 미완료: 1시간 넘게 결제 확인 안 됨 | 결제창은 열었지만 서버 승인이 끝나지 않았다 | 3-2의 결제사 재확인 (승인됐다면 반영, 아니면 "청구되지 않음"으로 정리됨) |
| 결제 안 됨 (failed · canceled) | 결제가 취소 · 거절됐다 | 다시 결제해도 된다 |
| 목록에 주문이 없다 | 주문이 만들어지지 않았다 (결제창만 열림) | 청구된 것이 없다 |

3. **결제 환경** 열: `test-docs`는 토스 문서의 공용 예제 키로 한 테스트 결제다 → **내 토스 상점 관리자에는 내역이 보이지 않는 것이 정상**이다. `test`는 내 테스트 키, `live`는 실결제.
4. 특정 주문의 결제 처리 기록(승인 요청 · 결제사 알림 · 재확인 등)을 보려면 `supabase\check-payment-detail.sql`을 열어 `여기에_주문번호`를 MEU-로 시작하는 번호로 바꾼 뒤 같은 방법으로 실행한다.

### 3-2. 결제사(토스)에는 어떻게 기록됐나

- 앱에서: **MY → 결제내역 → 주문 상세 → "결제사에 다시 확인하고 맞추기"**. 미유가 내 토스 키로 결제사에 이 주문번호를 **조회**하고, 결제사 기록이 승인이면 주문을 맞추고 리포트를 준비한다. 결제사에 기록이 없으면 "청구된 금액 없음"으로 정리한다 (결제사 응답만 기준).
- 토스 개발자센터 → 내 상점 → 결제내역: **내 테스트 키로 결제했을 때만** 보인다. 공용 예제 키(`test_gck_docs_…` / `test_gsk_docs_…`)라면 안 보인다.
- 결과를 알려 줄 때는 **주문번호 · 판정 · 결제 환경 · 재확인 결과 문구**만 보내 주세요 (키 · 결제 키 전체는 필요 없음).

## 4. 관리자 화면 · 텔레그램 알림 — 테스트 환경에서 미리 연결

공개 배포 전에 미리 연결해 확인해 둘 수 있다. 연결하기 전에는 알림이 서버 로그에만 남는다 (코드는 구현되어 있지만 **내 텔레그램에 실제로 도착하는지는 연결해 봐야 안다**).

### 4-1. 관리자 화면 (`/admin`)

1. Supabase → **Authentication → Users** → 내 계정(카카오 로그인한 계정)의 **UID**를 복사한다 (내부 회원번호, 비밀키가 아님).
2. 메모장으로 `.env.local`을 연다: `notepad .env.local`
3. 아래 두 줄을 추가한다 (`CRON_SECRET`은 아무도 모르는 긴 무작위 문자열 — 아래 PowerShell로 만들 수 있다):

   ```
   ADMIN_USER_IDS=여기에_내_UID
   CRON_SECRET=여기에_무작위_문자열
   ```

   ```powershell
   [guid]::NewGuid().ToString("N") + [guid]::NewGuid().ToString("N")
   ```

4. 개발 서버를 껐다 켠다(`Ctrl + C` 후 `npm.cmd run dev`) → http://localhost:3000/admin 이 열린다 (관리자가 아닌 계정에는 "없는 페이지"로 보인다).

### 4-2. 텔레그램 봇 만들기와 연결

1. 텔레그램에서 **@BotFather**를 찾아 `/newbot` → 봇 이름과 아이디를 정하면 **토큰**을 준다 (`숫자:문자열` 모양). **토큰은 비밀이다 — 채팅에 보내지 않는다.**
2. 내가 만든 봇의 대화창을 열어 **Start**(또는 아무 글자)를 보낸다. (봇은 먼저 말을 걸 수 없어서 이 단계가 꼭 필요하다.)
3. 텔레그램에서 **@userinfobot**에게 말을 걸면 내 **Id**(숫자)를 알려 준다. 이것이 **채팅 번호**다.
4. `.env.local`에 추가:

   ```
   TELEGRAM_BOT_TOKEN=여기에_토큰
   TELEGRAM_CHAT_ID=여기에_채팅_번호
   ```

5. 개발 서버를 껐다 켠다 → `/admin` → **"텔레그램 알림 시험 (종류별 5건)"** 버튼.
6. 화면 위쪽 메시지와 **내 텔레그램**을 함께 본다:
   - "텔레그램이 시험 메시지 5건을 받았습니다" + 텔레그램에 `[미유·테스트]`로 시작하는 메시지 5건 → **연결 완료.**
   - "봇 토큰이 맞지 않습니다" → 토큰을 다시 복사해 넣는다.
   - "채팅 번호가 맞지 않거나 … Start를 하지 않았습니다" → 2번(Start)과 3번(번호)을 확인한다.
   - "텔레그램이 연결되어 있지 않습니다" → 4번의 두 줄이 `.env.local`에 있는지, 서버를 다시 켰는지 확인한다.

### 4-3. 알림 종류

| 알림 | 언제 오나 | 중복 |
| --- | --- | --- |

- 알림이 실패해도 결제 · 리포트 제공에는 영향이 없다 (텔레그램 장애를 흉내 낸 시험으로 확인함).

## 7. AI 비교 실행 (운영자 승인: 2026-10-13, 1단계 3,000원 한도 · 재시도 포함)

**먼저 알아둘 것**
- **ChatGPT · Claude 구독료와 API 이용료는 별개다.** 지금 쓰는 구독만으로 미유에서 AI를 부를 수 없다. API는 회사마다 따로 계정 · 결제 · 키가 필요하다.
- **3,000원은 "테스트에 쓸 최대 사용 금액"이고, 계정에 충전하는 금액과는 별개다.** 충전은 회사가 정한 최소 금액부터일 수 있다(남은 금액은 계정에 남는다). 3,000원을 넘기려는 호출은 미유가 보내지 않는다.
- **키는 채팅 · 문서 · 커밋에 붙여넣지 않는다.** 내 PC의 `.env.local` 파일에만 넣는다.
- **이번 비교는 "개인 통합 리포트"(9,900원)다.** 고민 반영 리포트(4,900원)는 AI 지시문이 아직 옛 규칙이라 넣지 않았다.

**한 단계씩** (앞 단계가 끝나면 다음 단계를 안내한다)

1. **최신 코드 적용** — 1장(새 ZIP → 기존 `.env.local` 복사 → `npm.cmd ci` → `npm.cmd run dev`).
2. **OpenAI API 계정 · 결제 · 키** — 구독이 아니라 API 플랫폼(platform.openai.com)에서 한다. 결제 수단 등록과 소액 충전, 월 사용 한도 설정, 키 발급까지.
3. **`.env.local`에 OpenAI 키 입력** — 아래 "키 입력 위치".
4. **Claude API 계정 · 결제 · 키** — Claude 구독이 아니라 Claude Console(platform.claude.com)에서 한다. 같은 순서.
5. **`.env.local`에 Claude 키 입력.**
6. **비용 · 키 입력 확인(호출 없음):** 새 `miyu` 폴더에서 PowerShell로 `node --env-file=.env.local scripts\run-ai-compare.ts` — 모델 · 예상 비용 · 한도와 "키 입력 확인: 후보 A 있음 · 후보 B 있음"이 나오고 "호출하지 않았습니다"로 끝나면 정상이다 (키 값은 나오지 않는다).
7. **실제 생성 4건:**

   ```powershell
   node --env-file=.env.local scripts\run-ai-compare.ts --stage stage-1 --execute --approved-cap-krw 3000 --approved-on 2026-10-13
   ```

   - 승인 금액 · 날짜를 빼거나 키가 하나라도 없으면 **아무것도 호출하지 않고** 멈춘다. 화면에는 글 내용이 나오지 않는다(건수 · 비용 · 첫 시도 형식 통과 여부만).
8. **실제 미유 리포트 화면에서 읽기:** 결과 폴더(`pilot-data`)가 있는 `miyu` 폴더에서 `npm.cmd run dev`를 켠 상태에서(켜면 나오는 Local 주소의 번호를 쓴다) 브라우저로 `http://localhost:3000/dev/compare`를 연다. 목록에서 결과를 누르면 리포트 화면이고, 그 화면 위쪽의 **"대화로 보기"**를 누르면 같은 글이 채팅 화면으로 보인다(`/dev/compare/<결과 폴더 이름>/<인물>-X/talk`). 결과 폴더 이름만 붙인 주소(`/dev/compare/<결과 폴더 이름>`)는 목록으로 보내진다. 가상 인물 2명 × X · Y 4건이 실제 리포트 화면으로 보인다(어느 AI인지는 가려져 있다). 같은 내용이 `pilot-data\ai-compare\stage-1-…\blind` 폴더에 글 파일로도 있다.
9. **채점:** `evaluation-sheet.md`로 채점하고 **끝나기 전에는 `key-open-after-scoring.json`을 열지 않는다.** 이 폴더는 저장소에 올라가지 않는다.
10. **결과 보고:** 채점표와 `cost-and-checks.json`의 요약(건수 · 비용 · 형식 통과)만 알려 준다. 키 · 글 전체는 필요 없다. **4건으로는 순위를 정하지 않는다** — 작동하는지 · 비용이 예상대로인지 · 명백한 결함이 있는지만 본다.

**Claude만 먼저 쓰기 (OpenAI 계정이 아직 없을 때)** — `--only A`를 붙인다. Claude 키(`ANTHROPIC_API_KEY`)만 있으면 되고, 생성은 가상 인물 2명 × Claude 1개 = **2건**이다 (예상 약 460원, 모두 고쳐 쓰기까지 가는 최악 약 2,080원, 한도는 같은 3,000원). 승인한 범위 안이다.

```powershell
node --env-file=.env.local scripts\run-ai-compare.ts --only A
node --env-file=.env.local scripts\run-ai-compare.ts --stage stage-1 --only A --execute --approved-cap-krw 3000 --approved-on 2026-10-13
```

첫 줄은 호출 없는 확인, 둘째 줄이 실제 생성이다. **이름을 가린 비교는 아니다** — 글은 모두 `X`(= Claude)이고, 실제 미유 리포트 화면(`/dev/compare`)에서 읽는 방법은 같다. 한 모델만으로는 "작동하는지 · 비용 · 명백한 결함 · 읽을 만한지"를 볼 수 있을 뿐 모델 사이의 우열은 알 수 없다. 나중에 OpenAI 키를 넣고 `--only` 없이 4건 비교를 따로 할 수 있다 (그때는 새로 생성하므로 비용이 다시 든다).

**실행이 "생성 0/2건 · failed"로 끝났을 때 (형식 검사 실패)** — 2026-10-13 첫 실행이 이렇게 끝났다 (Claude는 응답했지만 글이 검사를 통과하지 못했다). 이제 화면에 **걸린 이유**가 나오고, 그때의 글은 결과 폴더의 `failed` 폴더에 저장된다. 같은 명령을 그대로 다시 실행하면 이미 쓴 돈이 한도에 반영되지 않으니, **쓴 비용을 빼고** 한 인물만 다시 돌린다 (아래 `621`은 첫 실행에서 쓴 금액이다 — 실제 쓴 금액으로 바꾼다):

```powershell
node --env-file=.env.local scripts\run-ai-compare.ts --stage stage-1 --only A --persona P01 --already-spent-krw 621 --execute --approved-cap-krw 3000 --approved-on 2026-10-13
```

- 승인 총액은 그대로 3,000원이고, 이 명령은 그중 이미 쓴 621원을 뺀 **2,379원 안에서만** 쓴다 (한 인물 예상 약 230원, 고쳐 쓰기까지 가는 최악 약 1,050원).
- 끝나면 "실패 이유" 부분(검사 문구이며 글 내용이 아니다)을 알려 달라고 하면 된다. 이유를 보기 전에는 검사 기준을 바꾸지 않는다.

**리허설 (키 · 비용 없이 흐름만 시험)** — 키를 넣기 전에 "생성 → 파일 저장 → 화면에서 읽기"가 끝까지 도는지 보고 싶을 때 쓴다.

```powershell
node scripts\run-ai-compare.ts --rehearsal
```

네트워크를 쓰지 않고 키도 필요 없으며 비용은 0원이다. 글은 **모의 글(실제 AI 글이 아니다)**이고 결과 폴더 이름이 `rehearsal-`로 시작한다. `/dev/compare`에서 같은 모양으로 열려 화면을 미리 확인할 수 있다. 실제 생성과 달리 AI 품질에 대해서는 아무것도 알려 주지 않는다.

**키 입력 위치** — 새 `miyu` 폴더 안의 **`.env.local`** 파일이다 (`.env.example`이 아니다. `.env.local`은 Windows 탐색기에서 안 보이면 PowerShell로 연다).

```powershell
notepad .env.local
```

파일 맨 아래에 아래 두 줄을 추가하고, `=` 뒤에 키를 **공백 없이** 붙여넣고 저장한다. 따옴표는 쓰지 않는다. 따로 두 번에 나눠 한 줄씩 넣어도 된다.

```
OPENAI_API_KEY=여기에_OpenAI_키
ANTHROPIC_API_KEY=여기에_Claude_키
```

- 이 두 줄은 이번 비교를 내 PC에서 실행할 때만 쓴다. 호스팅 환경변수 · 채팅 · 문서 · 커밋에는 넣지 않는다(`.env.local`은 저장소에 올라가지 않는 파일이다).
- 키가 노출됐다고 느껴지면 회사 콘솔에서 그 키를 바로 지우고 새로 만든다 (`runbook.md`의 키 노출 대응).

기록: 이 코드는 가짜 응답으로만 시험했고, 실제 응답 모양은 첫 호출에서 확인된다. 오류 번호(`INVALID_RESPONSE` · `AUTH` · `BILLING` · `RATE_LIMITED`)가 나오면 그대로 알려 준다.

## 6. 자체 성향 질문 — 풀어보기와 검토 (선택)

공개 사이트가 아니라 내 PC의 파일(또는 비공개 링크)이다. **두 번에 나눠서** 한다.

**먼저 `풀어보기`(`miyu\docs\assessment-take.html`)** — 채점 방향과 운영자 설명이 없는 화면이다. 실제 사용자처럼 30문항을 풀고, 완료 후 검토 모드에서 "정답이 뻔해 보인 문항 · 둘 이상이 다 나 같았던 문항 · 뜻을 모르겠던 문항 · 고르고 싶은 답이 없던 문항"을 표시한 뒤 **복사할 글**을 채팅에 붙여넣는다. 처음 풀 때 점수 방향이 보이면 답이 유도되므로 이 화면을 먼저 한다.

**그 다음 `검토 화면`(`miyu\docs\assessment-review.html`)** — 점수 방향이 보이는 두 번째 검토다. 아래 순서를 따른다.

1. ZIP을 푼 폴더에서 `miyu\docs\assessment-review.html`을 더블클릭한다 (브라우저로 열린다). PowerShell을 쓰려면 `miyu` 폴더에서 `start docs\assessment-review.html`.
2. 문항 탭에서 문항마다 **괜찮음 · 고쳐야 함 · 빼기**를 누르고 필요하면 한 줄 메모를 적는다. 표시는 이 브라우저에만 저장된다 (다른 기기와 공유되지 않음).
3. **검토 메모** 탭의 **검토 내용 복사**를 눌러 나온 글을 채팅에 붙여넣는다.
4. **부족한 점** 탭의 숫자는 실제 사람의 응답이 아니라 가상 응답으로 계산한 값이며, 실제 신뢰도나 정확도가 아니다. 읽는 범위는 A안(30문항 유지, 읽을 수 있는 관점의 뚜렷한 방향만 읽기, **최종 검사가 아니라 시범용**)으로 이미 정해졌다. 문항은 0.2로 고쳤다(문항마다 주 관점 하나, 13개 관점 중 5개만 읽을 수 있음) — 변경 내용은 `assessment-design-review-2.md`, 다음 순서(시범 인터뷰)는 `assessment-pilot-protocol.md`.

## 8. 실제 AI(Claude)로 리포트 · 채팅 시험 — 운영자가 직접 하는 것만 (한 단계씩)

**코드 수정 · 검증은 클로드가 하고, 운영자는 설정 적용과 키 입력만 한다.** 운영자 승인(2026-10-15): **리포트 생성과 채팅 질문을 합쳐 5,000원**(하나의 승인 · 하나의 장부). **`.env.local`에 승인 값을 직접 적기 전에는 호출이 일어나지 않는다.** 승인 금액 · 호출 수 · 기간을 넘길 수 있는 호출은 Anthropic에 요청 자체를 보내지 않는다(가짜 서버로 확인했다). 새 DB 변경은 없다(13 · 14번까지 적용돼 있으면 된다 — 15번은 `/admin`의 질문 수동 반영 버튼에만 필요하다).

**알아 둘 것**: 실제 호출은 한 번도 하지 않았다. 리포트 한 건은 이전 비교 실행에서 1건당 약 300~330원(고쳐 쓰기 포함)이었으므로 5,000원이면 리포트 몇 건과 채팅 질문 수십 건 정도다 — 정확한 시간 · 비용 · 글의 품질은 이번에 처음 확인한다. 리포트 한 건은 **몇 분** 걸릴 수 있다(생성 제한 시간 기본 8분).

1. **최신 코드로 옮기기** — 위 1번(ZIP 방식: 새 ZIP → 옛 `.env.local` 복사 → `miyu` 폴더에서 `npm.cmd ci`). 오류(EPERM)가 나면 `taskkill /F /IM node.exe` 후 다시.
2. **(선택) 테스트 리포트 지우기** — 지금 있는 개발용 리포트를 지우고 실제 AI로 새로 보고 싶을 때만. Supabase → SQL Editor:
   1. `supabase\check-test-reports.sql` 내용을 붙여넣고 Run — **읽기만 한다.** "지움 대상"으로 나온 리포트가 지워진다(결제 환경이 test인 주문의 리포트 중 실제 Claude로 만든 것이 아닌 것). 결과 표를 알려 주면 확인해 준다.
   2. 괜찮으면 `supabase\delete-test-reports.sql` 내용을 붙여넣고 Run — **리포트만 지운다.** 주문 · 결제 · 검사 결과 · 채팅 대화는 그대로다. "지운 리포트 수"가 나온다.
   3. 지운 뒤 결과 화면을 열면 "결제가 완료되었습니다 · 리포트를 만들지 못했습니다"와 **[리포트 다시 만들기]** 버튼이 보인다(지운 리포트가 없는 상태를 같은 화면이 쓴다 — 정상). 이미 결제한 주문이라 다시 결제하지 않고, 그 버튼을 한 번 누르면 같은 주문으로 새로 만든다.
   4. 채팅 무료 질문 수도 처음부터 다시 보고 싶으면 `delete-test-reports.sql` 맨 아래 선택 블록(주석)의 안내를 따른다.
3. **`.env.local`에 값 적기(메모장)** — 이름 옆에 값을 직접 입력한다. **키는 대화에 붙여넣지 않는다**(이전 비교 실험에서 넣은 `ANTHROPIC_API_KEY` 그대로 두면 된다):

   | 이름 | 값 |
   | --- | --- |
   | `AI_PROVIDER` | `anthropic` (리포트를 실제 Claude로 만든다) |
   | `AI_CHAT_PROVIDER` | `anthropic` (채팅 질문을 실제 Claude로 답한다) |
   | `ANTHROPIC_API_KEY` | (이미 넣어 둔 키 그대로) |
   | `AI_APPROVED_KRW` | `5000` — 승인 금액(원). 이보다 크게 적으면 연결되지 않는다 |
   | `AI_APPROVED_CALLS` | `60` — 승인 호출 수(고쳐 쓰기 · 재시도도 한 번씩 센다). 이보다 크게 적으면 연결되지 않는다 |
   | `AI_APPROVED_FROM` · `AI_APPROVED_THROUGH` | 시험하는 날 · 마지막 날(한국 날짜, 최대 7일). 예: `2026-10-16` · `2026-10-18` |
   | `AI_DAILY_BUDGET_KRW` | `5000` (선택 — 하루 AI 비용이 넘으면 새 구매 · 새 질문을 멈춘다) |
   | `AI_EST_COST_KRW_PER_REPORT` | `350` (선택 — 대기 중인 리포트를 예산에 미리 더하는 어림) |

   예전의 `AI_CHAT_APPROVED_KRW` · `AI_CHAT_APPROVED_CALLS` · `AI_CHAT_APPROVED_FROM` · `AI_CHAT_APPROVED_THROUGH`(채팅 전용 600원 시험, 기간이 지났다)는 **지우거나 비워 둔다** — 위 `AI_APPROVED_*`를 적으면 그쪽이 먼저 쓰인다. `AI_CHAT_EXTRA_QUESTIONS`는 채팅 시험을 더 많이 해 보고 싶을 때만 `5` 정도로 적고 끝나면 비운다.
4. **서버를 켜고 설정 확인** — `npm.cmd run dev` 후 `http://localhost:3000/setup`의 "리포트 생성기" · "자유 질문 AI" 줄이 "실제 Claude 연결됨 — 승인 금액 5,000원 …"으로 보이는지 확인한다. 빨간 글자로 이유가 나오면 그 이유대로 값을 고친다(호출은 아직 없다). **값이 틀리면 리포트는 개발용 규칙 생성기로 만들어지므로(비용 없음) 실제 AI 시험이 아니다 — 두 줄이 모두 "실제 Claude 연결됨"인지 꼭 확인한다.** 키 값은 화면에 나오지 않는다.
5. **리포트 만들기** — 카카오로 로그인 → 무료 분석 → 결과 화면에서 심층 리포트 결제(테스트 결제 9,900원, 실제 돈은 나가지 않는다) → "리포트를 만들고 있어요"에서 기다린다(몇 분). 완성되면 결과 화면의 리포트와 채팅방(상담방)의 풀이를 읽어 본다. **글이 어색하거나 오류 안내가 나오면 계속 시도하지 말고 화면(또는 오류번호)을 알려 준다.**
6. **채팅 질문 해 보기** — 상담방(예: 연애)에서 무료 질문을 보내 본다. 무료 질문을 다 쓰면 안내창이 뜨고, 입력칸 자리가 **[질문 3개 구매하기]** 버튼 하나로 바뀐다(그전에는 입력창 위에 작은 구매 버튼이 있다). 이 버튼을 누르면 **결제 화면(질문 3개 = 2,500원 부가세 포함, 테스트 결제)으로 넘어가고, 결제를 마치면 채팅방으로 돌아와 입력창이 열린다 — 그때 질문을 적어 보내면 된다(구매한 3개 중 하나가 쓰이고 남은 2개는 이어서 쓴다).** 결제 · 환불 · 중복 · 동시 질문까지 끝까지 확인하는 순서는 [`question-pack-live-test.md`](./question-pack-live-test.md).
7. **호출 수 · 비용 확인(읽기만 함)** — SQL Editor에 `supabase\check-chat-usage.sql`을 붙여넣고 Run. 결과 표 하나(리포트 · 맛보기 · 채팅 호출 수 · 비용 어림 · 막은 호출)를 알려 준다. "청구될 수 있는 호출 전체 … 여유율 1.1 포함" 줄이 승인 5,000원과 비교하는 값이다. 실제 청구 금액은 Anthropic 콘솔의 사용량으로도 본다.
8. **끝나면 연결을 끊는다** — `.env.local`에서 `AI_PROVIDER` · `AI_CHAT_PROVIDER` · `AI_APPROVED_*`를 지우고(비우고) 서버를 다시 켠다. 리포트는 개발용 생성기로, 입력창은 "준비 중"으로 돌아간다. (승인 기간이 지나면 값을 남겨 둬도 호출하지 않는다.)

실패하면: 승인 가드가 막으면 리포트는 "리포트를 만들지 못했습니다 · 다시 만들기"(결제는 정상), 채팅은 "이번에는 답을 만들지 못했어요"가 나오고 **Anthropic에는 요청이 나가지 않으며** 횟수 · 결제한 질문도 쓰이지 않는다. 승인 금액 · 호출 수를 더 쓰고 싶으면 운영자가 값을 다시 정해 알려 주고, 코드 상한(5,000원 · 60회 · 7일, `lib/config/ai-candidates.ts`의 `LIVE_TEST_LIMITS`)을 넘기려면 클로드가 다시 확인한 뒤 고친다.
