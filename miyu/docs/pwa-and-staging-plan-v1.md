## 2. 홈 화면 추가 안내 정책

- 위치: **푸터의 접힌 글 한 곳**("홈 화면에 추가해서 앱처럼 열기", `components/site/home-screen-tip.tsx`). 눌러야 펼쳐진다. 모달 · 팝업 · 자동 설치 · 설치 프롬프트 가로채기(`beforeinstallprompt`)는 **하지 않는다**(브라우저가 허용하지 않는 자동화 없음).
- 환경별 문구(`lib/pwa/home-screen.ts`, 사용자 에이전트(UA) 문자열 어림 — 틀릴 수 있다):

| 환경 | 안내 |
| --- | --- |
| iPhone/iPad Safari | 공유 버튼 → "홈 화면에 추가"(목록 아래쪽에 있을 수 있어요) → "추가". 홈 화면 앱은 Safari와 로그인이 따로일 수 있다고 알림 |
| iPhone의 다른 브라우저(Chrome · Edge · Firefox) | 이 브라우저의 공유 메뉴에서 찾고, 없으면 Safari에서 열기 |
| Android Chrome | ⋮ 메뉴 → "홈 화면에 추가" 또는 "앱 설치" |
| Android 삼성 인터넷 등 | 브라우저 메뉴에서 "홈 화면에 추가"/"현재 페이지 추가", 없으면 Chrome에서 열기 |
| 카카오톡 · 인스타그램 · 네이버 앱 안 브라우저 | 홈 화면에 추가할 수 없다고 알리고 "다른 브라우저로 열기"로 Safari(iPhone) / Chrome(Android)에서 열게 함 |
| 데스크톱 · 알 수 없음 | 안내 없음 |

- **이미 홈 화면 앱으로 열린 화면에는 보이지 않는다**: `display-mode: standalone`(+ `fullscreen` · `minimal-ui` · `window-controls-overlay`) 또는 iOS `navigator.standalone === true`. 서버가 그린 HTML에는 없고(브라우저를 알 수 없다) 화면이 열린 뒤에만 나타나서 깜빡이지 않는다.
- 메뉴 이름은 OS · 브라우저 버전에 따라 다르다. **실기기에서 실제 메뉴 이름과 맞는지 확인하기 전에는 문구를 확정으로 보지 않는다**(체크리스트 R1).

## 4. 폴드8 · 아이폰 듀오 — 반응형 모의 검사

### 4-1. 공식 사양에서 읽은 것 (조회 2026-10-19)

운영자가 알려 준 두 페이지를 열어 화면 항목을 읽었다. **페이지 본문을 요약 도구로 읽은 값이라 운영자가 한 번 더 눈으로 확인하는 것을 권한다.**

| 화면 | 물리 해상도(픽셀) | 화면 크기 · 비고 | 출처 |
| --- | --- | --- | --- |
| iPhone Duo 안쪽 | 1878 × 2670 (430 ppi) | 7.6인치 접이식 OLED | https://www.apple.com/iphone-duo/specs/ |
| iPhone Duo 바깥 | 1398 × 2034 (460 ppi) | 5.4인치 OLED | 같은 페이지 |
| Galaxy Z Fold8 메인(안쪽) | 1848 × 2448 | 7.6인치, 4:3 | https://www.samsung.com/uk/business/smartphones/galaxy-z/galaxy-z-fold8-lavender-256gb-sm-f971blvbeub/ |
| Galaxy Z Fold8 커버(바깥) | 1972 × 1248 (세로로 세우면 1248 × 1972) | 5.5인치, 10:16 | 같은 페이지 |
| 기기 치수 | iPhone Duo 펼침 164.6 × 117.8mm / 접힘 84.1 × 117.8mm. Fold8 펼침 161.4 × 123.9mm / 접힘 81.9 × 123.9mm | 펼친 모양이 가로로 넓은 4:3에 가깝다 | 같은 페이지 |

**두 페이지 어디에도 CSS 폭(viewport)이나 화면 배율(DPR)은 적혀 있지 않다.** 그래서 **물리 해상도를 CSS 폭으로 쓰지 않는다.**

### 4-2. 방법 — 가정한 배율로 나눈 크기를 여러 개 본다

`lib/qa/viewport-matrix.ts`(시험 `viewport-matrix.test.ts` — 물리 폭 그대로를 크기로 쓰는 항목이 없고 모든 크기가 "가정"으로 표시됐는지 확인):

- 각 화면의 물리 해상도 ÷ **가정한 배율 2 · 2.5 · 3** = CSS 크기(예: 안쪽 1878 × 2670 → 939 × 1335 / 751 × 1068 / 626 × 890). **어느 배율이 실제인지 모른다.**
- 일반 폰 기준(320 · 360 · 390 · 412)과 **가장 좁은 폭 280**(사양에서 온 값이 아닌 최악 폭).
- **접힘 = 바깥 화면 크기, 펼침 = 안쪽 화면 크기**로 창 크기를 바꾼 것이다. 가로 · 세로는 폭과 높이를 바꾼다.
- 분할 창: 안쪽 화면의 반 폭 · 1/3 폭(최소 240px로 제한 — 기기가 더 좁은 창을 허용하는지 모른다), 작은 떠 있는 창 400 × 600.
- 키보드: 보이는 높이를 약 55%로 줄인 것(실제 키보드가 화면을 줄이는 방식은 iOS · Android가 다르다).
- 글자 확대: 루트 글자 크기 130 · 150 · 200%(320 · 390 · 안쪽 616 폭).
- 점검(`scripts/qa-responsive.ts`): 가로 넘침 · 폭 밖 요소 · 글자 잘림 의심 · 24px 미만 눌리는 요소(44px 미만은 참고) · 끝까지 내렸을 때 마지막 눌리는 요소가 고정 막대에 가려지는지 · 6장 인생 흐름 시간축(막대 크기 · 겹침 · 상자 밖) · 시기 카드 · 채팅 입력줄이 보이는 높이 안인지 · **상태 유지**(접고 펴고 돌리고 분할하는 동안 분석 입력 · 채팅 입력 글 · 펼친 카드 · 스크롤).
- 화면: 홈 · 분석 · 간단 궁합 · 리포트 예시 · 예시 대화 + (로그인) 결과 리포트 · 상담방 · MY · 리포트 궁합 쌍.

### 4-3. 결과 (반응형 모의 검사 — 실제 폰 아님)

**이 문서를 처음 올린 커밋 시점에는 결과가 없다 — 대표 크기 14개 × 화면 9개 + 글자 확대 + 상태 유지 실행이 아직 끝나지 않았다(미기록, 통과로 읽지 않는다).** 끝나면 다음 커밋에서 이 칸에 날짜 · 점검 건수 · 문제 목록 · 고친 것을 적는다. 다음 두 가지는 이미 확인했다:
- 크기 표 자체: `lib/qa/viewport-matrix.test.ts` 5개 통과(물리 폭을 그대로 쓰지 않음 · 모두 가정 표시 · 접힘/펼침/세로/가로/분할/키보드/좁은 폭 포함).

### 4-4. 한계

- 창 크기를 바꾼 것이지 접이식 기기가 아니다 — 힌지 · 화면 전환 중 앱이 다시 그려지는 방식, 두 화면 사이의 재개, 주름 부근 터치, 다른 앱과 나란히 두는 분할의 실제 최소 폭, 실제 주소창 · 시스템 막대 · 키보드 높이를 보지 못했다.

현재: miutest는 **테스트용 사이트**이고 Supabase `wdvrwwajakjdfrajgxcm`도 사용자가 **미유 테스트 전용으로 확정**했다(2026-10-19). 그러나 migration 26의 외부 적용 · 외부 DB QA는 별도 지시 전까지 하지 않고(Windows 방의 읽기 전용 사전점검만 진행 중) 이 세션은 로컬 모의 QA만 한다. 실기기 · 홈 화면 설치 · 카카오 복귀 · 토스 결제 복귀는 모두 **미실행**이다.

### 6-1. 반드시 만족해야 하는 조건

1. **공개 HTTPS 주소**: 휴대폰이 열 수 있어야 하고(`localhost`는 폰에서 닿지 않는다), 홈 화면 앱 설치는 HTTPS에서 가장 확실하다(LAN IP의 `http://`는 iOS는 "홈 화면 추가"가 되지만 Android는 설치가 아니라 바로가기에 그칠 수 있다 — 미확인).
2. **운영과 분리**: 별도 Supabase 프로젝트 · 별도 배포 프로젝트 · 별도 카카오 앱 또는 별도 리다이렉트 · 별도 알림 방. 운영 키가 한 곳에도 들어가지 않는다.
3. **실결제 0 · 실제 AI 0**: 토스 **테스트 키**만, `PAYMENTS_LIVE_MODE` 비움, `AI_PROVIDER`는 비움(아래 6-5 결정 필요).
4. **접근 제한**: 주소를 아는 누구나 가입 · 저장하지 못하게(6-3).
5. **키는 대화에 붙이지 않는다**: 운영자가 각 화면에 직접 입력.

| 배포할 브랜치 | 작업 브랜치(`claude/miyu-claude-code-setup-klw8ms`)를 Production으로 지정하거나, 운영자가 승인한 별도 스테이징 브랜치. **`main`에는 `miyu/`가 없어서 `main`을 배포하지 않는다** |
| 환경 | **Production 범위에만** 값을 넣는다(Preview에 넣지 않는다 — Preview는 안전 장치가 DB를 막는다). `PREVIEW_ALLOW_DATABASE`는 쓰지 않는다 |
| 보호 | **Settings → Deployment Protection → All Deployments + Vercel Authentication**(권장 기본). 폰에서 열 때는 Vercel 로그인 화면이 먼저 나온다. iOS 홈 화면 앱은 Safari와 저장소가 따로라 **앱 안에서 Vercel 로그인을 한 번 더** 해야 할 수 있다 — 불편하면 "Protection Bypass for Automation"(공유 링크의 비밀 값이 주소에 들어간다 · 링크를 아는 사람은 열 수 있다 · 스테이징 DB에 시험 계정만 있다는 전제)을 **운영자가 따로 결정**한다 |
| 검색 노출 | Vercel 보호가 켜져 있으면 검색에 나오지 않는다. 보호를 끄거나 우회 링크를 쓰면 `robots.ts`가 **공개 화면은 허용**하므로 스테이징 전체를 `noindex`로 막는 스위치가 필요하다(**지금 코드에 없다 — 결정 후 작은 변경**, 6-6) |

### 6-4. 필요한 설정 이름 (값은 운영자가 직접 · 비밀값 없이)

이름 · 설명만 적는다. 값은 이 문서 · 채팅 · 커밋 어디에도 넣지 않는다(`.env.example` · `deploy-vercel-test.md` 4단계와 같은 이름).

### 6-5. 결정이 필요한 것 — 스테이징에서 궁합 2종 · 결제 · 공동 열람을 시험하는 AI 연결

코드 확인(`server/pair.ts` · `app/compat/actions.ts` · `lib/services/compat-service.ts`): **AI가 연결되지 않으면(`AI_PROVIDER` 비움) 사주 궁합 · 리포트 궁합의 결제가 `ai-not-connected`로 막힌다.** `mock-local`(가짜 AI)은 `127.0.0.1` 주소만 받아서 Vercel 서버에서는 쓸 수 없다. 그래서 호스팅된 스테이징에서는 개인 심층 · 무료 · 채팅 방 · 결제 · 환불 흐름은 시험되지만 **궁합 2종의 결제 · 생성 · 공동 열람은 시험되지 않는다.**

| 안 | 내용 | 비용 · 승인 |
| --- | --- | --- |
| A. 궁합 2종은 스테이징에서 보류 | 나머지 흐름만 시험하고, 궁합 2종은 지금까지의 로컬 결과(`launch-qa-evidence-2026-10-19.md`)에 둔다 | 승인 불필요. 단 **출시 판단 기준 ③(스테이징 결제 · 환불 · 공동 열람)이 궁합에는 비어 있게 된다** |
| B. 서버 안에서 도는 모의 모델 스위치를 신설 | `AI_PROVIDER=mock-builtin`처럼 저장소의 모의 작성기를 서버 안에서 쓰는 시험 전용 값(테스트 결제 모드에서만, 글은 "[모의 생성] … 판매할 수 없는 글"로 표시) | **코드 변경이므로 운영자 승인 필요**(v1 범위 동결 — 새 기능이 아니라 시험 도구). 실제 AI 호출 0. 판매에는 쓰지 못한다 |
| C. 실제 AI | 별도 승인 금액 · 호출 수 · 기간 | 이번에는 하지 않는다(추가 AI 호출 금지) |
| D. PC + 터널 | 6-2의 터널 | 외부 터널 계정 승인 필요 |

권장: **B를 승인받아 스테이징에서 궁합 2종까지 시험**하되, 승인 전에는 A로 두고 "스테이징 궁합 미실행"을 숨기지 않는다.

### 6-6. 격리 점검 목록 (운영자)

- [ ] 스테이징 Supabase는 새 프로젝트이고 `apply-staging-all.sql`(비어 있는 프로젝트 전용 · 표가 있으면 멈춤)로만 적용했다. **운영 DB에 이 파일을 실행하지 않는다.**
- [ ] 스테이징 환경에 운영 키가 한 개도 없다(Vercel 프로젝트가 따로이고 환경 범위가 Production뿐이다).
- [ ] 토스 키가 `test_` 로 시작하고 `PAYMENTS_LIVE_MODE`가 비어 있다(결제 화면 상단에 테스트 표시가 보인다).
- [ ] 실제 AI 키가 없다(`ANTHROPIC_API_KEY` 없음).
- [ ] 시험 계정은 가짜 이메일/별명이고 실제 고객 정보가 없다. 시험이 끝나면 계정 · 데이터를 지운다(스테이징 프로젝트를 지우면 된다).
- [ ] 접근 제한(Vercel Authentication) 또는 운영자가 결정한 대안이 켜져 있다. **우회 링크를 쓰면 전체 noindex 스위치를 먼저 정한다.**
- [ ] 카카오 앱: 스테이징용 Redirect URI(스테이징 Supabase의 `…/auth/v1/callback`)를 **운영 카카오 앱과 분리**해서 둘지 같은 앱에 더할지 운영자가 정한다(운영 앱 설정을 바꾸기 전에 따로 판단).
- [ ] 알림: 시험용 텔레그램 방(운영 알림 방과 섞이지 않게) 또는 비움.

### 6-7. 로그인 · 결제 복귀 주소 (등록할 곳)

| 용도 | 주소 | 어디에 알리나 |
| --- | --- | --- |
| 로그인 완료(카카오 · 이메일 확인 · 비밀번호 재설정이 돌아오는 곳) | `<스테이징>/auth/callback` (`?next=` 붙음) | Supabase → Authentication → URL Configuration → Site URL = `<스테이징>`, Redirect URLs = `<스테이징>/**` |
| 카카오 로그인 Redirect URI | 스테이징 Supabase 주소의 `/auth/v1/callback` (Supabase가 카카오에 알려 주는 주소) | 카카오 디벨로퍼스 → 카카오 로그인 → Redirect URI. 카카오 웹 도메인에 `<스테이징>`도 등록 |
| 결제 성공 / 실패 복귀 | `<스테이징>/payments/success` · `<스테이징>/payments/fail` (코드가 `window.location.origin`으로 만들어서 **주소를 미리 등록하지 않아도** 되는 구조 — 토스 테스트 환경이 허용 도메인을 따로 요구하는지는 문서로 확인하지 못했다, 테스트 결제 첫 시도에서 확인) | (등록 없음) |
| 결제 웹훅 | **등록하지 않는다**(Vercel 보호가 켜져 있으면 닿지 않고, 승인 · 환불은 결제 재조회로 맞춘다) | — |
| 정기 점검 | `<스테이징>/api/cron/reconcile` | Vercel Production 배포에서만 하루 한 번(Hobby) — `CRON_SECRET` 필요 |

### 6-8. 순서 (운영자가 직접 · 한 번에 한 단계)

1. 스테이징용 Supabase 새 프로젝트를 만든다 → `apply-staging-all.sql` 한 번 실행 → 확인 표에서 1~25번 "적용됨"(`staging-setup-guide.md` 1~2장).
2. (miutest 확인 결과에 따라) Vercel에 **새 프로젝트** `miyu-staging`을 만들거나 miutest를 6-3 · 6-4 · 6-6에 대조한다(Root Directory `miyu`) → Production 브랜치 지정 → 환경변수(6-4)를 Production에 직접 입력 → 보호를 켠다(6-3).
3. 6-5 결정(AI 연결 방식)을 알려 준다.
4. 첫 배포가 끝나면 `/admin`(시험 관리자 계정)의 "배포 정보"에서 환경 · 브랜치 · 커밋이 맞는지 본다(`deploy-vercel-test.md` 9단계).
5. Supabase · 카카오에 6-7의 주소를 등록한다.
6. 이메일 가입 → 확인 메일 도착 확인(SMTP 설정이 필요하다, `staging-setup-guide.md` 4장).
7. 폰으로 접속해 이 문서 5장을 **환경별로** 한 번씩(iPhone Safari → 홈 화면 앱 · Android Chrome → 홈 화면 앱 · 카카오톡 인앱 둘 · 접이식).
8. `staging-test-plan.md`의 12줄 흐름(가입 → 추천 → 포인트 → … → 개인정보 · 접근)을 시험한다.
9. 결과(통과 / 실패 + 한 줄 사유 · 오류번호 · 시각)를 알려 준다. 키 · 비밀번호 · 고객 정보는 붙이지 않는다.
10. 끝나면 `MIYU_TEST_OPEN_SALES`를 지우고 혜택 스위치를 끈다.

### 6-9. 하지 않은 것

- 배포 · 외부 서비스 연결 · DB 변경 · 결제 · 카카오/토스/Supabase 설정 · 터널 사용 · 실제 AI 호출. 위는 모두 **운영자가 직접 해야 하는 항목의 구체화**이고 이 세션은 실행하지 않았다.
- 스테이징으로 쓸 주소의 용도 · 격리가 확인되지 않았으므로 이 문서의 어떤 항목도 "스테이징에서 통과"로 쓰지 않는다.

## 7. 이 문서가 바꾸지 않은 것

개인 화면의 저장 금지(`private, no-store`) · 검색 제외 · 권한 확인 · 개인정보 처리 · 결제 · 판매 스위치 · AI 승인(6/6) · 실제 AI 호출 0.
