# 이용 후기(리뷰) 시스템 v1

운영자 요청(2026-10-17): 신규 방문자의 신뢰를 높이고, 무료 분석과 유료 리포트 구매 전에 **실제 이용자의 경험**을 볼 수 있게 한다. 이 문서는 구현한 구조 · 규칙 · 확인한 것 · **확인하지 못한 것**을 적는다.

> 개발 · 테스트 환경에서만 만들고 확인했다. 운영 DB 적용 · 실제 보상 지급 · 공개 배포 · 유료 AI 호출은 하지 않았다. 후기 글을 AI로 만들거나 고치거나 요약하는 코드는 없다.

## 3. 규칙

### 3-1. 이용 자격(서버가 모두 다시 확인)

화면이 보낸 종류 · 이용 건 번호를 믿지 않는다. 서비스가 본인 소유와 상태를 다시 읽는다.

- **개인 리포트**: 본인의 개인 통합 리포트 주문(상품 번호 `personal-integrated-report…`) + 상태 결제 완료 + 그 리포트 `ready`. 이용 건 번호 = 주문 번호.
- **사주 궁합**: 본인의 `saju-compat:<id>` 주문 + 결제 완료 + 리포트 `ready`.
- **리포트 궁합**(2026-10-17 연결): `PairReviewEligibility`(`list` · `find`)를 `lib/services/pair-review.ts`가 채운다. **결제한 사람의 이용 건 하나(쌍의 결제 주문)**만 — 결제 완료 + 리포트 완성 + 환불 아님 + 그 사람이 동의를 철회하지 않아 지금도 글을 읽을 수 있음. 상대(결제하지 않은 사람)는 같은 글을 읽어도 후기 · 보상 대상이 아니다(구매 한 건에 보상 한 번). 혜택으로 받은 0원 주문은 "무료 체험"이고 보상은 쿠폰의 후기 보상 허용이 있을 때만이다. 시험 `pair-review.test.ts` 3개(결제자만 · 상대 불가 · 만드는 중 불가 · 철회 · 환불 · 남의 주문 번호 · 보상 한 번). 쌍 표(DB 24번)가 없으면 리포트 궁합 후기만 없는 것으로 본다.
- **미유 채팅**: 본인의 검사 결과에서 **답을 받은** AI 질문(`chat_questions`, 16번 이후의 예약 중 `state = reserved`는 세지 않음)이 있을 때, 결과 번호당 한 번.
- 환불된 주문 · 결제 대기 · 리포트 생성 중/실패 · 다른 종류의 주문 번호는 모두 거절. 탈퇴하면 후기가 지워진다.
- **무료 체험**: 혜택으로 받은 0원 주문(체험단 · 쿠폰 · 포인트 교환)도 후기를 쓸 수 있고 "무료 체험 제공"으로 표시된다. 질문권 보상은 쿠폰의 `후기 보상 허용(reviewRewardEligible)`이 있을 때만 나온다(없으면 `ineligible`). 채팅은 그 결과로 심층 리포트를 산 적이 없으면 무료 체험으로 본다(운영 판단 — 운영자 확인 항목).

### 3-2. 보상(질문권)

- 한 건 = 질문권 `review.reward_credits`개(기본 1), 유효기간은 `credit.expire_days`(기본 1년). 별점 · 내용 방향 · 공개 동의와 무관하게 같다. 최소 글자 수(`review.min_body_chars`, 기본 20)만 본다.
- **글자 수가 모자라면 저장하지 않는다**(보상만 빼고 저장하지 않고 하나로 정했다 — 별점만으로 보상을 받을 수 없고, 설정을 0으로 하면 별점만도 가능). 수정할 때도 같은 기준이라 보상을 받은 뒤 글을 비울 수 없다. 같은 글자만 되풀이한 글 · 가림 표시(`[연락처 가림]`)로 채운 글은 채운 것으로 치지 않는다.
- 순서: ① 후기 저장(보상 상태를 쓸 때 정함: `pending`/`off`/`ineligible`) → ② `grantCredit`을 멱등 키 `review:<후기 번호>`로 부름 → ③ 결과로 `granted`/`failed` 확정. 질문권만 들어가고 확정 기록이 안 남았어도 다음에 같은 키로 맞추면 `duplicate`로 확정되어 **두 번 들어가지 않는다**.
- **스위치가 꺼져 있으면** 후기만 저장(`off`, 대가 표시 없음). 나중에 켜도 **소급하지 않는다** — 대가 표시와 어긋나지 않게(쓸 때의 표시가 기록으로 남는다). 지급이 실패해도 후기 저장은 막지 않고 `failed`로 남겨, MY를 열 때 · 관리자 버튼으로 다시 맞춘다.
- 수정 · 삭제 · 비공개 전환 · 다시 쓰기에서 **다시 지급도 회수도 하지 않는다**. 이미 쓴 질문권도 되찾지 않는다. **환불된 주문의 후기 보상은 회수하지 않는다**(운영자 확인 항목).

### 3-3. 공개 · 대가 표시

- 공개 후기 = `status = published` AND `public_consent = true`. 공개 동의는 처음에 **꺼져 있다**(작성자가 직접 눌러야 공개). DB 검사로 "공개 중이면 동의가 있어야 한다"를 막는다.
- 후기마다 종류 이름표 · 별점 · 글 · 날짜 · **대가 표시**("질문권 보상 제공" / "무료 체험 제공", 둘 다 해당하면 둘 다)가 보인다. 표시 문구는 **가안**이다(법정 문구는 법률 검토).
- 작성 화면에 공개 전 안내를 항상 보인다: 사주 · 관계 · 상담의 구체적 내용, 이름 · 생년월일 · 상대 정보는 적지 말 것 / 공개에 동의하면 메인과 전체 후기에 보임 / 동의하지 않으면 나만 보고 운영 기록 용도로만 쓰임 / 보상은 같다 / 미유는 후기를 고치거나 요약하거나 AI로 만들지 않음. 동의한 시각과 그때의 안내 판(`REVIEWS.noticeVersion`)을 후기마다 남긴다.
- 서버는 저장 전에 연락처 · 이메일 · 주민번호 · 카드 · 계좌처럼 보이는 부분만 가린다(`lib/personalization` 규칙 재사용). 그 밖에는 글을 고치지 않는다.
- 운영자가 숨긴 후기는 회원이 고치거나 공개를 바꿔도 다시 공개되지 않는다(숨김 해제는 운영자만). 운영자가 삭제한 후기는 회원이 다시 쓸 수 없다. 회원이 직접 지운 후기는 다시 쓸 수 있되 보상은 없다.

### 3-4. 메인 후기 영역

- 순서: 첫 소개 · 미유 캐릭터 → 궁합 → 상담 주제 → **실제 이용 후기** → 리포트 예시 · 가격 → FAQ.
- 공개 후기가 `REVIEWS.minToShowOnHome`(기본 1)개 미만이면 `null` — 제목도 빈 상태도 그리지 않는다. 가짜 후기로 채우지 않는다. DB가 연결돼 있지 않거나 후기 표가 없거나 읽다 오류가 나도 이 영역만 사라지고 홈은 그대로다.
- 최대 `REVIEWS.homeMax`(6)개. 운영자가 고른(선정) 후기를 먼저, 그다음 최신순. 종류 묶음(개인 · 궁합 · 채팅)마다 하나씩 먼저 담아 종류가 섞이게 한다. **별점 · 글의 긍정 · 부정으로 고르지도 거르지도 않는다.** [전체 후기 보기]는 항상 보인다.
- 긍정 후기만 골라 전체 반응처럼 보이지 않게: 별점 분포를 관리자 화면에서 "작성한 후기 전체 · 공개 중 · 메인에 보일 후기"로 나란히 본다.

### 3-5. 신고

공개 중인 후기에만, 로그인 없이. 이유는 개인정보 · 욕설 혐오 · 허위 광고 · 그 밖(**"내용이 마음에 들지 않아요"는 이유에 없다**). 같은 방문자(익명 방문 번호 쿠키)가 같은 후기를 두 번 신고하면 한 번으로 센다. 1분에 5건까지. 신고는 후기를 바로 숨기지 않는다 — 운영자가 읽고 정한다. 신고자의 이름 · 연락처는 받지 않는다.

### 3-6. 관리자

- 조치: 숨김 · 숨김 해제 · 삭제 · 메인 선정 · 선정 해제 · 신고 기각. **모두 사유 분류가 필수**이고 조치에 맞는 분류만 받는다(DB의 이력 표 검사로도 막는다). 기타는 메모 필수. **"부정적인 내용"이라는 분류는 어디에도 없다.**
- 이력 `review_admin_log`: 누가 · 언제 · 무엇을 · 사유 분류(+ 120자 메모). **후기 글은 복사하지 않는다.** 상태 변경과 이력 기록은 DB 함수 한 번에(한쪽만 남지 않는다). 운영 기록(`ops_events`)에는 후기 번호 앞 8자 · 조치 이름만.
- 선정 기준(화면에 적음): 글의 내용(구체적 이용 경험 · 처음 보는 분께 도움)과 종류 균형 — 별점 · 긍정/부정으로 고르지 않는다. 선정 · 해제는 이력에 남는다. (메인에 후기가 몇 번 보였는지 후기별 노출 횟수는 기록하지 않는다 — 새로 수집하는 개인 관련 기록을 늘리지 않으려는 판단.)
- 공개 후기 개인정보 점검: 공개 중인 후기 글을 연락처 · 이메일 · 긴 숫자 · 연도가 있는 날짜 · 생년 표현 · 주소 · 계정 아이디 표현으로 다시 훑어 **의심 후보**를 모은다(점검한 수를 함께 보인다 — "의심 없음"과 "점검하지 않음"이 구분된다). 판정이 아니다.
- 나만 보기 후기도 관리자 목록에서 읽을 수 있다("운영 기록 용도"라고 작성 화면에 알린 범위).

| **열람 후 유료 결제율** | **계산하지 않는다.** 주문과 익명 방문 기록이 이어져 있지 않다. 화면에 이유와 "후기 영역을 보여 주는 쪽과 숨기는 쪽을 나눠 비교하는 A/B 테스트가 필요"를 적었고, 열람자 · 비열람자의 결제율 차이를 후기의 효과라고 말하지 않는다 | — |

## 4. 화면 · 주소

- 홈 `/` — 후기 영역(공개 후기가 있을 때만). 열람 · 클릭은 `trackOnce`로 기록(추적 거부 신호가 있으면 기록하지 않음).
- `/reviews` — 전체 후기(`?kind=personal|compat|chat&page=`). 검색 제외(`noindex`) — 공개하고 싶으면 `app/reviews/page.tsx`의 `robots`만 바꾼다.
- `/my/reviews` — 아직 쓰지 않은 적격 건(쓰기 · 지운 후기 다시 쓰기) + 내가 쓴 후기(고치기 · 나만 보기/공개 전환 · 지우기 · 보상 상태). 리포트 · 사주 궁합 열람 화면 아래의 작은 "후기 남기기" 링크가 `?kind=&ref=`로 이 화면의 해당 칸을 펼친다. MY 허브에 바로가기 줄 "내가 작성한 리뷰".
- `/admin/reviews` — 위 3-6 · 3-7. `/admin`에 링크.
- `/dev/reviews-preview` — 화면 디자인용 가상 문구(모두 `[가상 문구]`로 시작, 운영 빌드에서는 열리지 않고 `noindex`). **실제 홈 · `/reviews`에는 가짜 후기를 넣지 않는다.**

## 8. 설계 판단 기록

- **보상은 DB 함수 안이 아니라 서비스가 `grantCredit`을 부른다**(질문권 장부 · 멱등 키는 기존 그대로, 후기 표에 보상 상태 `pending`/`granted`/`failed`로 앞뒤를 맞춤). 장부 로직을 한 곳에 두고 보상 지급 오류가 후기 저장을 막지 않게 하려는 선택이다.
- `reviews.free_trial`(무료로 제공받은 이용) 열을 더했다 — `disclosure` 하나로는 "무료 체험이면서 질문권 보상도 받음"을 둘 다 표시할 수 없어서다.
- 운영자가 지운 후기는 회원이 다시 쓸 수 없다(`deleted_by = admin`). 숨김 중에는 회원이 고쳐도 공개되지 않는다 — 운영 조치를 회원이 되돌리지 못하게.
- 이력 · 신고는 후기와 함께 지워진다(탈퇴 시 `on delete cascade`). 운영 기록(`ops_events`)의 후기 번호 줄은 남는다.
- `funnel_events` 이름 검사는 **나열한 목록을 유지**했다(기존 5개 + 후기 이벤트 2개, 결제 이벤트 같은 이름은 계속 거절). 서버 코드의 목록과 같은지 `server/review-migration.test.ts`가 확인한다. 다른 변경이 이름을 더하면 같은 방식으로 목록을 늘린다.

## 9. 법률 검토 · 운영자 확인 항목

법률 검토(문구를 만들지 않았다)

- 대가(질문권 보상 · 무료 체험)를 받고 쓴 후기의 표시 방식 · 문구(지금 "질문권 보상 제공" · "무료 체험 제공"은 **가안**).
- 후기 · 이력 · 신고의 보관 기간 · 탈퇴 후 처리, 공개 동의의 철회와 이미 게시된 후기의 처리, 약관 · 처리방침 문구.
- 후기 공개에서의 개인정보(글에 사주 · 관계 내용이 담길 수 있음) 처리 근거, 신고자 익명 번호(쿠키)의 처리.

운영자 확인

- 채팅 후기의 "무료 체험" 판단(심층 리포트를 산 적이 없는 결과 = 무료 체험)과 **무료 질문으로도 보상이 나온다는 점**. 한 사람이 검사 결과를 여러 개 만들어 반복하면 결과 번호마다 채팅 보상을 받을 수 있다(무료 질문 수 자체는 방 단위라 늘지 않고, 하루 검사 저장 한도가 있다). 필요하면 채팅 후기 보상을 계정당 1회로 제한한다.
- 환불된 주문의 후기 · 보상 처리(지금은 후기도 보상도 그대로).
- 선정 기준 문장과 메인 · 전체 후기 화면의 안내 문장("운영자가 고른 후기가 먼저 보일 수 있어요. 별점이나 긍정 · 부정으로 고르지 않고…")은 운영 원칙을 공개 문장으로 옮긴 것이다.
- 최소 글자 수 20 · 메인 최대 6 · 보상 1개는 가안이다.
