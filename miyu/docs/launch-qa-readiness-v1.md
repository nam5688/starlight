# 출시 필수 QA 준비 목록 (2026-10-18 · 준비만 — 아무것도 실행하지 않았다)

운영자 조율(2026-10-18): 궁합 2종 · 결제 · 환불 · 공동 열람 · 개인정보 · 모바일을 **테스트 입력 · 기대 결과 · 증거 · 승인 필요 여부**로 나눠 준비한다. 실제 결제 · 공유 배포 · 운영 DB · 유료 AI 호출 없이 목록만 만들었다.

- **이 문서의 모든 항목은 "미실행"이다.** 자동 시험(`npm run check`, 로컬 임시 DB · 가짜 결제사 · 모의 AI)이 통과한 것은 스테이징 · 실제 휴대폰 · 실제 AI에서 확인한 것이 아니다. **기존 체크 통과를 출시 GO로 보지 않는다.**
- **증거가 없으면 완료로 세지 않는다.** 증거는 항목 번호를 붙여 보관한다(예: `Q-PAY-03-토스취소내역.png`, `Q-PAIR-02-접근거부응답.txt`). 증거에 개인정보 · 키 · 결제 정보가 보이면 가리고 보관한다.
- 흐름의 전체 순서와 자동 시험이 이미 확인한 것은 `staging-test-plan.md`, 환경 준비는 `staging-setup-guide.md`, 법률 검토 항목은 `legal-review-list.md`, 대응 절차는 `runbook.md`가 말한다. 이 문서는 그 위에서 **출시 판단 5개 기준 가운데 ③ 스테이징 테스트 · ④ 개인정보 · ⑤ 모바일 · ② 궁합 AI 품질**을 항목별 증거로 닫기 위한 목록이다.
- **승인이 필요한 일(표의 "승인")**: ㉠ 스테이징 Supabase 프로젝트 만들기 · 마이그레이션 적용 · 환경변수 입력 — 운영자가 직접 ㉡ 토스 **테스트 키** 결제(실결제 아님) — 운영자가 직접, `PAYMENTS_LIVE_MODE=false` 확인 ㉢ 실제 AI 호출 — 별도 승인(지금은 추가 호출이 승인되지 않았다) ㉣ 공유 배포(Preview 포함) — 별도 승인. **실결제 · Production 배포는 이 목록의 어떤 항목에도 포함하지 않는다.**

상태 표시: **미실행** = 아직 하지 않음 · **자동만** = 로컬 임시 DB / 가짜 결제사 / 모의 AI 시험은 있음(실제 환경 미확인).

## 8. 이 목록이 하지 않는 것

- 실결제, 운영 DB 변경, 공유 배포(Preview 포함), 보상 실지급, 유료 AI 호출 — 하지 않았고 이 목록은 그 승인이 아니다.
- 항목을 "통과"로 표시하지 않았다. 증거가 모이기 전에는 상태 칸을 바꾸지 않는다.
- 개인 심층 콘텐츠의 합격 · 동결을 선언하지 않는다 — 실제 전문과 근거를 운영자가 대조해 품질에 도달했을 때만 동결한다(아직 미검증).
