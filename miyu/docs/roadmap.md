## 2~3단계 중 이번에 구현한 것 (2026-10-12)

### 계획

1. 검사 · 채점 · 리포트 · 주문 규칙을 채널과 무관한 코드(`lib/`)로 분리하고, 저장소 · 결제사 · 생성기는 약속(인터페이스)으로 연결
2. Supabase 표 · 접근 정책(RLS) · 상태 규칙 트리거
3. 카카오 로그인(Supabase Auth) + 로그인 전 결과 보관(암호화 쿠키) → 로그인 후 저장
4. 토스페이먼츠 주문서형 결제위젯 테스트 결제 → 서버 승인 → 구매 권한 → 리포트 생성 → 같은 버전 다시보기
5. 웹훅, 실패 · 취소 · 응답 유실 처리
6. 검증: 단위 테스트, 실제 DB 테스트, 로컬 Supabase 비슷한 환경에서 전체 흐름 브라우저 테스트

### 완료 항목

- [x] 핵심 로직 분리: `lib/services`(저장 · 주문 · 승인 · 리포트), `lib/commerce`(주문 규칙), `lib/integrations`(Supabase · 토스 구현체). 핵심 폴더가 Next.js · React · 외부 SDK를 불러오지 않는지 테스트로 확인
- [x] DB: `profiles` · `assessments` · `user_regions` · `orders` · `payment_events` · `reports`, 본인 조회만 허용(RLS), 직접 쓰기 차단, 주문 상태 규칙 · 결제 완료 1건 · 완성 리포트 수정 불가 트리거
- [x] 카카오 로그인 (이메일 없는 사용자 허용), 로그아웃, 세션 갱신(`proxy.ts`)
- [x] 로그인 전 결과는 암호화 HttpOnly 쿠키에 30분 보관 → 로그인 후 서버 채점으로 다시 계산해 저장
- [x] 결과 화면 `/results/[id]`: 저장된 무료 요약 + 구매 영역 / 구매 후에는 저장된 리포트
- [x] 결제: 서버가 금액 결정 · 주문 생성 → 결제 화면 `/checkout/[주문번호]` → 성공 시 서버 승인(금액 · 소유자 확인, 멱등키) → 리포트 생성
- [x] 실패 · 취소 · 응답 유실(확인 중) · 환불(웹훅) 처리, 결제 상태와 리포트 상태 분리, 리포트 다시 만들기
- [x] 테스트 키만 허용 (`PAYMENTS_LIVE_MODE=true`가 아니면 `test_` 키만)
- [x] MY: 저장한 결과 · 구매 상태 · 리포트 상태 목록
- [x] 문서: `docs/setup-guide.md`(계정 연결 순서), 기획서 · 로드맵 · `.env.example` 갱신

### 검증 기록 (클라우드 개발 환경 · Linux · Chromium)

| 검사 | 결과 |
| --- | --- |
| `npm run typecheck` · `npm run lint` · `npm run build` | 통과 |
| `npm test` (채점 · 서비스 흐름 · 토스 연결 요청 형식 · 암호화 쿠키 · 핵심 폴더 독립성) | 33/33 통과 |
| `npm run test:db` — 로컬 Postgres 16 + Supabase Auth + PostgREST에 마이그레이션 적용 후: 가입 시 프로필 생성, 실제 DB 위 서비스 흐름, 본인 결과만 조회, 직접 쓰기 거부, 상태 규칙 · 고유 조건 · 리포트 수정 불가 | 7/7 통과 |
| 전체 흐름 브라우저 검사 (390px · 1440px) — 가짜 카카오 서버 · 가짜 토스 API 사용: 검사 → 카카오 로그인(이메일 없음) → 저장 → 결제 → 금액 위조 거부 → 승인 → 리포트 → 새로고침해도 같은 버전 → MY → 웹훅(위조 무시 · 환불 반영) → 로그아웃 / 다른 회원 접근 차단 / 결제 취소 · 카드 거절 · 응답 오류 후 재확인 | 22/22 통과 |
| 키를 넣지 않은 상태의 화면 검사 (390px · 1440px, 1단계 흐름 · 키보드 · 넘침 · '설정 전' 표시) | 58/58 통과 |
| **실제 카카오 · 실제 토스페이먼츠 · 실제 Supabase 프로젝트와 연결** | **아직 안 함** — 계정 · 키 필요 (`docs/setup-guide.md`) |
| Windows PC에서 직접 실행 | 아직 안 함 |

로컬 검증 환경은 `supabase/tests/local-stack.sh`(Linux 전용)로 띄운다. 실제 카카오 · 토스 서버에는 접속하지 않았다.

### 남은 일 (2단계)

- [ ] 운영자: Supabase 프로젝트 · 카카오 앱 · 토스 테스트 키 준비 → `.env.local` 입력 → 실제 연결 확인
- [ ] 검사 척도 후보 검토 → 이용 조건 확인 → 운영 문항 `licensed`로 교체
- [ ] 사주 엔진 후보 검토(정확도 · 라이선스) → `lib/saju/engine.ts` 연결 → 기획서 6장 검수 항목 테스트

### 남은 일 (3단계)

- [ ] AI 해석 생성기 (구조화된 결과만 입력, 형식 검증, 작업 큐 분리)

- [ ] 환불된 주문의 리포트 열람 정책 확정
