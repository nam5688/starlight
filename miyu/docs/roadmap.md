# ME:U(미유) 진행 단계

**첫 출시 상품은 개인 통합 리포트 하나에 집중한다.** 추가 카테고리 · 커플 비교 · 미유피플 · 제휴는 아래 "보류 · 후속 확장 목록"에 보관한다.

개인 통합 리포트로 첫 구매를 만들고, 상대가 직접 참여하는 커플 비교로 넓힌다 ([`business-plan.md`](./business-plan.md)). 독립형 모바일 웹으로 먼저 출시하고(카카오 로그인 · 토스페이먼츠 웹 결제), 앱인토스 입점은 보류한다. 메뉴를 더 늘리지 않는다.

| 단계 | 내용 | 상태 |
| --- | --- | --- |
| 1 | 화면과 흐름 (샘플 데이터) | 완료 |
| 2 | 카카오 로그인 · 가입 동의 · 결과 저장 / 검사 도구 · 사주 엔진 검토 | **로그인 · 동의 · 저장 완료 (운영자 실제 확인)** · 사주 엔진 연결 완료(manseryeok, 교차 검증) · 검사 도구는 대기 |
| 3 | 테스트 결제 · 구매 권한 · 리포트 생성 · MY / AI 해석 · 관리자 | **테스트 결제 · 구매 권한 · MY · 백그라운드 생성 · AI 생성기(모의 모델) · 결제 중단 복구 · 관리자 · AI 비용 통제 완료** · 실제 AI 제공사(선택 · 승인 대기) |

| 4 | 텔레그램 알림 · 쿠폰 · 출시 검수 | 알림(종류별 · 테스트 표시 · 주문당 한 번) · 정기 점검 · 지표 · 운영 매뉴얼 · **회원 탈퇴(정책 초안)** **구현됨**(실제 텔레그램 · Supabase Auth 연결 전) · 쿠폰 · 약관 확정 · 출시 검수는 대기 |
| 5 | 두 가지 유입 실험 → 우정 비교 · 고민 해결 | 대기 |

출시 준비 상태(무엇이 테스트만 통과했고 무엇이 실제로 연결됐는지)는 [`launch-checklist.md`](./launch-checklist.md)에서 관리한다.

**지금 운영자가 할 일:** Supabase 연결 → 카카오 로그인과 결과 저장 확인 → 그다음 토스페이먼츠 테스트 결제 확인. 순서는 [`setup-guide.md`](./setup-guide.md), 진행 상황은 개발 서버의 `/setup` 화면.
실제 결제와 공개 배포는 운영자 확인 전에 하지 않는다.

## 사업 실행 순서 (운영자 기획, 2026-10-12)

1. 실제 개인 리포트 한 개와 커플 비교 리포트 한 개를 끝까지 완성 — 문구 수보다 답변 근거와 결과 품질 먼저 (검사 도구 · 이용료 확정이 전제)
2. 개인 구매와 상대 초대 흐름 — 카카오 로그인 · 저장 · 구매 권한 · 공동 열람 · 실패 복구 (로그인 · 저장 · 구매 권한 · 실패 복구는 구현됨)
3. 자기이해 · 커플 비교 두 가지 유입 메시지로 실제 고객 반응 확인
4. 확인된 흐름에 우정 비교와 고민 해결 연결 — 설계해두되 한꺼번에 판매 가능한 것처럼 공개하지 않음

운영자가 언급한 `meu-growth-plan/` 문서 묶음은 아직 저장소에 없다. 받으면 `business-plan.md`와 대조한다.

1. 검사 · 채점 · 리포트 · 주문 규칙을 채널과 무관한 코드(`lib/`)로 분리하고, 저장소 · 결제사 · 생성기는 약속(인터페이스)으로 연결

## 무료 · 유료 구분과 구매 판단 근거 (2026-10-12, 운영자 2차 피드백)

운영자가 미리보기를 보고 "돈을 냈는데 무료랑 뭐가 다르지?"를 가장 먼저 풀라고 했다. 방향: 숨긴 문장이 아니라 **읽어 보니 더 알고 싶어지는 것**과 **구매하면 답해 주는 질문**을 함께 보여 준다.

구현됨 (`lib/report/free-insight.ts` · `preview.ts` · `components/report/*`)
- 대표 경향: 이름은 앞부분만 가리되, **응답이 뒷받침하는 문장으로 만든 해석 문단**은 무료로 전부 보여 준다. 모두에게 붙는 문장이 아니라, 해당 문항에 해당 방향으로 답했을 때만 그 문장이 들어간다. 근거가 하나도 없으면 문단을 만들지 않고 일반 한 줄 요약의 앞부분으로 돌아간다. 구매하면 "이렇게 읽은 이유"(근거 문항과 내 응답)가 보인다.
- 잠긴 자리: 흐린 문장 대신 **답해 줄 질문**을 보여 준다 (핵심 요약 2가지 · 기질 · 관계 점수 · 나머지 상황 · 실천 제안). 질문은 모두에게 같은 안내 문구이며, 구매한 리포트에 답이 되는 부분이 실제로 있는 질문만 넣는다 (`preview.test.ts`가 확인).
- 사주: 오행 키워드(목 시작 · 성장 · 확장 / 화 표현 · 열정 · 교류 / 토 안정 · 조율 · 유지 / 금 기준 · 정리 · 결단 / 수 관찰 · 사고 · 유연함)와 내 원국의 쉬운 풀이 한 가지는 무료. 각 기운이 **관계 · 일 · 선택**에서 나타나는 모습은 유료. 개수만으로 성격을 정하지 않는다는 안내를 함께 둔다.
- 유료 상황 해석은 **이런 모습 → 잘 발휘될 때 → 과해질 때 → 해볼 선택** 순서로 읽힌다. 일 · 가까운 관계 상황이 연애 · 직장 사례 역할을 한다.
- 구매 안내: "내 관계 패턴과 잘 맞는 상대 확인하기"(어울리는 관계 조건이 있는 결과만) + "개인 통합 리포트 · 9,900원 · 포함 내용 보기 · 샘플 리포트 읽어 보기". 샘플 리포트(`/report/sample`)는 가상 인물의 완성된 유료 리포트로, 개인 무료 결과와 구분된다. (2026-10-13부터 읽기 구조 예시로 바뀜 — 아래 "제품 방향 · 읽기 구조" 참고)
- 약속하지 않는 것: 상대의 나이 · 직업 · 만나는 날짜, 특정인과의 궁합.

한계 (솔직하게)
- 지금 문항(개발용 예시 6 + 8문항)으로는 "바쁘다는 설명이 있으면 기다릴 수 있지만 설명 없이 반응이 바뀌면…" 같은 **상황 대비 문장**을 근거 있게 만들 수 없다. 이런 문장은 상황형 문항(`tendency-types-v2.md`의 구분 질문)이 들어온 뒤에 같은 규칙으로 추가한다.
