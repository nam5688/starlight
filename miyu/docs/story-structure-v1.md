# 영역별 이야기 구조(story-v1) — 칸을 채우는 리포트에서 영역마다 이야기를 끝까지 쓰는 리포트로

> 2026-10-16 운영자 검토 반영. **비교용 후보이며 제품 기본값이 아니다. 실제 서비스 AI로는 한 번도 시험하지 못했다(검증되지 않음).**
> 이 변경으로 쓴 새 유료 호출은 0회 · 0원이다. 아래의 글은 모두 같은 계열의 하위 작업자(대리 작성기)가 쓴 것이고 실제 서비스에 연결된 AI의 글이 아니다.

## 1. 왜 바꿨나 — 반복의 원인은 단어가 아니라 칸의 나눔이었다

실제 AI의 첫 글(지시문 0.13, P01)을 검토 후 수정했을 때 "혼자 정리"라는 말은 11번에서 3번으로 줄었다. 그런데 **같은 설명**("내가 확인하는 시간이 상대에게는 거리나 기다림으로 느껴진다")은 제목 · 관계 · 회복 · 고민 반영에 그대로 남았다. 단어를 줄인 것과 같은 설명을 줄인 것은 다르다.

원인은 구조에 있었다(`docs/prompt-pack-review.md` 12-7에서 센 값).

| 이전 읽기 구조(reading-v1) | 값 |
| --- | --- |
| 한 사람을 설명하는 글 칸 | 약 98개 |
| 행동을 제안하는 칸 | 18개 (주제 watch 3 · 소단락 tryIt 6 · 반응 단계 helpful 1 · 시기 watch 4 · 행동 4) |
| 근거 목록의 응답 근거 | 6개 (사주 34 · MBTI 1) |
| 계획 문구에 박힌 말 | 가까운 관계 세 번째 소단락의 질문이 "혼자 정리할 때"로 시작 |

모델은 근거 6개로 98칸을 채우려고 같은 성향을 요약 · 예시 · 풀이 · 주의 · 행동 · 시나리오 칸마다 다시 썼다. **같은 단어가 두 번 나오면 막는 검사를 더하는 것은 해법이 아니다** — 같은 단어를 다른 뜻으로 쓸 수도 있고, 단어를 전부 바꿔도 같은 말을 되풀이할 수 있다. 그래서 검사가 아니라 칸의 나눔을 바꿨다.

## 2. 무엇이 바뀌었나

| | 이전(reading-v1) | 영역별 이야기(story-v1) |
| --- | --- | --- |
| 구성 | 주제 5개 + 시기, 칸마다 요약 · 예시 · 풀이 · 살펴볼 점 + 특징 카드 · 관계 조건 · 반응 단계 · 소단락 | **영역 4개**(핵심 · 가까운 관계 · 일과 재물 · 현재와 앞으로의 흐름) + 고민(있을 때만) + 행동 3개 |
| 한 영역 | 요약 2문장 + 예시 + 풀이 1~3문단 + 살펴볼 점 (+ 소단락 3개) | **제목 한 줄(그 영역에서만 말하는 연결) + 이야기 문단 3~5개** |
| 행동 | 칸마다(18개) | 영역 본문에는 "~해 보세요" 과제 문장을 영역마다 1개까지, **구체적 실천은 마지막 3개에 모은다**(어느 영역에서 나온 행동인지 `area` 표시) |
| 시기 | 큰 흐름 + 소단락 · 시기별 풀이에서도 | **흐름 영역에만**(다른 영역에서 대운 · 세운 · 올해 · 연도를 말하면 검사가 막는다) |
| 응답 · MBTI | 근거에 달기만 해도 통과 | 영역마다 그 영역과 맞닿는 개인 성향 근거를 연결해야 통과, MBTI는 핵심 · 관계 · 일 가운데 2곳 이상 |
| 제목 | 본문 뒤 결론으로(0.11) | 같음 + 영역 제목끼리 · 맨 위 문장과 겹치지 않기, 응답 둘을 붙인 제목 금지 |

글 칸이 약 98개에서 약 40개로 줄었고, 영역마다 하나의 이야기를 쓴다. **글을 무조건 짧게 만들자는 것이 아니다** — 깊이가 필요한 영역에는 문단을 충분히 쓰고, 같은 내용을 채우려고 있던 칸만 없앴다.

### 저장 모양 · 호환
- 같은 저장 모양(`kind: "integrated-reading"`)에 **`layout: "story"`**로 구분한다. 영역의 첫 문단은 `summary`, 나머지 문단은 `details`에 담고 요약 · 예시 · 특징 카드 · 소단락 · 살펴볼 점은 없다. 흐름은 `flow.summary` + `flow.paragraphs`.
- 그래서 **이미 저장된 리포트는 그대로 읽힌다**(layout이 없으면 이전 화면). 채팅 · 관리자 보기 · 내보내기 · 월별 달력 · 고민 리포트의 "이미 준 내용" 비교가 두 형식을 모두 읽는다.
- 저장된 블록 id는 `tendency` · `love` · `work-money`를 그대로 쓴다(채팅방이 읽는 이름). 그래서 채팅방 코드를 바꾸지 않았다.
- **기본값은 바꾸지 않았다.** 생성기의 기본은 여전히 reading-v1이고 story-v1은 선택 형식이다(`createAiReportGenerator({ format: "story-v1" })`, 비교 실행기 `--variant story-v1`). 기본으로 바꾸는 것은 실제 글을 읽고 운영자가 정한다.

## 3. 영역마다 어떤 자료를 우선 읽나 (지시문에 그대로 들어간다)

| 영역 | 우선 참고 | 개인 성향 근거 연결 |
| --- | --- | --- |
| 내 사주의 중심과 지나온 모습 | 사주(원국 · 십신 · 월령 · 통근 · 강약 후보) + **평소 행동 방식 네 가지** + 기질 + 입력한 MBTI | 2개 이상 |
| 가까운 관계에서의 나 | 사주(배우자 자리 · 합 · 충) + 관계 불안 · 거리 두기 + 타인 반응 민감도 + 입력한 MBTI(표현의 속도) | 1개 이상 |
| 일과 재물의 방향 | 사주(재성 · 관성 · 식상) + 평소 행동 방식 + 기질 + 입력한 MBTI(일을 납득하는 방식) | 1개 이상 |
| 현재와 앞으로의 흐름 | 사주 시기(대운 · 세운) 거의 전부. 개인 성향은 "이 흐름을 어떻게 받아들이는가"에만, **MBTI는 쓰지 않는다** | 요구 없음 |
| 알려 준 고민 | 앞 영역의 결론을 지금 선택에 적용(성향 설명을 다시 쓰지 않는다) | — |
| 지금 해 볼 행동 3개 | 앞 영역에서 나온 행동을 한곳에, 적어도 두 영역에서 | — |

사주 약 60~70 · 개인 성향 약 30~40은 설명의 우선순위일 뿐이다. 화면에 비율 · 점수 · 정확도로 보이지 않고, 근거 개수를 맞추려고 끼우지 않는다(영역별 사용 규칙으로 맞춘다).

## 4. 근거 만들기가 바뀌었다 (이 변경은 이전 형식에도 적용된다)

- **평소 행동 방식 네 가지**(에너지 · 정보 · 판단 · 생활)가 AI에게 가지 않았다. 근거를 만드는 코드가 기질 4 · 가까운 관계 2만 읽었다. 이제 뚜렷한 쪽(65 이상 · 35 이하)이 `survey.ei|sn|tf|jp.high|low` 근거로 넘어가고, 글자 코드가 아니라 행동 이름("함께하며 채움")으로 쓴다. 가운데 점수는 만들지 않는다. (`SURVEY_RULE_VERSION` survey-dev-0.1 → 0.2)
- **입력한 MBTI**는 알파벳이 아니라 선호의 방향(직접 쓴 한 줄 풀이: "에너지는 안에서 충분히 정리한 뒤 밖으로 꺼내는 쪽" …)으로 풀어 근거 문구에 건넨다. 본문에 알파벳 코드를 쓰면 검사가 막고, 응답과 다르면 응답이 먼저다. 공식 검사의 설명을 옮기지 않았다.
- P01은 근거 41개 → **45개**(사주 34 · 응답 6 → 10 · MBTI 1). 사주 34 : 개인 성향 11이라 개수만으로는 아직 사주가 약 75%다 — 영역별 연결 규칙이 개수의 한계를 메운다.
- P01에서 응답(에너지: 함께하며 채움)과 입력한 MBTI(안에서 정리하는 쪽)가 **서로 다르다.** 이전 글은 MBTI 쪽 문장만 썼고 이 차이를 다루지 못했다. 새 지시문은 "응답이 먼저, 차이는 상황별로"를 요구한다.

## 5. 검사 — 코드가 막는 것과 사람이 읽어야 하는 것

**코드가 막는다**(`story-validate.ts`, 같은 글 규칙 `textIssues`를 이전 형식과 공유)
- 영역 3개 · 문단 수 · 문단 60~380자 · 3문장 이하 · 근거 ID · 모든 영역에 사주 근거
- 영역마다 맞닿는 개인 성향 근거 연결(핵심 2 · 관계 1 · 일 1) · MBTI 2곳 이상 + 시기 영역에는 금지 + 근거만 달고 본문에 안 쓰면 금지 · 알파벳 유형 코드 금지
- 시기 이야기(대운 · 세운 · 올해 · 내년 · 연도)는 흐름 영역에만 · 영역 본문의 행동 과제 문장 1개 이하
- 영역 제목끼리 · 맨 위 문장과 겹침 · 본문이 제목을 되풀이
- 한 문단의 서로 다른 사주 용어 2개 이하(문단 하나에서 새 개념을 여럿 배우지 않게) — 한 문장 2개 · 설명 없는 용어 · 근거 없는 판정은 이전과 같다
- 행동 정확히 3개 · 어느 영역에서 나왔는지 표시 · 적어도 두 영역 · 서로 다른 행동
- 이전 형식과 같은 글 규칙: 점수 · 원인 단정 · 응답 읽어 주기 · 나이 · 결정 대행 · 계산되지 않은 해 · 같은 문장 반복

**코드로 못 막고 지시문과 사람이 읽는 평가에 있다**
- 같은 결론을 낱말만 바꿔 되풀이하는 것(영역 사이의 의미 반복) — 구조(영역마다 연결 하나)로 줄이고, 12자 이상 같은 구절 확인(`findRepeatedPhrasesIn`)과 내용 검사(`checkReadingDepth`, 켜 둔 경우)는 어림이다
- 반응 민감도를 "상대 마음을 읽는 능력"으로 옮기는 것 · 반응 민감도와 관계 불안을 하나로 합치는 것 · 신중함을 "표현이 서툼"으로 옮기는 것 · 갈림(강약이 모이지 않음)을 "상황마다 강해졌다 약해졌다 하는 성격"으로 번역하는 것 — 지시문에만 있다
- 대표 제목이 응답 둘을 붙인 요약인지 — 지시문과 사람이 읽는 평가

## 6. 사용자 검토에서 지적된 문장 문제는 어디서 다뤘나

| 지적 | 처리 | 위치 |
| --- | --- | --- |
| 대표 제목이 응답 두 개를 붙인 요약("신중함 + 거리 필요") | 맨 위 문장은 "이번 리포트에서 가장 중심이 된 연결 하나"의 결론, 영역 제목을 옮기지 않기 | 지시문 · 영역 제목 겹침 검사 |
| 실령 설명이 한 문단에서 개념을 여럿 가르침 | 한 문단 새 용어 2개 이하(검사), 구조 용어는 한 문단에 몰아 쓰지 않기 | 검사 + 지시문 |
| 갈림 → 상황별 성격 변화 번역 | **0.13이 오히려 "상황에 따라 ~쪽으로 기울 수 있어요"라고 쓰게 했다 — 그 문장을 뺐다.** 갈림은 계산 상태이지 성격 변화가 아니라고 적었다 | 지시문(이전 지시문 0.13은 그대로 보존) |
| 반응 민감도 ≠ 관계 불안 · ≠ 상대 마음 읽기 | 별개로 가르고 장면마다 어디서 나타나는지 쓰게 함 | 지시문 |
| 신중함 ≠ 표현이 서툶(식상 없음의 귀속) | 근거가 가리키는 쪽까지만, 없으면 점검 시간이 길다는 것까지 | 지시문 |
| 일 · 돈 · 시기 반복 | 시기는 흐름에만(검사), 일은 역할 · 권한 · 속도 · 협업 · 평가 기준, 돈은 근거가 약하면 한 문단 안 | 검사 + 지시문 |
| 고민 반영이 앞 성향을 다시 씀 | 앞 영역의 결론을 지금 선택에 적용 | 지시문 |
| 행동이 문단마다 "적어 보세요" | 영역마다 1개 이하, 구체적 실천은 마지막 3개 | 검사 + 지시문 |

## 7. 비용 (호출하지 않고 계산한 값)

환율 1,600원 · 여유율 1.1, 입력 추정은 실제 지시문 · 근거 길이 기준이다.

| | reading-v1(0.13) | story-v1(0.1) |
| --- | --- | --- |
| 지시문 길이 | 약 17,200자 | 약 15,400자 |
| 사용자 메시지(P01) | 약 16,800자 | 약 16,900자 |
| 호출 1회 최악(출력 최대 24,000토큰 예약) | 558원 | 558원 |
| 고쳐 쓰기까지 한 건의 최악 | 1,204원 | 1,204원 |
| 평소 수준 어림(출력 1만 토큰) | 311원 | 311원 |

최악 값은 출력 최대치를 모두 쓴다고 예약하는 값이라 두 형식이 같다. **실제 출력 토큰이 줄었는지는 새 호출 없이는 알 수 없다**(칸이 줄어 줄 것이라고 기대하지만 재지 않았다). 남은 승인 잔액(3,000 − 2,097 = 903원)은 한 건의 최악(1,204원)보다 적어 가드가 최악 예약으로 막을 수 있으므로 **새 호출 전에 운영자가 승인 총액을 다시 정해야 한다.**

## 8. 이번 실제 시험(P01)의 입력 경로

P01은 **기존 개발용 22문항 경로**였다(새 장면 질문 10장면이 아니다). 가상 인물이 개발용 문항에 답한 값으로 요약을 만들고, 근거 6개의 fact가 모두 "개발용 문항 — 백분위가 아님"이며 장면(scenario) 근거는 0개였다. 그러므로 그 시험은 "사주 구조 근거 + 글쓰기 지시문"의 시험이었고 **새 질문이 더 나은 풀이를 만드는지 본 시험이 아니다.** 기록은 `docs/samples/real-ai/reading-0.13-P01-stage-1-20261016-153543/provenance.json`의 "입력 경로".

## 9. 대리 작성기 시험 결과 (2026-10-16, 새 유료 호출 0회 · 0원)

> **실제 서비스 AI가 아니다.** 지시문(`story-v1-prompt-0.1`)과 근거 목록 파일을 AI 하위 작업자(대리 작성기)에게 주고 받은 글을 제품 검사에 넣었다. 지난번 실제 모델은 대리 작성기와 다른 순서로 써서 검사 오탐을 낸 적이 있으므로, 이 통과를 실제 모델의 통과로 읽지 않는다. 글은 `docs/samples/story-v1-proxy/`에 있고 사람이 문장을 고치지 않았다(P01 · 서윤 각각 1차 · 2차, 서윤 2차는 고쳐 쓰기 전 · 후).

### 9-1. 검사가 먼저 잡은 것 (모두 글을 본 뒤에 검사 · 지시문을 고친 사후 수정이다)

| 시도 | 걸린 것 | 원인 | 한 일 |
| --- | --- | --- | --- |

### 9-3. 읽고 알게 된 것

- **줄어든 것**: 글 칸 98 → 37(P01) · 34(서윤), 글자 수 약 40% 감소(7,050 → 4,250), "혼자 정리" 되풀이 10줄 → 2줄, 12자 이상 같은 구절 되풀이 3(1차) → 0(2차), 같은 맺음 틀 반복은 예산으로 막힘. 행동은 마지막 세 개로 모였다.
- **그대로 남은 것(정직하게)**: "확인한다 · 꺼낸다 · 속에서 정리한다"라는 한 가지 모티프가 P01에서는 43줄 중 8줄에 여전히 나온다. 줄 수 대비 비율로는 이전 구조(원문 10/89 = 11%)보다 높다(8/43 = 19%) — 글이 짧아졌는데 한 가지 모티프의 몫은 줄지 않았다. 이 사람의 응답 근거가 6개뿐이라 대리 작성기가 같은 한 가지로 영역마다 풀이를 이어 갔고, 영역마다 장면은 달라졌다(핵심 → 말이 속에서 묵음 · 관계 → 거리를 말로 건넴 · 일 → 기준을 확인함 · 흐름 → 확인하다 늦어짐). **구조가 단어 반복은 줄였지만 "한 가지 특징이 모든 영역을 끌고 가는" 반복은 근거 수가 늘기 전에는 구조만으로 없어지지 않는다는 뜻**이고, 이것이 반복인지 일관된 이야기인지는 사람이 읽고 판단해야 한다(코드가 구분하지 못한다).
- **지켜진 것**: 성격 4축과 입력한 MBTI 방향이 핵심 · 가까운 관계 · 일 영역에서 "입력해 주신 성향"으로 쓰였고 흐름 영역에는 쓰이지 않았다. 알파벳 코드 · 이름은 없다. 시기 이야기는 흐름 영역에만 있다. 갈림(강약)은 성격 변화로 번역되지 않았다. "반응 민감도 ≠ 상대 마음 읽기 ≠ 관계 불안"은 서로 다른 이야기로 나뉘었다(P01 2차 관계 영역).
- **남은 문장 문제(읽고 본 것, 평가는 같은 계열 모델의 읽기이며 사용자 평가가 아니다)**: 서윤 2차의 "일지에 편재" 해석 등 해석 근거가 맞는지는 근거 목록과 나란히 사람이 대조하지 못했다. 제목은 영역의 결론 한 문장으로 나아졌지만 P01 핵심 영역 "일간… 밭이나 평지" 문단은 용어 풀이로 시작해 첫 문단이 설명서 느낌이 남는다.

### 9-4. 이 시험으로 말할 수 없는 것

- 실제 서비스 AI가 같은 지시문으로 형식 검사를 통과하는지(통과율). 실제 모델로 이 구조를 한 번도 호출하지 않았다.
- 사용자(실제 고객)가 이 글을 더 좋게 읽는지. 이 읽기는 추가 AI 검토이며 사용자 평가가 아니다.
- 비용: 이번에 호출하지 않았다. 지난 계산(호출 1회 최악 558원 · 한 건 최악 1,204원, 환율 1,600원 · 여유율 1.1)은 그대로이고 **남은 승인 잔액 약 903원은 한 건의 최악보다 적어서 새 호출 전에 운영자가 승인 총액을 다시 정해야 한다.** 예산 증액(6,000원)은 보류 상태다.

## 10. 하지 못한 것 · 운영자 결정 항목

- **실제 서비스 AI로 story-v1을 한 번도 시험하지 못했다.** 대리 작성기의 통과는 실제 모델의 통과가 아니다(지난번 실제 모델은 대리 작성기와 다른 순서로 써서 검사 오탐을 냈다).
- 새 유료 호출은 운영자 승인 전에는 하지 않는다. 승인 총액 · 호출 수는 운영자가 정한다.
- 기본 형식을 story-v1으로 바꿀지, 서윤 예시(`/report/sample`)를 새 형식으로 바꿀지는 실제 글을 읽은 뒤 정한다(지금 예시는 reading-v1 그대로이고 새 형식 예시는 개발용 화면 `/dev/story`에서만 읽는다).
- 새 장면 질문(10장면)과 이 구조를 함께 시험하는 것은 이번 범위가 아니다(문항 추가 · 사주 엔진 확장 · 모델 변경 없음).
- 영역 사이의 의미 반복은 사람이 읽는 평가가 필요하다(코드는 어림).
- 개발용 화면 `/dev/story`(이 PC에서만, 서윤 예시 · 대리 작성기 글)와 시험 `lib/samples/sample-story-report.test.ts`는 새 형식의 예시일 뿐 서비스에 연결되지 않았다.

## 11. 0.2 수정과 기본 형식 전환 (2026-10-16 2차 검토 반영 — 새 유료 호출 0회 · 0원)

운영자 2차 검토 요지: story-v1은 98칸 구조보다 훨씬 낫고 **신규 생성의 기본 형식으로 바꾸는 방향이 맞다**, 다만 ① 영역 첫 문단이 "사주 설명서"처럼 읽히고 ② "확인 · 꺼낸다 · 속에서 정리" 모티프가 반복되며 ③ 일부 문장이 오행 · 십성 없음을 생활 기능의 부족으로 옮긴다("수 기운이 없어서 쉬어 가는 힘이 없다", "재성 없음 → 돈 결정에서 확인 기준이 필요"). 실제 AI 시험은 이 구조 수정 뒤에 한 건만.

### 11-1. 바꾼 것 (지시문 `story-v1-prompt-0.2` · 검사 · 근거 나누기)

| 항목 | 바뀐 점 |
| --- | --- |
| 문단 순서 | 생활 풀이(이 사람의 모습) → 그렇게 읽은 이유(사주) → 응답으로 나타나는 방식 → 부담 → 방향. **첫 문단에는 사주 용어를 쓰지 않는다**(검사 `FIRST_PARAGRAPH_TERMS_MAX = 0`) |
| 없는 기운 · 십성 | 한 문장에 종류 이름 + 없음 + (생활 기능 풀이 또는 인과 연결)이 함께 있으면 막는다(`ABSENCE_MAPPING`). "없음"은 시기에 크게 느껴질 수 있다 · 전통 해석이 생활에서 채우라고 권한다까지만 말하고 이 사람의 능력 · 결함 · 행동의 원인으로 쓰지 않는다 |
| 개인 근거 나누기 | 영역마다 먼저 쓸 개인 근거를 겹치지 않게 나눠 건넨다(`personalEvidenceFor` — 핵심 · 일은 평소 행동 방식 · 기질, 가까운 관계는 관계 반응 · 타인 반응 민감도). 같은 개인 근거(MBTI 제외)는 두 영역까지만 앞세우고 흐름 영역은 하나까지(`PERSONAL_REUSE`) |
| 반복 모티프 | 근거를 나누는 것으로 줄이려 했고, 문장 규칙만으로는 줄지 않는다고 보았다(아래 11-3) |
| **기본 형식 전환** | `lib/config/product.ts`의 `REPORT_GENERATION.format`이 `"story-v1"`이다(생성 서버 `server/live-ai.ts` · `server/services.ts`가 읽는다). **신규 생성에만 적용되고 이미 저장된 리포트는 그대로 읽힌다 — 자동으로 바꾸지 않는다.** 실제 AI 시험이 통과하지 못하면 이 한 줄을 `"reading-v1"`로 되돌린다. 개발용 시나리오 화면(`server/dev-scenario.ts`)은 reading-v1로 고정이다 |
| 검사 보정 | `CONCRETE_ACT`(행동의 구체성 어림 — `lib/report/v2/depth.ts`)의 동사 목록을 넓혔다 — 서윤 0.2의 `actions-concrete` 오탐 때문이다(**글을 본 뒤에 고친 사후 수정**이고 새 글이 통과한다는 증거가 아니다) |

### 11-2. 대리 작성기 시험 (같은 구조 · 실제 AI 아님)

- 가상 인물 P01: 첫 글이 형식 검사 2건에 걸렸다(입력한 MBTI 근거를 달았는데 본문에서 쓰지 않음 · "정관"을 "~을 뜻하는 정관"으로 풀어 설명 방식 불인정) → 제품과 같은 방식으로 이유를 주고 **고쳐 쓰기 한 번** → 통과(`docs/samples/story-v1-proxy/prompt-0.2/P01-after-one-rewrite.json`).
- 서윤: 첫 글이 한 번에 통과(`seoyun-first-response.json`) — 개발용 화면 `/dev/story`의 예시(`lib/samples/sample-story-draft.ts`)가 이 글이다. `/report/sample`은 reading-v1 그대로다.
- 영역 첫 문단은 생활 풀이로 시작했고(사람이 읽어 확인), 없음 → 기능 번역은 검사 · 지시문으로 막혔다. 같은 계열 모델의 읽기이며 사용자 평가가 아니다.

### 11-3. 반복 모티프 — 구조 수정으로 줄지 않았다 (직접 센 값, 어림)

P01의 "확인한다 · 꺼낸다 · 속에서 정리" 계열(43줄 기준):

| 낱말 | 0.1 | 0.2 |
| --- | --- | --- |
| 확인 | 8줄 | 5줄 |
| 가다듬 · 가라앉 | 0줄 | **11줄** |
| 혼자 정리 | 2줄 | 5줄 |
| 꺼내 | 8줄 | 7줄 |

- **모티프가 줄었다고 말할 수 없다.** 한 낱말은 줄었지만 같은 뜻의 다른 낱말("가다듬는다 · 가라앉힌다")이 늘었다. P01에게 있는 개인 근거(입력한 MBTI의 방향 + 알려 준 고민)가 한 방향(안에서 정리한 뒤 꺼냄)이라 **영역마다 나눠 건네도 같은 한 가지 특징이 영역마다 이어진다.** 근거의 수가 늘기 전(새 장면 질문 · 심화 검사 등)에는 구조 · 문장 규칙만으로 없어지지 않는다 — 그것이 일관된 이야기인지 반복인지는 사람이 읽어 판단한다.

### 11-4. 같은 시험에서 발견했지만 고치지 않은 것

- **무료 화면의 고정 문구가 같은 번역을 한다**: `lib/saju/plain.ts`(오행 "수"가 적을 때 "생각을 멈추고 쉬어 가는 일이 서툴 수 있어요")와 `lib/saju/glossary.ts` · `lib/saju/interpret/rules.ts`의 오행 의미 문구("쉬어 가는 힘")가 "없음 → 생활 기능 부족"의 형태로 읽힌다. 새 규칙(위 11-1)은 AI가 쓰는 글만 막으므로 **코드가 쓰는 이 고정 문구는 같은 기준으로 다시 쓰는 것이 필요하다** — 이번 범위가 아니어서 건드리지 않았고 별도 작업으로 남긴다.

### 11-5. 하지 못한 것

- **실제 서비스 AI로 story-v1(0.2)을 한 번도 시험하지 못했다.** 남은 승인 잔액 약 903원은 한 건의 최악(1,204원)보다 적다. 운영자 검토의 "총 승인 한도 4,000원" 제안은 **권고이며 승인이 아니다** — 운영자가 `.env.local`에 직접 값을 적기 전에는 호출하지 않는다(코드 상한 `LIVE_TEST_LIMITS` 5,000원 · 60회 · 7일은 그대로).
- 응답 근거가 6개뿐인 사람의 모티프 반복은 근거를 늘리는 작업(장면 질문 연결 등)이 필요하다.
