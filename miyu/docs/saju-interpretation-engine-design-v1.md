# 명리 해석 근거 확장 설계안 (2026-10-18, 설계만 · 구현 · 프롬프트 변경 · AI 호출 없음)

운영자 지시: "미유의 가장 큰 문제는 AI 모델이 아니라 사주 해석 엔진이다. 읽기 카드 21개를 만드는 것만으로는 부족하다 — 읽기 카드에 들어갈 **해석 자체를 먼저 확장**해라. 해석 후보를 여러 개 만들고, 고객 관심 중심으로 고르고, 마지막에 AI가 인생 이야기로 쓰는 순서로. 코드가 정답 문장을 미리 만들어 두는 방식도 피해라. 단일 명식에서 후보가 몇 개 나오는지, 명식끼리 얼마나 달라지는지 평가할 수 있는 구조로 설계해라."

이 문서는 **설계안**이다. 코드 · 지시문 · 시험 · 판매 설정은 바꾸지 않았고 AI 호출 · 결제 · DB · 배포는 하지 않았다(4차 AI 시험도 승인되지 않았다). 숫자는 **설계 검증용 임시 측정**(저장소에 올리지 않은 스크립트, 4장 · 가정 명시)이다. 외부 오픈소스 조사는 `saju-opensource-survey-v1.md`, 읽기 카드 · 과거 회고 정책은 `story7-interpretation-design-v1.md`에 있다.

## 0. 한눈에

1. **지금 AI가 받는 명리 재료는 "십성 그룹 하나 = 같은 한 줄" 구조라 모든 사람이 비슷한 풀이를 받는다**(다른 명식 4개와 비교해 근거 94쌍 중 70쌍이 같은 문장 — 74%). 그리고 **지난 시기는 한 줄도 받지 못한다**(근거에는 현재 · 다음 대운과 올해부터 3년만 있다). 엔진은 대운 10개와 어느 해든 간지를 이미 계산할 수 있는데 근거로 건네지 않았다.
2. 해법은 문장표를 늘리는 것이 아니라 **"해석 프레임" 층**을 두는 것이다. 프레임 = **서로 다른 사실 둘 이상이 겹칠 때만 나오는 조합 조건** + 그 조합이 전통에서 읽히는 **의미 범위(키워드)** + 좋은 면 · 어려운 면 · 과거 · 미래의 **얼굴**. 코드는 사실과 후보를 만들고 **결론 문장은 AI가 쓴다.**
3. 첫 측정(프레임 78개 · 무작위 명식 4,000개): **명식 하나당 평균 16.5개 프레임(p10 12 · p90 21), 얼굴 둘(밝은 면 · 어려운 면)을 곱하면 약 33개 해석 각도**. 임의의 두 명식의 프레임 겹침은 평균 0.235(자카드)이고 **같은 프레임 집합인 쌍은 0%**. 영역마다 드문 조합 2개를 고르면 **9개 영역 선택을 합친 조합이 4,000명 중 3,837가지**(가장 흔한 조합이 3명).
4. 측정은 **설계의 결함도 바로 잡았다**: 처음 조건(한 사실만 확인)은 지난 세운 프레임이 94% · 87%의 명식에 나왔고, 초년 환경 영역은 62%가 비었고, 한 프레임은 계산상 영원히 0%였다. 조건을 겹치게 고치자 해소 또는 완화됐다(남은 문제는 4-3).
5. **응답은 보조 신호**다 — 어느 프레임 · 어느 얼굴을 앞세울지만 고르고, 프레임이 있고 없음 · 계산 근거는 바꾸지 않는다(불변 조건, 0원 시험 가능).
6. **구현은 이 설계를 운영자가 검토한 뒤**다. 구현해도 프롬프트 변경 · AI 호출은 단계마다 따로 승인받는다. 후보가 많다고 풀이가 좋아진다는 보증은 없다 — 글의 품질은 실제 AI 글을 읽고 정한다.

## 2. 설계 원칙

1. **후보 ≠ 문장.** 코드가 만드는 것은 사실(신호)과 후보 프레임이고 고객이 읽는 문장은 AI가 쓴다. 후보 안에 결론 문장을 두지 않는다.
2. **단일 신호 금지.** 프레임은 **서로 독립인 사실 둘 이상이 겹칠 때만** 나온다. 한 사실(십성 하나 · 오행 하나)로는 어떤 성격 · 사건 · 기능 결핍도 만들지 않는다 — "정재가 없으니 돈 관리가 약하다" 같은 번역은 기존 BLOCK 규칙 그대로다.
3. **원칙표와 명식별 강조를 나눈다.** 고정 문장이 허용되는 곳은 **용어 · 원칙 풀이**(십성이 무엇인지, 합 · 충이 무엇인지, 지장간이 무엇인지)뿐이다. **어느 프레임이 이 사람에게 나오는지 · 어느 얼굴을 앞세울지 · 어느 시기인지는 명식과 응답에 따라 달라진다.**
4. **판정 이름을 지어내지 않는다.** 격국 · 용신 · 신살은 근거에 없으면 쓰지 않는다. 프레임 이름은 내부 라벨이고 고객 화면에 나가지 않는다(전문가 검증 · 정통 판정처럼 보이지 않게).
5. **후보는 좋은 면 · 어려운 면을 함께 가진다.** 한쪽(좋은 면만 · 어려운 면만)으로 읽는 프레임을 만들지 않는다.
6. **과거는 가능성이다.** 지난 시기 프레임은 "그 시기에 이런 주제가 두드러졌을 수 있어요" 가능성 + 나이대 창으로만 쓰고, 사건 · 나이 단정 · 현재 나이 이후 시기를 과거로 쓰지 않는다. 사주에서 읽은 시기와 보편 경험(대체로 그 나이에 겪는 일)을 라벨로 구분한다.
7. **모두에게 같은 소재를 붙이지 않는다.** 가족 갈등 · 이별 · 진로 고민 같은 소재는 프레임이 나올 때만 쓰고 고르는 기준은 **희소도 우선**(흔한 조합보다 드문 조합)이다. 프레임이 없으면 말하지 않거나 보편 질문 한 줄로 둔다.
8. **응답은 보조 신호다.** 프레임의 있음 · 없음 · 계산 근거는 응답이 바꾸지 않는다(불변 조건). 응답은 어느 프레임 · 얼굴이 먼저 나올지와 "사주에서 읽은 모습과 일치 / 차이 / 보완 / 응답 없음"의 표시만 정한다.
9. **측정 가능해야 한다.** 모든 프레임은 무작위 명식에서의 **명중률**을 세고, 100% · 90% 이상은 불량, 극히 드문 것은 점검 대상으로 둔다(`ruanxiaoer888/bazi-engine`의 명중률 감사 방식에서 방법만 가져옴 — 코드 · 데이터 아님).
10. **전통 해석 규칙은 모두 초안이다.** 전문가 검토 전이며 "검증됨 · 감수"라고 쓰지 않는다. 문헌 출처를 직접 확인하지 못한 프레임은 출처를 적지 않고 "전통 해석"으로만 쓴다.

## 3. 프레임 스키마

### 3-1. 필드(데이터 구조 — 코드가 아님)

```
Frame {
  id            "D2"                      // 내부 식별자(고객에게 나가지 않음)
  area          "연애 · 배우자"            // 10개 영역 중 하나
  signals[]     [{ id, fact }]            // 겹쳐야 하는 사실 둘 이상 (각 사실은 근거 ID와 같은 계산값)
  rule          "AND ≥ 2 + 부정 조건"      // 겹침 규칙 · veto(있으면 안 되는 사실)
  applies       { minAge, needsHour, gender? }   // 시각 미상 · 연령 하한 · 성별 조건
  principle[]   [용어 풀이 ID]             // 원칙표에서 가져오는 설명(고정 문장은 여기에만)
  meaning       키워드 8개 이내            // 이 조합이 전통에서 읽히는 의미 범위 — 문장 아님
  faces         { bright, hard, past, future }   // 각 얼굴 = 초점 키워드 + 피할 단정
  window        null | { fromAge, toAge, basis: "period" | "life-stage" | "universal" }
  responseHooks [{ axis, mode: "match" | "differ" | "complement" }]  // 응답이 얼굴 순서만 고르는 연결
  uncertain     boolean                    // 월주 절기 경계 · 시각 미상으로 흔들리면 true → 해석 근거에서 제외
  forbidden[]   단정 금지 어휘(가족사 · 사건 · 효과 보장 등)
}
```

### 3-2. "문장이 아닌 후보"의 선

- `meaning`과 `faces`는 **키워드와 초점**이다(예: 연애 프레임 face.hard = "관계를 정하는 속도 · 확인받고 싶은 마음" 같은 8단어 이내). 완성 문장 · 권유 문장 · 시나리오를 넣지 않는다.
- 검사: `meaning` · `faces`에 서술어 어미(~요 · ~다)와 사건 동사가 들어가면 시험이 거절한다(구현 시 0원 시험).
- AI는 후보 묶음에서 **자기가 쓸 프레임을 고르고**, 후보에 없는 해석을 만들지 못한다(기존 근거 ID 규칙 그대로).

### 3-3. 프레임 하나가 AI 근거 목록에 들어가는 모습

기존 근거(`Evidence`)와 같은 틀을 쓴다 — 별도 경로를 만들지 않는다. `id: saju.cand.D2` · `fact` = 겹친 사실의 계산 문장(위치 · 개수 · 시기) · `cue` = 원칙 풀이 참조 + 의미 범위 키워드 + 얼굴 초점 · `topics` · `strength`(겹친 사실 수) · `period`(시기 프레임) · `uncertain`. 규칙 이력 `rule-meta`에 `saju.cand.*` 항목(전문가 검토 전 초안)을 더한다.

각 영역: 전통에서 읽는 의미 · 쓰는 신호 · 적용 조건 · 쓰지 않는 것. **프레임 78개의 전체 조건과 측정 명중률은 부록**에 있다.

| **A 종합 성향** | 일간이 계절(월령)과 뿌리를 얻었는가, 어떤 십성이 드러나는가 | 득령 · 통근 · 투간 그룹 · 십성 개수 · 일지 관계 · 한열 · 오행 몰림과 빈자리 | 시각 미상이면 시주 없이 | 신강 · 신약 판정(갈림이면 "갈림") |

### 4-1. 프레임의 얼굴(예: D2 — 배우자성이 숨어 있고 일지가 충 · 형 관계)

| 얼굴 | 초점(키워드, 문장 아님) |
| --- | --- |
| 좋은 면 | 인연이 겉으로 드러나기보다 천천히 알아가는 쪽 · 깊게 보는 눈 |
| 어려운 면 | 마음이 움직이는 데 시간이 걸림 · 가까운 사이에서 거리 조절 문제가 표면화되기 쉬운 자리 |
| 과거 가능성 | (지난 대운에 배우자성이 겹친 창이 있을 때만) 그 시기에 관계 주제가 두드러졌을 가능성, 나이대 창 |
| 미래 흐름 | (현재 · 다음 대운이 배우자성일 때만) 인연의 주제가 활발해질 수 있는 시기 |

AI는 이 키워드를 **그 사람의 응답과 장면**으로 풀어 쓴다. 사실처럼 쓸 수 없는 것: 실제 연애의 시작 · 이별 · 상대의 속마음.

## 5. 후보 선택과 AI 전달 (고객 관심 중심)

```
명식 + 성별 + 기준일
   │ ① 후보 수집: 프레임 전체의 겹침 조건 검사 → 나온 프레임 + 얼굴 + 시기 창 (코드, 0원)
   ▼
후보 풀 (명식당 약 16개 프레임)
   │ ② 점수 매기기: 희소도(명중률 역수) · 겹친 신호 수 · 시기 적합(과거는 현재 나이 이전만)
   │               · 고객 관심 가중(연애 · 재물 · 과거 회고 · 미래 흐름 우선) · 응답 적합(얼굴 순서만)
   ▼
   │ ③ 중복 정리: 같은 신호를 두 장이 핵심으로 쓰지 않는다 · 같은 소재 한 번 · 영역당 2~3개
   ▼
후보 묶음 (영역당 2~3개 · 약 20개 안팎) ── 읽기 카드 21개(질문 풀)와 연결
   │ ④ AI: 묶음에서 1~2개를 골라 "과거 가능성 → 현재 응답 → 미래 흐름" 이야기로 쓴다 (후보 밖 해석 금지)
   ▼
   │ ⑤ 기존 검사(근거 · 단정 금지 · 시기 · 용어)로 확인
```

- **희소도 우선**이 흔한 조합의 반복을 막는다(측정: 영역마다 카탈로그 순서로 고르면 과거 영역에서 두 명식이 같은 선택일 확률이 22%, 희소도 우선이면 9.3%).
- **고객 관심 가중**: 연애 · 재물 · 과거 회고에 높은 가중(운영자 지정), 영역마다 최소 1개 보장(프레임이 없으면 비운다 — 지어내지 않는다).
- **응답은 보조**: `responseHooks`가 있는 프레임에서만 응답이 "match면 이어 쓰기 · differ면 상황별 차이로 설명 · complement면 응답이 구체화 · none이면 사주만"을 정한다. **같은 응답을 두 장의 핵심 근거로 반복하지 않는다**(운영자 결정 그대로).
- 시각을 모르면 시주에 기대는 프레임(G5 등)을 후보에서 뺀다. 월주가 절기 경계면 월지에 기대는 프레임은 `uncertain`으로 해석 근거에서 제외한다(기존 규칙 그대로).

### 6-1. 첫 측정 결과 (프레임 78개 · 4,000명, 고정 시드 20261018)

가정: 출생 1960~2006 균등 · 성별 반반 · 시각 미상 20% · 기준일 2026-10. **실제 이용자 분포가 아니다.** 프레임 조건은 미유가 정한 설계 가설이며 전통 문헌 · 전문가 검토를 거치지 않았다. 이 숫자는 **후보 구조의 차이**이지 완성된 글의 차이가 아니다. 스크립트는 저장소에 올리지 않았다(구현 승인 뒤 정식 측정 도구로 만든다).

- **명식 하나당 프레임**: 평균 16.5 · p10 12 · 중앙 16 · p90 21 · 최소 5 · 최대 27. 각 프레임은 얼굴 둘 이상이라 **약 33개 이상의 해석 각도**.
- **영역별**(프레임 수 · 명식당 평균 · 한 개도 없는 비율): A 12 · 2.2 · 4.1% / B 11 · 1.4 · 17.7% / C 9 · 1.5 · 13.3% / D 9 · 1.6 · 11.5% / E 8 · 1.4 · 12.2% / F 7 · 1.4 · 9.1% / G 6 · 1.3 · **32.3%** / H 8 · 2.6 · 5.2% / I 7 · 2.0 · 9.4% / J 1 · 1.0 · 0%.
- **명중률 80% 이상**: J(개운)뿐. **5% 미만**: 12개(부록 표시).
- **두 명식의 프레임 집합 겹침**: 자카드 평균 **0.235**, 완전히 같은 쌍 **0.00%**.
- **영역마다 2개 고르기 — 두 명식이 같은 선택일 확률**(드문 것 우선): A 2.9% · B 8.4% · C 6.6% · D 5.5% · E 10.3% · F 6.1% · **G 15.0%** · H 9.3% · I 4.9%. 카탈로그 순서로 고르면 H 22.0% · G 15.7% — 희소도 우선이 낫다.
- **9개 영역 선택을 합친 전체 조합**: 3,837가지 / 4,000명(가장 흔한 조합 3명).
- **과거 회고 인스턴스**(프레임 + 나이대 5년): 명식당 평균 3.5 · p10 0 · p90 7 · **0개 10.0%**(그 사람은 "사주에서 읽은 시기" 대신 보편 경험으로 라벨을 달리해 한 줄) · 가장 드문 인스턴스를 고르면 서로 다른 값 43종, 두 명식이 같을 확률 4.0%.

**읽는 법**: 지금 근거는 같은 십성 그룹이면 같은 cue 문장(94쌍 중 70쌍)이었다. 프레임 구조에서는 같은 프레임 집합인 명식이 없고 영역별 선택이 같을 확률이 대부분 10% 이하다. **다만** 이 숫자는 구조의 차이를 센 것이고, 같은 프레임을 받은 두 사람에게 AI가 비슷한 글을 쓰는 문제(문장 반복)는 별도다 — 실제 글을 읽어야 안다.

## 7. 글쓰기 단계 (프롬프트 변경은 하지 않는다 — 개념만)

운영자가 정한 순서: ① 명리 근거 확장 → ② 해석 후보 여러 개 → ③ 고객 관심 중심 선별 → ④ AI가 인생 이야기로 작성.

- AI 입력 = 기존 근거 + **후보 묶음**(프레임 사실 · 의미 키워드 · 얼굴 초점 · 시기 창 · 응답 연결 표시).
- AI의 일 = 후보 중 1~2개를 골라 **과거 가능성 → 현재 응답 → 미래 흐름**으로 엮는다. 선택하지 않은 후보는 쓰지 않는다. 사건 · 나이 · 원인을 단정하지 않는다(검사가 막는다).
- 지시문 0.6은 이 구조가 구현된 뒤에 **후보 사용 규칙을 더하는 최소 수정**으로 한다(문체 · 목차 변경 없음).

## 8. 구현 단계 · 비용 · 승인 (운영자 검토 뒤)

| 단계 | 내용 | 승인 필요 |
| --- | --- | --- |

| 1 | 프레임 계산 순수 함수(`lib/saju/interpret/` 아래, 기존 엔진 값만 사용) + `rule-meta`의 `saju.cand.*` 항목(검토 전 초안) + 불변 시험 | 운영자 승인 |

## 9. 위험 · 한계

- **전통 해석 프레임은 모두 초안이다**(외부 전문가 검토는 하지 않기로 결정). "검증됨 · 감수"라고 쓰지 않고 출처를 직접 확인하지 못한 프레임은 "전통 해석"으로만 쓴다.
- **바넘 효과**: 조합이 많아져도 키워드가 막연하면 누구에게나 맞는 말이 된다 — 프레임은 **측정 가능한 사실(위치 · 개수 · 시기)**에 묶고 얼굴 초점을 구체적 주제로 둔다.
- **후보가 많다고 글이 좋아지지 않는다.** 같은 프레임에서 AI가 반복하는 문제는 별도이고(문장 반복은 기존 검사 · 사람이 읽는 평가) 이 설계는 **재료의 다양성**만 다룬다.
- **고정 문장이 키워드로 위장되는 위험**: `meaning` · `faces`가 사실상 문장이 되면 74% 문제가 되돌아온다 → 8단어 · 서술어 금지 검사.
- **과거 회고는 불안 · 단정으로 흐를 수 있다**: 나이대 창 · 가능성 표현 · 현재 나이 이전만 · 응답과 모순되면 쓰지 않음. 민감한 주제(이별 · 가족)는 프레임이 있어도 과장하지 않는다.
- **측정은 설계 가설 위의 숫자다.** 프레임 조건을 바꾸면 숫자가 바뀐다. 균등 출생 분포 가정은 실제 이용자와 다르다.
- **계산 차이**(`saju-opensource-survey-v1.md` 4장): 지장간 표 · 오행 개수 방식이 학파마다 달라 근거에 "어느 기준인지"를 밝혀야 한다.
- **시각 미상**: 시주 프레임 제외, 월주 경계 흔들림은 `uncertain`, 대운 전환은 연 단위 "무렵".
- **라이선스**: `ruanxiaoer888/bazi-engine`의 규칙 데이터(CC BY-NC-SA)는 보지 않고 쓴다 · Open Bazi Engine은 라이선스 표시가 없어 코드를 가져오지 않는다.

## 10. 운영자 결정 항목

1. 프레임 카탈로그(부록 78개)의 **영역 · 방향 승인** 또는 수정(특히 D 연애 · E 재물 · H 과거).
2. **G 인간관계 영역을 넓힐지**(프레임 6개로는 부족하다는 측정).
3. 프레임의 AI 전달 형태 — **사실 + 의미 키워드 + 얼굴 초점**(문장 고정 금지) 선을 이대로 둘지.
4. **배우자성 기준**: 전통 한 가지(남 재성 · 여 관성)로 둘지, 두 학파를 병기할지(Bazi Atlas 방식).
5. **십이운성(표)** 추가 여부 — 새 계산이며 네 개 오픈소스가 같은 표를 쓰는 항목이라 대조는 쉽다. 신살이 아니다.
6. **지장간 표 · 오행 개수** 근거에 "어느 기준인지" 표시를 넣을지(표 자체는 바꾸지 않는다).
7. 시기 프레임이 없는 사람(10%)의 과거 회고를 **보편 경험 라벨 한 줄**로 둘지 비워 둘지.
8. 구현 승인 시점과 **4차 AI 시험을 구현 뒤로 미룬다**는 순서 확인(운영자 말씀대로 지금은 시험하지 않는다).

## 11. 하지 못한 것

- 프레임 78개 조건은 내가 정한 가설이다 — **전통 문헌과 대조하지 못했고 전문가 검토도 받지 않았다.**
- 측정은 **프레임 구조**의 차이뿐이다. 후보를 AI에게 주었을 때 글이 실제로 달라지는지는 **한 번도 시험하지 못했다**(승인 전 호출 없음).
- 응답 민감도 시험은 설계만 했고 코드로 돌리지 않았다.
- 표본의 출생 분포 · 성별 비율 · 시각 미상 비율은 가정이다.
- 외부 엔진과 같은 출생정보로 계산을 대조하지 못했다(조사 문서 참고).
- 전통 의미 키워드(`meaning`)의 문헌 출처를 직접 확인하지 못했다.
