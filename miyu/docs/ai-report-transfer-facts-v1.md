# 개인 심층 리포트 생성 시 AI 제공사 전송 사실표 (검토용 · 2026-10-19)

**이 문서는 법률 검토자가 볼 사실표다.** 개인정보 처리방침의 공개 문구를 바꾸지 않았고(공개 적용 없음), 법률 적합성(위탁인지 제3자 제공인지 · 국외 이전 해당 여부 · 동의 필요 여부)을 판단하거나 선언하지 않는다. 전송 구조도 바꾸지 않았다. 아래는 **코드를 읽어 확인한 것**, **운영자 PC 보고로만 아는 것**, **확인하지 못한 것**을 칸으로 나눈 것이다.

- **범위**: 개인 심층 리포트(기본 형식 `story-7`, 한 줄로 되돌리는 `story-v1`도 같은 근거를 쓴다)를 만들 때 서버가 AI 제공사(Anthropic)로 보내는 요청. **채팅 자유 질문 · 맛보기 리포트 · 고민 반영 리포트 · 사주 궁합 · 리포트 궁합의 AI 요청은 이 표에 없다** — 경로마다 보내는 항목이 달라 따로 작성해야 한다(미작성).
- **근거**: `lib/report/survey-evidence.ts` · `lib/report/ai/generator.ts` · `lib/report/reading/story7-prompt.ts` · `lib/integrations/ai/providers.ts` · `supabase/migrations/…ai_usage.sql` · `app/privacy/page.tsx`(현재 공개 문구) · 운영자 PC의 5차 저장본(`input-check.md` 5절)을 읽은 보고. 이 환경에서 네트워크 수준으로 실제 요청 본문을 잡아 보지는 못했다. 입력 확인 파일(`input-check.md`)은 **실제 요청과 같은 함수**로 만든 사본이고 일치는 `lib/report/ai/own-run.test.ts`가 시험한다.
- 표에는 개인 값(글자 · 연도 · 나이 · 점수 · MBTI)을 적지 않았다.

## 1. 전송 항목 (요청 한 건의 구성)

요청 본문은 `model · max_tokens · system(지시문) · messages · thinking · output_config`뿐이고 사용자 식별 필드(메타데이터 · 사용자 ID)는 없다(`providers.ts`). `messages`의 첫 사용자 메시지는 JSON 하나(`buildStory7UserMessage`)이며 그 구성은 다음과 같다.

| # | 항목 | 요청 안의 위치 | 내용(범주) | 본인 정보인가 | 확인 |
| --- | --- | --- | --- | --- | --- |
| 1 | 지시문 | `system` | 고정 문구(말투 · 금지 · 형식) | 아니오 | 코드 |
| 2 | 기준 날짜 | `referenceDate` | 요청을 만든 날의 날짜 | 아니오(생성 시각) | 코드 |
| 3 | 사주 원국과 계산 결과 | `evidence[].fact` · `cue`(`saju.*`) | 원국 여덟 글자(출생 시각을 모르면 세 기둥)와 자리, 일간, 오행 개수, 십성 분포, 월령 · 뿌리 · 강약 후보 · 조후 후보, 지장간, 공망, 배우자 자리 · 별, 육친 대응, 인연의 경향(나이 방향), 개운 후보 | **예** — 생년월일 원문은 아니지만 원국과 아래 4번으로 출생 연도 · 월을 대략 추정할 수 있다 | 코드 · 운영자 PC 보고 |
| 4 | 시기 | `evidence[].fact`(`saju.daeun.*` · `saju.seun.*` · `saju.frame.*`), `period` · `ageWindows` | 대운 · 세운 간지와 **연도 범위**, 프레임 시기 근거의 **"만 N세 무렵" 나이 범위** | **예** — 출생 연도 · 월 추정 가능 | 코드 · 운영자 PC 보고 |
| 5 | 성별에서 나온 문구 | `saju.spouse-star` · `saju.partner` 등의 `fact` | "여성 원국 / 남성 원국" 같은 문구(성별 입력값이 문장으로 들어감) | **예** | 운영자 PC 보고 |
| 6 | 출생 시각 모름 여부 | `saju.hour.unknown` | 시각을 모를 때만 있는 근거 | **예**(입력 여부) | 코드 |
| 7 | 응답에서 계산한 근거 | `evidence[].fact` · `cue`(`survey.*`) | **항목 이름 + 응답 환산값 숫자(0~100) + "(응답 환산값, 개발용 문항 — 백분위가 아님)"** 과 경향 문장. 뚜렷한 영역(65 이상 · 35 이하)만 | **예** — 문항 문장과 고른 선택지는 가지 않으나 환산값 숫자는 간다 | 코드(`survey-evidence.ts` 34 · 50 · 86행) |
| 8 | 입력한 MBTI | `evidence[]`(`self.mbti`) | 본인이 알고 있는 MBTI **네 글자**와 선호 방향 문장 | **예** | 코드(`survey-evidence.ts` 97행) |
| 9 | 용어 사전 · 장 구성 · 시기 목록 | `terms` · `sections` · `periods` | 고정 사전 · 장별 질문 · 근거 ID 목록 | 아니오(3~8번의 근거 ID를 가리킴) | 코드 |
| 10 | 고민 맥락(조건부) | `context` | 저장된 고민 기록이 **있을 때만**: 주제 · 질문 · 상황 · 맞았던/달랐던 점 · 발췌(연락처 등은 가림 처리 후). 고민 입력 화면은 지금 숨겨져 있어 새로 쌓이지는 않으나(`CONCERN_RECORDS.visible = false`) 이미 저장된 맥락이 있으면 간다 | **예**(자유 서술) | 코드(`report-service.ts` 127행 · `context.ts`) |
| 11 | 고쳐 쓰기 재호출 | 같은 대화의 다음 요청 | 첫 응답이 검사에 걸리면(운영 기본 고쳐 쓰기 1회) **모델이 쓴 이전 글(최대 20,000자)과 오류 목록**이 같은 대화에 다시 실려 간다 | **예**(생성된 글) | 코드(`generator.ts` 393행) |

**가지 않는 것(코드로 확인)**: 닉네임 · 이메일 · 로그인 식별자 · 회원번호 · 주문번호 · 생년월일 원문 · 출생지 · 22개 문항의 문장과 고른 선택지 · 결제 정보. 닉네임은 생성된 글의 `{name}` 자리에 서버에서 나중에 채운다(story-7은 `story7-assemble.ts`의 `fillStory7Name`). 시험은 닉네임 · 연도 · 지역 · 시각 문자열이 요청에 없음을 확인한다(`own-run.test.ts`).

## 2. 목적

| 요청 | 목적 |
| --- | --- |
| 첫 요청 | 구매한(또는 생성이 승인된) 개인 심층 리포트 본문 작성 |
| 고쳐 쓰기 요청 | 같은 리포트가 형식 · 근거 검사를 통과하지 못했을 때 다시 쓰기 |

## 3. 확인된 처리 경로 (코드)

| 단계 | 확인된 사실 |
| --- | --- |
| 전송 | 서버가 `https://api.anthropic.com/v1/messages`로 HTTPS 요청을 직접 보낸다(Node 기본 `fetch`, 제공사 SDK · 중계 서버 없음, `providers.ts`). 주소를 바꾸는 선택값(`baseUrl`, 기본값이 위 주소)이 코드에 있다 — 운영에서 쓰는지는 확인하지 않았다 |
| 호출 전 | 승인 금액 · 기간 · 호출 수를 호출마다 확인하는 가드와 하루 예산이 있다. 어기면 요청이 나가지 않는다 |
| 우리 쪽 호출 기록 | 표 `ai_usage`: 리포트 번호 · 제공사 · 모델 · 지시문 버전 · 입력/출력 토큰 수 · 예상 비용 · 지연 시간 · 결과(ok · invalid · timeout · error) · 오류 코드 · 목적 · 크레딧 종류 · 방 이름 · 요청 키. **요청 · 응답 · 리포트 내용은 없다** |
| 우리 쪽 보관 | 생성된 리포트는 Supabase에 저장되고 구매자 본인이 조회한다(전송이 아니라 보관). 탈퇴 시 삭제 범위는 `withdrawal-policy.md` |
| 로그 · 알림 | 서버 로그 · 운영 기록 · 알림에는 비밀값 가리기(`lib/ops/redact.ts`)를 거친 값만 남긴다는 규칙과 구현이 있다. **모든 경로의 실제 로그를 점검해 본문이 남지 않음을 확인한 것은 아니다** |
| 현재 공개 문구(변경하지 않음) | 처리방침 5번 "처리 위탁"에 Anthropic은 **"자유 질문에 답하는 AI (질문 글과 그 방의 풀이 글만 전달, 이름 · 생년월일 제외 …)"** 로만 적혀 있고, **리포트 생성 요청의 전송 항목은 공개 문구에 없다.** 같은 5번에 "위탁 업체별 위치와 국외 이전 여부는 출시 전 확정"이라는 문장이 있다 |

## 4. 확인하지 못한 것 (이 환경에서 알 수 없다)

| 항목 | 왜 모르는가 | 어디서 확인하나 |
| --- | --- | --- |
| 제공사 쪽 보관 여부와 기간 · 학습 이용 여부 · 오용 방지 목적 보관 · 사람이 열람하는 경우 · 하위 처리자 | 코드로 알 수 없고 이 세션은 계약 · 콘솔 설정을 보지 못했다 | 운영자 계정의 계약 형태 · 데이터 보존 설정 · 제공사 약관 원문 |
| 처리 지역(서버 위치)과 국외 이전 해당 여부 · 고지 방식 | 위와 같음 + 법률 판단 | 법률 검토(`legal-review-list.md` 1-1) |
| 위탁인지 제3자 제공인지, 동의가 필요한지 | 법률 판단 — 이 문서는 판단하지 않는다 | 법률 검토 |
| 요청을 보내는 웹 호스팅 서버의 위치 | 호스팅 업체가 미확정(처리방침에도 "출시 전 확정") | 운영자 결정 |
| 실제 네트워크 수준의 요청 본문 | 이 환경에는 키가 없어 호출하지 않았다 | 운영자 PC의 입력 확인 파일(같은 함수로 만든 사본)과 5차 저장본 |
| 모든 로그 경로에서 본문이 남지 않는다는 실측 | 하지 않았다 | 스테이징 점검(`launch-qa-readiness-v1.md` Q-PRV-05) |
| 채팅 · 맛보기 · 고민 · 궁합 2종의 AI 요청 항목 | 이 표의 범위 밖 | 경로별로 같은 형식의 표를 따로 작성 (궁합 2종: 2026-10-19부터 요청에 **사용자가 알려 준 두 사람의 사이**(여섯 값 중 하나 + 읽는 법 지침)가 더해졌다 — `compat-relationship-v1.md` 4장. 이름 · 생년월일 · 성별은 값으로 가지 않는다. 공개 처리방침 3-2에 이 범위와 "현재 AI 미연결"을 사실로 적었다 — 법적 충분성은 검토 전) |

## 5. 이미 바로잡은 사실 어긋남 (2026-10-19)

| 어디 | 전에는 | 사실 | 조치 |
| --- | --- | --- | --- |
| 입력 확인 파일 1절 (`lib/report/ai/own-run.ts`가 새로 만드는 안내 문구) | "가지 않는 것: … 점수 숫자" | 응답 환산값 숫자와 MBTI 네 글자가 근거 문장 안에서 간다 | 새로 만드는 안내 문구만 정정했고 일치 시험을 더했다. **이미 저장된 5차 입력 확인 파일은 바꾸지 않았다**(운영자 PC의 원본이며 옛 문구가 그대로 있다) |
| `legal-review-list.md` 1-1 | "점수는 보내지 않는다" | 같음 | 사실대로 정정 |

전송 구조(어떤 값이 요청에 들어가는지)는 바꾸지 않았다. 환산값 숫자를 보낼지는 운영자 결정이고, 바꾸면 근거 `fact`를 읽는 검사들의 영향 범위를 먼저 봐야 한다.

## 6. 검토자에게 묻고 싶은 것 (결정은 운영자 · 법률 검토)

1. 위 3~8번(원국 · 시기 · 성별 문구 · 응답 환산값 · MBTI)을 보낸다는 사실을 처리방침에 어느 수준으로 적을 것인가.
2. 출생 연도 · 월을 추정할 수 있는 정보(원국 · 시기의 연도 · 나이 범위)를 생년월일 원문과 달리 취급해도 되는가.
3. 고쳐 쓰기 때 모델이 쓴 글이 다시 실려 가는 것(11번)의 고지.
4. 제공사 쪽 보관 · 학습 이용 · 국외 이전의 확인 방법과 시점.

## 7. 이 문서가 하지 않는 것

법률 적합성을 선언하지 않는다 · 처리방침 · 약관의 공개 문구를 바꾸지 않았다 · 전송 구조를 바꾸지 않았다 · AI를 부르지 않았다.
