## 2. 읽는 방식 (점수를 더하지 않는다)

1. **선택지 → 행동 근거 한 문장.** 선택지 문장을 그대로 쓰지 않는다. 예: s15-3 "왜 취소됐는지 상황을 좀 더 물어본다" → "가까운 사람과의 약속이 취소되면 왜 취소됐는지 더 물어본다". 점수 · 유형 이름은 붙이지 않는다.
2. **장면마다 주 구분 하나.** 같은 장면이 여러 구분에 겹쳐 반영되지 않는다. 주 구분이 아닌 읽기는 하지 않는다. 선택지가 그 구분의 어느 쪽인지 문장만으로 정할 수 없으면 **읽지 않는다**(29개, 이유를 표에 적었다).
3. **구분 9개**: 에너지를 채우는 방식 · 정보를 받는 방식 · 결정/판단 기준 · 일을 꾸리는 구조 · 예상 밖 상황의 첫 반응 · 시도와 신중/새로움 · (애착 세 가지 방식) 가까운 사람과의 확인 방식 · 갈등 뒤 회복 순서 · 도움 받는 방식.
4. **구분마다 여러 장면을 가로로 읽는다**(아래 3장). 평균 내지 않는다.
5. **애착은 이름 대신 세 가지 방식으로만** 읽는다(안정 · 불안 · 회피형이라는 이름은 어디에도 쓰지 않는다). 세 방식은 **개인 유형 10개 계산에 연결하지 않는다.**
6. **응답은 사주를 구체화하는 재료**다. 사주가 큰 방향(갈래)을 정하고 응답이 그 안의 모습을 가른다는 기존 순서를 그대로 둔다.
7. 리포트 AI에는 점수가 아니라 "사실 + 조건형 해석 후보 + 쓰는 사주 조건 + 붙이면 안 되는 결론"을 근거로 넘기는 방식(기존 `scenario-evidence.ts`의 형식)을 쓴다 — **이 연결은 만들지 않았다**(AI 호출이 필요한 단계).

## 3. 충분 · 상반 · 부족 판정 규칙

구분 하나를 읽는 순서(코드 `judgeDistinction`):

| 순서 | 조건 | 결과 |
| --- | --- | --- |
| 1 | 그 구분을 읽는 장면이 3개보다 적게 설계됨 | **부족**(`design-short`) — 어떤 답이어도 읽지 않는다 |
| 2 | 답한 장면(1~4번을 고름)이 3개보다 적음. "해당 없음" · 미응답은 답한 것으로 세지 않는다 | **부족**(`few-answered`) |
| 3 | 답한 장면 가운데 그 구분으로 읽히는 선택을 한 장면이 2개보다 적음 | **부족**(`few-read`) |
| 4 | 읽힌 쪽이 둘 이상. 약하게 읽힌 선택도 반대쪽 신호로 센다 | **상반(상황별 차이)** — 어느 쪽이 진짜인지 정하지 않고 장면 이름과 함께 둘 다 보인다 |
| 5 | 읽힌 쪽이 하나, 뚜렷하게 읽힌 장면이 2개보다 적음 | **부족**(`weak-only`) |
| 6 | 읽힌 쪽이 하나이고 같은 쪽 읽기가 한 가지 맥락(일 · 친구 · 가까운 관계 · 혼자)에만 있음(가까운 관계 구분은 맥락이 하나뿐이라 이 조건이 없다) | **부족**(`one-context`) |
| 7 | 그 밖(읽힌 쪽 하나 + 뚜렷한 장면 2개 이상 + 맥락 조건 통과) | **충분** — 읽힌 장면이 3개 이상이면 강, 2개면 중 |

## 5. 기존 개인 유형 10개 연결안

**구조는 그대로다**: 사주가 큰 방향(갈래 후보, `personal-type.ts`의 `sajuTilt`)을 정하고, 응답이 그 안의 두 모습 가운데 하나를 가른다. 두 모습을 가르는 응답 행(`FLAVOR_RULES`)과 유형 이름 · 문구는 **한 글자도 바꾸지 않는다.** 바뀌는 것은 응답 행을 읽는 방법뿐이다 — 22문항은 점수의 차이로, 28문항은 위 3장의 읽기 상태로.

| 응답 행 | 28문항으로 읽는가 |
| --- | --- |
| ei · tf · jp | 읽는다(에너지 · 판단 기준 · 구조) |
| caution · novelty | 읽는다(첫 반응 · 시도와 신중/새로움) — 점검 먼저 = caution 높음, 바로 실행 = 낮음, 익숙한 쪽 = novelty 낮음 같은 **근사**이며 신중한 기질이라고 단정하지 않는다 |
| sn · sensitivity · persistence · avoidance · anxiety | **읽는 구분이 없다** — 어떤 답이어도 근거가 없다 |

**결과(코드 `typeCoverage`)**: 두 행을 모두 읽는 유형은 **신중 몰입형 · 안정 구축형 · 유연 적응형** 3개, 한 행만 읽는 유형은 **섬세 공감형 · 독립 추진형 · 관계 조율형 · 탐색 확장형 · 기준 중심형 · 책임 완수형** 6개, **빠른 실행형은 읽는 행이 하나도 없어 닿을 수 없다.**

**정하는 규칙(코드 `readFlavor28` · `typeFrom28`)**:
- 한 모습만 받쳐지고(받치는 행이 둘 이상이거나 강한 방향 하나) 그 모습의 다른 행이 상황별 차이로 읽히지 않았을 때만 정한다. 지금 22문항보다 보수적이다.
- 두 모습이 모두 받쳐지거나, 받침이 하나뿐인데 강하지 않거나, 읽은 행이 없으면 **유형을 정하지 않고 혼합 경향**이다(이유를 구분해 둔다). 사주 후보가 둘 이상일 때는 받침이 더 많은 하나만 고르고 같으면 정하지 않는다.
- 사주가 갈래를 정하지 못하면(`balanced` · `month-uncertain`) 응답과 상관없이 정하지 않는다.
- **운영자 예시 입력(2026-10-17에 고른 28개, 기본값 아님)** 은 에너지 · 판단 기준 · 첫 반응 · 시도와 신중 · 회복 순서에서 상황별 차이가 나와 어느 사주 갈래에서도 유형이 붙지 않는다 — 억지로 하나로 묶지 않는 예시다(표 문서 예시 D).

**가상 무작위 응답 5,000개 측정**(모든 선택지를 같은 확률로 고른 가상 응답이며 실제 사람이 아님): 갈래가 하나로 정해졌다고 가정했을 때 유형이 붙은 몫은 비겁 9.9% · 식상 1.3% · 재성 3.4% · 관성 4.0% · 인성 5.2%. 이 숫자는 설계가 어디서 막히는지 보는 참고이고 사람의 몫이 아니다.

| 저장 | `assessments.answers`(jsonb) = 문항 id → 1~5 · `content_version` 열이 이미 있음 | 같은 열에 장면 id → 선택지 번호와 새 `content_version`. **열 · 표를 새로 만들 필요가 없을 수 있다**(확인 필요). 다만 입력 검증(`pickKnownAnswers` · `validateAnswers`)은 22문항 id 전용이라 새 검증이 필요하다 | 기존 행은 바꾸지 않는다 |
| 요약(`summary`) | 지금 모양(`FreeSummary`: 점수 행)을 화면 · 리포트 · 맛보기 · 궁합 근거가 모두 읽는다 | 새 버전은 점수가 아니라 읽기 상태를 담아야 하므로 **새 모양**이 필요하다. 읽는 쪽 코드(`free-insight` · `survey-evidence` · 개인 유형 · 맛보기 입력 · `pair-evidence`)가 두 모양을 구분해서 읽어야 한다 | 저장된 summary는 다시 계산하지 않는다 |
| 무료 미리보기(로그인 전) | `scoreDevAnswers` → `buildDevFreeSummary`(단일 입구) | 같은 입력에서 같은 읽기 · 같은 유형을 내는 **하나의 함수**를 로그인 전 · 후가 함께 쓰게 한다(`free-preview-parity.test.ts`와 같은 방식으로 확인) | 영향 없음 |
| 로그인 후 · 이어 쓰기 | 탭 임시 보관(`profile/draft.ts`) · 로그인 전 보관 쿠키 | 임시 보관에 **질문 버전 id**를 함께 넣어 다른 버전의 답을 섞지 않는다 | 22문항을 풀던 중이면 22문항으로 이어서 끝낸다 |
| 개인 유형 · 럭키 지수 | 사주 갈래(변경 없음) + 22문항 점수로 두 모습 가르기 | 사주 쪽은 그대로, 응답 쪽만 5장의 연결안으로 교체 | 저장된 유형은 그대로 보임 |
| 무료 풀이 · 리포트 근거 · 맛보기 | 점수 행 → 문장 · 근거 | 읽기 상태 → 근거(사실 + 조건형 해석 후보 + 쓰는 사주 조건 + 붙이면 안 되는 결론). **AI 지시문 · 검사 수정과 실제 AI 재검증(별도 승인 비용)이 필요하다** — 이번에 하지 않았다 | 저장된 글은 바뀌지 않는다 |
| 리포트 궁합 | 두 사람의 같은 영역 점수(뚜렷한 영역만) 비교 | 두 사람이 **같은 질문 버전**으로 답했을 때만 같은 장면 · 읽을 수 있는 구분 단위로 비교. 22문항과 28문항 사이는 비교하지 않는다(해당 영역 "비교하지 않음") — **운영자 결정 항목** | 이미 연결된 쌍 · 결제한 쌍은 그대로 |
| 간단 궁합 · 사주 궁합 | 질문 응답을 쓰지 않음 | 영향 없음 | 영향 없음 |
| 공개 안내 · 문항 기록 | `/assessment-basis` · `provenance.ts`는 22문항 기준 | 28문항은 외부 추천 문항이라 독립성 미확인 — 안내 문구와 출처 기록을 새 문항에 맞춰 고쳐야 한다(법적 보증 아님) | 영향 없음 |
