# 장면 질문 풀이 검사 보강 · 테스트 화면 (2026-10-16)

**상태: 개발용. 일반 이용자 화면 · 검사 · 저장된 회원 결과 · 점수표 · 운영 리포트 생성에는 연결하지 않았다.** 기존 회원의 결과 · 결제 · 권한 · 운영 화면은 바꾸지 않았다.
**실제 AI는 이번에 한 번도 부르지 않았다.** 아래 글은 모두 시험용 대리 작성기(AI 하위 작업자)가 쓴 것이고 실제 서비스 AI의 글이 아니다.

운영자 지적(2026-10-16): "잘못된 응답 추가와 선택지 재진술이 제품 검사를 통과함 — 운영 연결 전에 검사도 고쳐야 한다."

## 2. 검사는 세 겹이고, 통과/실패와 품질을 따로 낸다

| 겹 | 무엇을 보나 | 어디 있나 | 한계 |
| --- | --- | --- | --- |
| ① 코드 검사 | 글자 · 정규식으로 찾을 수 있는 표지 | `lib/report/reading/answer-use.ts` (+ 기존 `validate.ts`) | 말만 바꿔 되풀이한 문장을 못 찾는다(정밀도를 높게, 재현율을 낮게 잡았다) |
| ② 의미 검토 | 문장마다 결론인지 · 답 요약인지 · 지어낸 응답인지 | `lib/report/reading/semantic-review.ts` (질문지 + 결과 읽기) | **실제 서비스에 연결하지 않았다** — 검토용 AI 호출은 비용이라 운영자 승인이 따로 필요하다 |
| ③ 사람이 읽는 평가 | 새로 알게 해 주는지 · "미유다운지" | 운영자 · 가려 읽는 사람 | 한 번도 하지 않았다 |

코드 검사는 둘로 나뉜다. **하나로 합쳐 "통과 · 실패" 하나만 내지 않는다.**

| 구분 | 이름 | 무엇을 막나 | 어기면 |
| --- | --- | --- | --- |
| 지어내지 않았는가 (통과 / 실패) | ECHO | 고른 선택지 문장(또는 끝맺음만 바꾼 문장)을 그대로 옮김 | 글을 저장하지 않는다 |
| | INVENTED | 답을 받지 못한 장면(해당 없음 · 선택지 없음 · 미응답 · 한 장면만 답함)의 행동 · 반응을 사실처럼 씀. 관계 반응 단계의 상황이 그런 장면이면 단계들이 모두 해당 | 글을 저장하지 않는다 |
| | UNCITED | 읽은 구분의 행동을 그 근거 ID를 달지 않고 씀 | 글을 저장하지 않는다 |
| 새로 알게 해 주는가 (별도 품질) | TITLE | 제목이 고른 답 둘 이상을 나열하거나, 답 하나를 제목의 절반 넘게 그대로 요약 | 켜 두면 고쳐 쓰게 한다(`quality: false`로 끌 수 있다) |
| | FLAT_EITHER | "~인지 ~인지 그날그날 달라질 수 있어요"처럼 갈라 주는 조건 없이 끝남 | 켜 두면 고쳐 쓰게 한다 |

### 허용하는 것 / 막는 것

- **허용**: 사주에서 읽은 성향을 조건형("~기 쉬워요 · ~수 있어요 · ~했을 거예요")으로 그 장면에 적용하는 추론. 공감과 예측은 계속 쓴다.
- **막음**: 답하지 않은 응답을 답한 것처럼 쓰는 것 — "사주로 읽은 경향"이라고 포장해도 조건형이 아니면 같다.
- **허용(과잉 차단 방지)**: 고른 행동을 풀이 안에서 설명하는 문장("마음이 어느 정도 정리된 뒤에야 이야기를 꺼내는 편이라 …"). 처음에 4글자 조각이 70% 겹치면 막게 했더니 이런 정상 문장(W의 연애 소단락)까지 걸려 **90%로 올렸다**(어림이며 시험으로 정한 값).
- 12글자 미만의 짧은 선택지 글("혼자 정리할 시간")은 일상 표현과 겹쳐 옮겨 쓴 것으로 세지 않는다.

### 근거 구분 (사주 / 응답 / 연결 해석)

글 조각마다 어느 근거인지는 가르지 못한다. 대신 주제 블록마다 인용한 근거를 **사주 · 응답 · 입력 정보(MBTI)**로 나눠 보이고(`sourceMix`), 응답 근거를 달았지만 글에서 그 장면을 쓰지 않은 곳을 알린다. "사주 + 응답"은 한 주제 안에서 두 근거를 이어 읽은 풀이라는 뜻이다. 테스트 화면의 "근거 구분"에 나온다.

## 4. 의미 검토가 더 본 것 (시험용 대리 검토기, 한 번)

`docs/samples/scenario-generation/review/`. 35개 글 조각을 판정했다.

| 글 | 결론 | 답 요약 · 나열 | 지어낸 응답 | 범용 | 얼버무림 |
| --- | --- | --- | --- | --- | --- |
| X | 24 | 6 · 2 | 0 | 1 | 2 |
| X.fixed | 26 | 6 · 1 | 0 | 1 | 1 |
| H.v0.9 | 6 | 0 · 1 | 6 | 20 | 2 |
| H (0.10) | 13 | 0 · 2 | 1 | 17 | 2 |

- **코드 검사를 통과한 X.fixed에서도** 검토기는 맨 위 핵심 문장("신중하게 이해하고, 조용히 빈 곳을 메우는 사람")을 답 요약으로 보았다. 그래서 코드 검사 통과를 "좋은 글"이라고 말하지 않는다.
- **의견이 갈린 곳**: H(0.10)의 성향 제목 "계획이 서야 첫걸음을 떼는 사람" — 읽을 수 없던 장면(혼자 해 볼 수 있는 작은 일 · 역할 없을 때)과 이어지는 성향이다. 검토기는 지어낸 응답으로 판정했지만 "사주에서 온 경향일 수 있어 애매하다"고 적었다. 코드 검사는 장면의 행동을 말하는 문장만 막는다(허용 쪽). **이 선을 어디에 둘지는 운영자 판단이 필요하다.**
- 검토기는 거칠다: H.v0.9에서 35곳 중 20곳을 "범용"으로 보았고, 반응 단계의 상황 설정 문장을 답 요약으로 보았다(질문지에서 상황 설정 자리는 빼야 한다). 같은 글을 여러 번 읽혀 판정이 일치하는지는 보지 못했다.

## 5. 테스트 화면 (`/dev/scenario`)

내 컴퓨터에서만 열린다(공개 배포에서는 열리지 않는다). 아무것도 저장하지 않는다.

1. PowerShell에서 `miyu` 폴더로 이동해 `npm run dev`를 실행한다.
2. 브라우저에서 `http://localhost:3000/dev/scenario`를 연다.
3. ① 누구의 사주로 볼지(서윤 · P01 가상 인물, 또는 내 생년월일 — 저장하지 않고 사주만 그 자리에서 계산해 버린다) → ② 장면 10개에 답한다(좋고 나쁜 답 없음, 점수로 바뀌지 않음) → ③ 풀이 보기.
4. 결과에는 이번 답에서 **읽힌 구분 · 리포트 AI가 받는 응답 근거 · 생성 과정(검사에 걸린 것) · 지어내지 않았나 · 새로 알게 해 주나 · 근거 구분 · 비용**이 보이고 아래에 실제 리포트 화면이 나온다.
5. [저장된 시험 글 보기]는 AI를 부르지 않는다. 서윤 · P01에 기준(X) · 다른(Y) · 일부 없는(H) 응답 등 저장된 조합 그대로일 때만 글이 나오고, 다른 조합이면 읽힌 구분과 근거만 보인다.
6. [실제 AI로 새로 쓰기]는 **닫혀 있다.** 열려면 운영자가 승인한 뒤 `.env.local`에 `DEV_SCENARIO_LIVE=yes`를 직접 적어야 하고, 기존 승인 값(`AI_PROVIDER=anthropic` · `AI_APPROVED_*`)도 있어야 한다. 이전 5,000원 승인에 자동으로 포함되지 않는다. 눌러도 한 번 더 확인하고, 호출은 운영 리포트와 같은 승인 가드를 거친다(승인 금액 · 호출 수 · 기간을 넘으면 요청이 나가지 않는다).

## 6. 하지 못한 것

- 실제 AI로 이 검사 · 지시문 0.11을 시험하지 못했다. 이 검사는 AI가 아니라 대리 작성기의 글로만 확인했다.
- 말만 바꿔 되풀이한 문장 · 사주에서 온 성향 단정과 지어낸 응답의 경계는 코드로 가르지 못한다.
- 의미 검토를 운영 경로에 연결하지 않았고, 검토 결과를 반복해 일치도를 보지 않았다.
- 새 검사는 장면 질문 경로에서만 켠다. 지금 22문항 화면 · 저장된 리포트 · 운영 생성에는 연결하지 않았다.
- 실제 사람에게 질문을 풀어 보게 하거나 글을 읽혀 본 적이 없다(인지 인터뷰 전).

## 7. 7건 생성 경로와 운영 경로의 차이

| 항목 | 7건 시험(X Y Z W H V R) | 운영 경로(`liveReportGenerator`) |
| --- | --- | --- |
| 작성기 | 시험용 대리 작성기(AI 하위 작업자). 파일을 읽고 JSON을 파일로 씀 | 실제 Claude(`claude-sonnet-5-5`)를 API로 호출 |
| 지시문 | 제품 지시문 그대로(0.9 · 0.10 · 이번 고치기는 0.11) | 같다 |
| 사용자 메시지 · 근거 | `buildReadingUserMessage` + 장면 질문 근거(`scenarioEvidence`) | 같은 함수. 근거만 장면 질문 근거로 바꿔 끼움(`adaptEvidence`) |
| 생각 강도 · 최대 출력 · 시간 제한 | 없음(작성기 설정) | 생각 중간 · 최대 출력 24,000 · 호출 5분 |
| 형식 검사 | 제품 검사를 내가 따로 돌려 이유를 전달 | 생성기가 호출마다 검사 |
| 고쳐 쓰기 횟수 | X · W 두 번, Y 세 번(제품보다 많음) | 한 번(반복 표현은 그대로 받아들임) |
| 응답 사용 검사 | 7건을 쓸 때는 없었다(나중에 이번에 대 봄) | `extraChecks`로 켤 수 있음(기본은 없음) |
| 부분만 고쳐 쓰기(Z · V) | 있다(바탕 글을 주고 바뀐 곳만) | **없다.** 운영은 매번 처음부터 쓴다 |
| 비용 · 시간 · 실패율 | 재지 못함 | 호출마다 사용 기록 |

그래서 7건의 결과는 운영 경로의 결과가 아니다. 운영 경로 시험은 `/dev/scenario`의 [실제 AI로 새로 쓰기]로 하고, 비용은 `docs/scenario-live-test-plan.md`의 승인안에 따른다. 부분 고쳐 쓰기(Z · V)는 운영에 없는 방식이라 **처음부터 쓰는 시험과 따로** 본다.
