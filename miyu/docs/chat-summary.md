# 채팅 요약 저장 (운영자 요청 2026-10-15)

채팅방에서 나눈 이야기를 **짧은 "질문 → 답변" 요약으로 저장**하고, MY에서 방(카테고리)별 · 저장한 날짜별로 다시 보는 기능이다. 구현됨 · **DB 14번 변경이 있어야 동작한다**(없으면 저장만 "준비 중"으로 막히고 대화 · 질문은 그대로 된다).

## 사용자가 보는 것

| 위치 | 동작 |
| --- | --- |
| 채팅방 머리글 오른쪽 **[저장하기]** (≡ 메뉴에도 "저장하기 · 지금까지 한 대화를 요약 저장해요") | 지금까지 나눈 대화를 요약해 저장한다. **이전에 저장한 뒤의 대화만** 담는다(저장마다 "이전 저장 이후"). 방금 저장했으면 "새로 저장할 대화가 없어요", 대화가 없으면 "아직 저장할 대화가 없어요". 결과는 머리글 아래 한 줄로 알리고 "저장한 채팅 요약 보기" 링크가 붙는다 |
| ≡ 메뉴 **대화 종료하기** | 대화가 없으면 바로 새 대화로 시작. 있으면 안내창 "**이전 채팅내용은 다시 볼 수 없어요. 저장할까요?**" — **예**(요약 저장 후 종료) · **아니오**(저장하지 않고 종료) · 계속 대화하기(Esc · 바깥 누르기도 같음). 종료하면 이 방의 대화가 지워지고 새 대화로 시작한다. 저장하겠다고 했는데 못 저장하면(한도 · 준비 중) 대화를 지우지 않고 이유를 알린다 |
| MY → **저장한 채팅 요약 보기**(`/my/chats`) | 방(카테고리)별 목록(저장 개수 · 가장 최근 저장일) → 방을 누르면(`/my/chats/<방>`) 저장한 날짜가 최근인 순서로 "질문 / 답변" 목록. 요약 하나 지우기(펼쳐서 한 번 더 눌러야 지워짐) · **이전 대화 기록 모두 지우기** |
| 뒤로 가기(←) | 방을 나가기만 한다. 대화는 서버에 저장돼 있어 다시 들어오면 이어진다(기존 동작). 종료가 아니다 |

예시 화면(가상 인물 서윤)에는 서버 저장이 없어 저장하기 · 대화 종료 버튼이 없다(기존 "이 채팅방 새로 시작하기"만).

## 요약에 담기는 것 (코드가 규칙대로 줄인다 · AI 미사용 — `lib/report/chat/summary.ts`)

- **읽은 풀이 이름표**(예: "가까운 관계") — 리포트 글은 옮겨 담지 않는다(테스트가 확인).
- **먼저 묻는 질문 → 고른 답**(예: "먼저, 지금 어떤 상황인지 물어봐도 될까요? → 썸 타는 중이에요")
- **내 경험 답장**(맞아요 · 상황에 따라 달라요 · 잘 모르겠어요)
- **직접 적은 질문 → 미유 답의 앞부분**(질문 120자 · 답 170자 안에서 문장이 끝난 곳에서 줄인다)
- 일상 예시 · 분석 이유 같은 보조 버튼은 질문이 아니므로 담지 않는다.
- 한도: 요약 하나에 질문 30개 · 읽은 풀이 12개. 직접 저장은 회원당 100개(넘으면 MY에서 지운 뒤 저장).

## 저장하지 않아도 남는 "참고 기록" (운영자 요청 — 숨기지 않고 알린다)

운영자 요청: *저장하지 않으면 사용자가 다시 볼 수는 없지만, 시스템은 내부 기록을 남겨 다음 질문에서 참고한다.*

- 대화를 **저장하지 않고 끝내면**, 같은 요약이 `visible = false`로 남는다. 브라우저(회원 계정)는 읽을 수 없다(DB 접근 정책).
- 같은 방에서 다음에 질문하면 **같은 방 · 같은 검사 결과의** 이전 이야기(직접 저장한 요약 + 참고 기록, 직접 적은 질문과 답만, 최근 4쌍)를 `memory`로 AI에 함께 보낸다. 다른 방의 이야기는 가져오지 않는다(방마다 새 대화로 시작한다는 원칙). 오늘의 운세 방은 쓰지 않는다. 이번 대화에 이미 있는 질문은 중복해서 보내지 않는다.
- AI 지시문 `chat-v1-prompt-0.4`(현재 0.5 — 무료 맛보기 `profile` 추가, `CLAUDE.md` 채팅 항목): memory는 "이전에 한 이야기의 줄임이며 새 근거가 아니다 · 지금 질문과 이어질 때만 가볍게 · 그때의 상황이 지금도 같다고 단정하지 않는다". **이 변경(memory) 뒤 실제 AI 글은 한 번도 보지 못했다(검증되지 않음).** 가짜 AI 서버로는 memory가 전달되는 것까지 확인했다.
- **보관 기간 90일(운영자 결정 2026-10-15)**: 저장하지 않은 대화의 참고 기록은 만든 지 90일이 지나면 다음 질문에서 쓰지 않고(지워지기 전에도), 정기 점검(`/api/cron/reconcile`, 매시 처음 10분 안의 실행)이 지운다. 직접 저장한 요약은 이 기간과 상관없이 회원이 지울 때까지 남는다. 값은 `lib/config/product.ts`의 `CHAT_SUMMARY_POLICY.referenceKeepDays` 한 곳(안내창 · 처리방침 문구가 이 값을 읽는다).
- 알림: 대화 종료 안내창 아래 작은 글씨(90일 뒤 자동 삭제 · 지우는 방법) · 처리방침 3-1 · `docs/withdrawal-policy.md` 11번. 방마다 최근 12개까지만 남긴다.
- 지우기: MY의 **이전 대화 기록 모두 지우기**(저장한 요약 + 참고 기록 모두) · 회원 탈퇴 때 함께 삭제(`withdraw_member_data`).
- 질문 · 답 내용은 `ops_events` · `ai_usage` · `chat_questions` 등 어떤 기록에도 들어가지 않는다(e2e로 확인).

## 확인한 것 · 못 한 것

- 단위 테스트: 요약 규칙(문장 끝 줄이기 · 이전 저장 이후만 · 리포트 글 미포함 · 읽을 때 모양 확인 · 참고 쌍 고르기) · 서비스(저장 · 중복 · 종료 예/아니오 · 참고 기록 · 한도 · 남의 결과 · 지우기 · 탈퇴 · 표가 없을 때) · 질문에 memory가 붙는 것(`chat-service.test.ts`).
- 실제 DB(임시 Postgres + PostgREST): 본인이 저장한 것만 읽힘 · 참고 기록은 브라우저가 못 읽음 · 직접 쓰기 거부 · 서버도 고치지 못함 · 소유자 · 방 이름 · 크기 규칙 · 동시 저장 한 번만 · 대화 저장이 요약 위치를 되돌리지 않음 · 탈퇴 삭제 · **표 · 열이 없을 때**(`npm run test:db`).
- 브라우저(운영 빌드 + 가짜 로그인 · 가짜 AI, 390px · 1440px): 저장 → 중복 저장 안내 → 종료 안내창(계속 / 아니오 / 예) → 참고 기록이 다음 질문에 전달됨 → MY 방별 목록 · 날짜별 요약 · 지우기 · 모두 지우기.
- **못 한 것**: 실제 AI로 memory를 넣은 답이 자연스러운지(한 번도 보지 못했다). 정기 점검이 매시 실제로 도는지(운영자가 `CRON_SECRET` · 예약 실행을 연결해야 한다 — 연결 전에는 90일이 지난 기록을 "쓰지 않을 뿐" 지우지는 못한다). 실제 사용자의 이해(안내창 문구가 충분한지).

## 제안 — 사용자의 "맞아요" 응답을 모아 다른 사람의 풀이에 도움을 주자는 아이디어 (운영자 2026-10-15, **구현하지 않았다**)

운영자 생각: *"맞아요" 같은 반응이 쌓이면 사주 데이터베이스가 되어 다른 사람의 채팅에도 도움이 될 것 같다.*

- **채팅 내용(질문 · 답 · 요약)을 다른 사람의 상담에 직접 쓰는 것은 권하지 않는다.** 개인 이야기가 섞일 수 있고, 지금 처리방침은 그런 사용을 알리지 않았다. 쓰려면 별도 동의 · 비식별 처리 · 처리방침 변경이 먼저다.
- **안전하게 할 수 있는 것(제안)**: 대화 글이 아니라 **풀이마다 누른 반응의 개수**(맞아요 · 상황에 따라 달라요 · 잘 모르겠어요)만 익명으로 센다. 용도는 "어떤 풀이가 자주 어긋나는지" 운영자가 **규칙을 점검하는 참고**이고, 사용자에게 보이는 글에 "N%가 맞다고 했어요" · 정확도를 쓰지 않는다(표본 · 응답 편향을 알 수 없고, 검증된 정확도를 지어내지 않는 원칙). 사주 규칙의 검증 자료로 쓰려면 응답자 구성 · 조건을 따로 설계해야 한다.
- 이미 있는 것: 눌렀던 행동 목록(`talk_rooms`)에는 반응이 들어 있지만 회원별 대화 기록이라, 합산 자료로 쓰려면 개인과 떼어 낸 집계 표가 따로 필요하다(새 마이그레이션 + 처리방침 · 동의 문구).
- 결정이 필요하면: 집계만 할지(권장) · 동의를 받을지 · 언제 만들지.
