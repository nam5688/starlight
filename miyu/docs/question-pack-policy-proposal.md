# 질문 3개 묶음 — 남은 질문 처리 정책안 (제안 · 약관 미반영 · 법적 확정 아님)

- 작성 2026-10-15, 같은 날 2차 수정(운영자 점검 반영) · **제안 문서다.** 약관 · 화면에는 아직 반영하지 않았다. 운영자가 6장의 결정 항목에 답하면 그대로 약관 · 화면에 넣는다.
- 가격은 건드리지 않는다: **질문 3개 묶음 2,500원(부가세 포함), 낱개 없음**(운영자 확정). 이 문서는 "묶음에서 쓰고 남은 질문 1~2개를 어떻게 다룰지"만 정한다.
- **이 문서는 법적으로 확정된 것이 아니고 법률 자문도 아니다.** 법령 조문을 읽은 것과 "내 서비스에 적용되는지"는 다르며 적용 판단은 하지 못했다. 아래 1장에서 **직접 원문을 읽은 것 · 요약만 본 것 · 읽지 못한 것**을 구분했고, 6장의 질문 목록으로 전문가(변호사 · 전자상거래 · 결제 분야)에게 확인받는 것을 권한다. "문제없다"는 결론은 이 문서 어디에도 없다.
- **정책(환불 · 유효기간 · 탈퇴 · 서비스 종료)이 확정되기 전에는 실결제로 질문 묶음을 팔지 않는다.** (고객 문의 채널은 2026-10-16에 정해졌다 — 카카오톡 채널 "미유톡"의 CS 전용 상담톡.) 코드가 막는다 — `MIYU_CASH.policyDecided`가 `true`이고 문의 채널(`lib/config/business.ts`의 `SUPPORT_CONTACT`)이 채워졌을 때만 실결제 모드의 질문 결제가 시작된다(테스트 키 결제는 그대로 열려 있다).

## 1. 확인한 사실과 확인하지 못한 것

"원문 확인"은 공식 자료의 글을 직접 열어 읽은 것(도구가 길게 인용하지 못해 요약으로만 받은 부분은 따로 표시), "요약만"은 검색 결과 요약만 본 것, "못 함"은 확인하지 못한 것이다. **이 표에서 법적으로 확정된 것은 조문의 문구까지**이고 내 서비스에 적용되는지는 어느 줄도 확정이 아니다.

## 2. 환불 계산 — 주문별 누적 방식 (구현됨)

묶음(주문) 하나는 질문 3개 · 2,500원이다. **누적 환불 질문 수 k에 대한 누적 환불액 = ⌈2,500 × k ÷ 3⌉(원 미만 올림)**이고, 토스에 입력할 "이번 취소 금액" = 그 누적액 − 이미 환불한 누적액이다.

| 누적 환불 질문 수 | 누적 환불액 | 이번에 토스에서 취소할 금액 (1개씩 환불할 때) |
| --- | --- | --- |
| 1개 | 834원 | 834원 |
| 2개 | 1,667원 | 833원 |
| 3개 (전부) | **2,500원** | 833원 |
| 합계 | **2,500원** | 834 + 833 + 833 = **2,500원** (예전 방식은 834 × 3 = 2,502원이었다) |

- 한 번에 환불해도 같은 값이다: 2개를 한 번에 → 1,667원, 3개를 한 번에 → 2,500원. **어떤 순서로 나눠 환불해도 마지막 누적액은 같다**(시험으로 확인: 두 계산식이 TS · DB에서 같고, 여러 가격 · 묶음 크기에서 결제액을 넘지 않는다).
- **묶음마다 기록한다**(DB `question_packs`): 산 질문 수 · 쓴 수 · 환불한 수 · 누적 환불액(원) · 구매 시각. 누적 환불액이 결제액을 넘는 값은 DB가 거부한다. 남은 질문 = 산 수 − 쓴 수 − 환불한 수(0 아래로 내려가지 않는다).
- **운영자가 토스 관리자에 입력할 금액**은 `/admin`에서 주문을 찾으면 그대로 보인다(예: "질문 1개 환불 → 833원"). 다른 금액을 넣어 환불하면 미유는 질문을 회수하지 않고 "맞는 누적 금액은 834 · 1,667 · 2,500원"이라고 운영자에게 알린다.
- **이미 쓴 질문은 환불 안내에 넣지 않는다.** 예) 1개를 쓰고 남은 2개를 환불하면 누적 1,667원(쓴 1개 몫 833원은 환불하지 않는다).
- **쓴 질문까지 환불해 버린 경우**(전액 취소 · 환불 처리 중에 질문을 쓴 경우)는 쓴 몫이 "회수하지 못한 몫"으로 기록되고 알림이 나간다. 미유는 쓴 질문 값을 되찾지 않는다.
- **전액 취소**(토스 상태 `CANCELED`)는 같은 함수가 나머지를 모두 반영한다. 부분 환불을 한 뒤 전액 취소해도 이미 회수한 질문은 다시 회수하지 않는다.

## 3. 지금 구현이 하는 것 (코드를 읽고 시험으로 확인한 사실)

| 상황 | 동작 |
| --- | --- |
| 묶음 결제 | 승인되면 DB가 질문 3개를 한 번만 넣고 묶음 한 줄을 만든다. 같은 승인이 6번 동시에 와도 한 번 |
| 질문 사용 | 질문 한 번에 1개. 동시에 6번 써도 정확히 3번만 성공, 잔액 음수 없음. 가장 먼저 산 묶음에서 먼저 쓴다. 답을 받지 못하면 되돌린다(환불로 이미 정산된 묶음이면 돌려주지 않는다) |
| **부분 취소** | **16번 이후 결제분은 반영한다**(웹훅 · 결제 재확인 어느 쪽이든). 16번 전 결제분 · 질문 수에 맞지 않는 금액은 반영하지 않고 운영자에게 알린다 |
| 전액 취소 | 주문 "환불됨", 이 묶음의 남은 질문만 회수(다른 묶음은 그대로) |
| 무료 질문 한도 | DB 예약으로 서버가 여러 대여도 지킨다 |
| 유효기간 | **없다.** 묶음의 구매 시각은 기록하지만 아직 쓰지 않는다 |
| 탈퇴 | 남은 질문이 있으면 막는다(**임시**, 최종안이 아니다) |
| 환불 신청 접수 | **받는 화면이 없다.** 운영자가 고객의 말을 듣고 토스 관리자에서 취소하는 수동 처리뿐이다 |
| 문의 채널 | **카카오톡 채널 "미유톡"(CS 전용 상담톡)** — 하단 · 약관 9조 · 탈퇴 막힘 안내에 표시. 응대 시간 · 환불 처리 담당 방식은 정해지지 않았다 |
| 실결제 | 이용 기준 확정 + 문의 채널이 있어야 열린다 — **문의 채널은 있지만 이용 기준이 미확정이라 지금도 막혀 있다** |

## 4. 정책안

각 항목마다 **옵션 → 추천 → 이유 → 구현에 필요한 것**이다. 추천은 "법이 요구해서"가 아니라 "소비자 분쟁 · 선불 성격 논란 위험을 줄이면서 혼자 운영하기에 단순한" 쪽이다.

### P1. 미사용 질문 환불

| 옵션 | 내용 | 장점 | 단점 |
| --- | --- | --- | --- |
| A | **구매 7일 안 + 쓰지 않은 질문만** 환불, 7일이 지나면 환불 없음 | 환불 부담이 가장 작다 | 7일 뒤 남은 질문이 "돈만 묶인" 상태가 되어 선불 · 상품권 성격 논란이 커진다 |
| **B (추천)** | **유효기간 안이면 언제든 쓰지 않은 질문을 환불**, 수수료 없음, 금액은 2장의 누적 방식 | 선불 성격 논란과 탈퇴 문제를 한꺼번에 줄인다 | 운영자의 수작업이 늘 수 있다(질문 1~2개당 833~1,667원 환불) |
| C | 환불 없음, 탈퇴 때 소멸 안내 | 운영 단순 | F2의 단서와 부딪힐 가능성이 크다 — 추천하지 않는다 |

- 이유: F2 때문에 **7일 안에는 최소한 이 규칙이 필요할 가능성이 높다**(해석). 7일 뒤까지 넓히는 것은 법이 요구한 것이 아니라 제안이다.
- **구현 상태**: 환불 금액 계산 · 부분 취소 반영은 **구현됨**. 환불 신청을 받는 곳(R2)은 **없음**.

### P2. 유효기간 — **각 묶음의 구매일 기준** (예전 "마지막 구매일부터 1년"은 철회한다)

예전 안은 새로 구매할 때마다 남은 질문의 만료일이 함께 늘어났다. 이번에는 **묶음마다 자기 구매일부터 따로** 센다(구매 시각은 이미 묶음 장부에 기록돼 있다). 질문은 가장 먼저 산 묶음부터 쓰이므로 먼저 만료될 질문이 먼저 쓰인다.

| 옵션 | 내용 | 환불 수단과의 관계 (T2) |
| --- | --- | --- |
| A | 없음(무기한) | 장부가 계속 남고 서비스 종료 때 부담이 크다 |
| **B (추천)** | **각 묶음의 구매일부터 180일** | 계좌이체 취소 가능 기간(180일)과 맞춘다 — 유효기간 안에는 토스 취소로 환불할 수 있다. 카드는 1년까지 취소가 보통 가능하다 |
| C | 각 묶음의 구매일부터 1년 | 카드는 대체로 가능하지만(1년을 넘으면 카드사 데이터 보관에 따라 안 될 수 있음), **계좌이체 · 휴대폰으로 산 묶음은 후반에 토스로 취소할 수 없다** → 수동 송금이 필요 |
| D | 6개월 | B와 거의 같다 |

- 추천 B의 이유: 환불을 약속하는 기간 안에는 환불 수단이 항상 있게 한다. **휴대폰 결제는 결제한 달에만 취소할 수 있으므로**(T2) 열 거면 환불을 수동 송금으로 처리하거나 열지 않는 것을 권한다 — 실결제에서 어떤 결제수단을 열지는 운영자가 정한다.
- 만료 뒤 처리(제안): 질문으로는 쓸 수 없게 하되 **소멸시키지 않고 환불 신청을 받는다.** 소멸시켜도 되는지는 F7을 보면 확신할 수 없으므로 전문가 확인 항목이다.
- 만료 안내: 묶음 만료 30일 전부터 MY와 채팅방 입력창에 "남은 질문 N개 · 사용 기한 ○○(가장 빨리 끝나는 묶음 기준)" 표시.
- **구현에 필요한 것**: 질문 사용 · 남은 질문 계산에서 만료된 묶음을 빼는 규칙 + 만료 표시 → **아직 구현하지 않았다**(기간이 정해진 뒤 새 DB 변경 17번 또는 코드로).

### P3. 쓰지 않은 질문과 "묶음 구조"에 대한 고지

결제 화면과 약관에 다음을 구매 전에 보여 준다(F3의 표시 취지):

- "질문 3개 묶음 2,500원(부가세 포함) · 1개씩 결제할 수 없어요"
- "구매하면 적어 둔 질문에 바로 답하고 1개가 쓰여요. 남은 2개는 이어서 쓸 수 있어요"
- "쓰지 않은 질문은 환불할 수 있어요 · 사용 기한 ○○(P2)"
- 무료 질문이 먼저 있어 써 본 뒤 구매할 수 있다는 것

지금 결제 화면은 첫 두 줄까지 보이고, 환불 · 유효기간 문구는 정책 확정 전이라 "아직 확정 전"으로만 적혀 있다.

### P4. 탈퇴 — "무기한 막힘"을 최종안으로 두지 않는다 (설계만 · 미구현)

현재 임시 처리(막음)는 회원이 질문을 다 쓸 때까지 탈퇴 권리를 막는 구조라 **최종안으로 두면 안 된다.** 제안 흐름:

1. 탈퇴 화면이 "쓰지 않은 질문 N개가 있어요"와 **환불 예정액**(2장의 누적 방식)을 보여 준다.
2. 회원이 **셋 중 하나**를 고른다.
   - **환불을 신청하고 탈퇴** — 신청이 접수되면 **환불 접수번호(예: `RF-20261015-AB12`)와 처리 안내**(처리 기한 · 환불 수단 · 문의 채널)를 화면에 보여 주고(이메일 발송은 만들지 않는다 — 개인정보를 늘리지 않는다) 탈퇴를 진행한다. 환불은 운영자가 토스 관리자에서 실행하고(미유는 환불을 실행하지 않는다) 미유가 결제사 기록으로 맞춘다. 개인정보는 바로 지우고 주문 · 결제 · 환불 신청 기록만 이름 없이 남긴다. 탈퇴 뒤에도 접수번호로 문의할 수 있다.
   - **환불받지 않고 포기하고 탈퇴** — "쓰지 않은 질문 N개는 사라지고 돌려받지 못한다"를 읽고 직접 확인 문구를 적으면 진행하고 포기에 동의한 사실을 기록에 남긴다. (이 선택지를 둬도 되는지 자체가 전문가 확인 항목이다 — 소비자의 환불 권리를 포기시키는 구조로 읽힐 수 있다.)
   - **탈퇴하지 않음.**
3. 환불 신청이 접수됐지만 운영자가 처리하기 전에 회원이 탈퇴해도 환불은 이어진다(주문 · 결제 기록은 5년 남으므로 F6 방향과 맞다).

- **구현에 필요한 것**: 환불 신청 접수 기록(접수번호 · 주문 · 신청 시각 · 처리 상태 — 질문 · 대화 내용 없음) + 탈퇴 함수가 "남은 질문이 있으면 막음" 대신 "환불 신청이 접수됐거나 포기 동의가 기록됐으면 허용"으로 바뀜 → **새 DB 변경(17번)**. **아직 구현하지 않았다.**
- **그때까지의 임시 처리**: 탈퇴를 막는 문구는 "임시"라고 밝혀 두었고, 환불은 문의 채널(카카오톡 채널 "미유톡")로 신청받아 운영자가 처리한다.

### P5. 서비스 종료 · 중단 — **제안이며 외부 검토 전**

- 종료 **30일 전**(제안)에 사이트와 MY에 공지하고, 종료 전까지 환불 신청을 받는다. **공지 기간이 적절한지 · 법적으로 요구되는 기간이 있는지는 전문가 확인 항목이다.**
- 종료 시점에 남은 질문이 있는 회원은 2장과 같은 계산으로 환불한다(운영자가 토스에서 처리).
- **토스 취소 가능 기간(T2)을 넘긴 결제**(휴대폰 당월 · 계좌이체 180일 · 카드 1년 이상)는 토스 취소가 안 될 수 있어 **다른 방법(계좌 송금 등)**이 필요하다. 이 경우 환불 계좌를 받아야 하는데 개인정보 · 보관 방식은 정해지지 않았다.

### P6. 오류 · 중복 결제

- 같은 묶음을 두 번 결제한 경우: 중복분 전액 환불(`runbook.md` 절차 그대로).
- 질문이 안 들어간 경우: "결제사 확인 후 질문 넣기"(15번)로 넣거나 환불.
- 결제 시작을 두 번 눌러도 결제할 수 있는 대기 주문은 하나만 남고, 같은 승인 주소를 여러 번 열어도 질문은 한 번만 들어간다(시험함).
- 결제창을 인증만 마치고 닫은 경우: MY의 주문 화면 · 정기 점검이 결제사 기록으로 결제 완료를 맞춘다(가짜 결제로 시험함, 실제 결제로는 아직).

### P7. 고객 문의 채널 — **정해졌다(2026-10-16): 카카오톡 채널 "미유톡" CS 전용 상담톡**

환불 신청 · 문의의 입구다. 운영자가 알려 준 채널(`http://pf.kakao.com/_xjxnqmX/chat`, 카카오톡에서 "미유톡"을 검색해도 나온다)을 `lib/config/business.ts`의 `SUPPORT_CONTACT`에 넣었고 사이트 하단 · 약관 9조 · 탈퇴 막힘 안내에 보인다. 이메일과 응대 시간은 정해지지 않아 비워 두었다(지어내지 않는다).

- **이 채널로 환불을 받을 때 정해야 할 것(운영자)**: 환불 신청에 필요한 정보(주문번호 · 결제 시각 · 닉네임 — 이름 · 생년월일 · 질문 내용은 받지 않는다) · 응대 시간 · 처리 기한(영업일 ○일) · 상담 기록의 보관 기간(카카오 채널 관리자 기능이라 미유 DB와 별개이며 개인정보 처리방침에 반영 필요).
- 이 채널로 오는 환불 신청은 **접수번호를 부여하는 기능이 아직 없다**(R2 미구현) — 그때까지는 주문번호가 접수 기준이다.

## 5. 약관 초안 문구 (미반영 — 결정 후 `app/terms/page.tsx` · 결제 화면에 넣는다)

> **유료 질문**: 무료 질문을 모두 쓴 뒤에는 질문 3개를 묶어서 결제하고 이어서 물을 수 있습니다(1개씩 결제하는 방법은 없습니다). 가격은 질문 3개에 2,500원(부가세 포함)입니다. 결제한 질문은 질문을 보낼 때마다 1개씩 쓰이고, 답을 받지 못한 질문은 쓰이지 않습니다.
> **사용 기한**: 결제한 질문은 **각 묶음을 결제한 날부터 ○일(제안: 180일)** 동안 사용할 수 있으며, 가장 먼저 결제한 묶음부터 쓰입니다. 기한이 지나면 질문으로는 사용할 수 없으며, 쓰지 않은 질문은 환불을 신청할 수 있습니다.
> **환불**: 쓰지 않은 질문은 사용 기한 안에 언제든 환불을 신청할 수 있습니다. 환불 금액은 한 묶음(2,500원)당 **누적 계산**으로 정하며(질문 1개 834원 · 2개 1,667원 · 3개 2,500원, 원 미만 올림) 한 묶음에서 환불받는 총액은 결제 금액을 넘지 않습니다. 이미 답을 받은 질문은 환불하지 않습니다. 환불은 결제수단으로 돌려드리며 신청 후 영업일 기준 ○일 안에 처리합니다(카드는 카드사 사정으로 3~4영업일이 더 걸릴 수 있습니다).
> **회원 탈퇴**: 쓰지 않은 질문이 있는 경우 탈퇴 화면에서 환불을 신청하고 탈퇴할 수 있으며, 환불 접수번호와 처리 안내를 드립니다. 주문 · 결제 · 환불 기록은 관련 법령에 따라 이름을 알 수 없는 상태로 보관합니다.
> **서비스 종료**: 서비스를 종료하는 경우 종료 ○일 전에 공지하고, 쓰지 않은 질문은 위와 같은 방법으로 환불합니다. (제안 문구 — 외부 검토 전)
> **문의**: 카카오톡 채널 "미유톡" 상담톡(운영자가 정한 채널, 응대 시간 · 처리 기한은 ○).

(괄호 ○는 운영자 결정 항목. "소멸" · "환불 불가" 같은 표현은 전문가 확인 전에는 넣지 않는다. 이 문구는 제안이며 법적으로 확정된 것이 아니다.)
