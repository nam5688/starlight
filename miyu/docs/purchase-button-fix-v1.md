# "심층 리포트 받기 · 9,900원" 버튼 무반응 — 원인 · 수정 · 확인 범위 (2026-10-20)

사용자 보고: 로그인한 뒤 상담방 · 구매 안내 화면의 "심층 리포트 받기 · 9,900원" 버튼을 모바일에서 눌러도 아무 반응이 없다. 호출 0 · 실결제 없음 · 외부 설정 변경 없음 · 결제 가드 그대로.

## 1. 원인 — 한 가지가 아니라 세 가지가 겹쳐 있었다 (로컬에서 모바일 크기 브라우저로 재현)

| 구분 | 예전 동작 | 결과 |
| --- | --- | --- |
| **스크롤 앵커(실제 원인)** | 상담방 · 구매 안내(`LockedRoom`) · 결과 화면 입구(`TalkEntry`)의 "받기" 버튼이 **다른 화면에서 같은 결과 화면의 `#r-purchase`로 가는 링크**였다 | 화면 이동은 되지만 모바일(소프트 내비게이션)에서 **구매 영역까지 스크롤되지 않고 맨 위에 머물렀다**(재현: 이동 뒤 `scrollY = 0`, 구매 영역은 화면 밖). 눌러도 아무 일도 없는 것처럼 보임 |
| **조용한 되돌림** | 결제를 시작하는 서버 동작은 막히면(결제 연결 전 · 새 구매 중지 · 로그인 풀림 · 이미 결제함 · 삭제한 기록 · 오류) **이유 없이 같은 결과 화면으로 되돌아갔다** | 막힌 이유가 어디에도 안 보임 |
| **폼 submit / 서버 액션 / disabled** | 폼 · 서버 동작 자체는 정상(결제 가드 · 소유자 확인 · 금액 확인은 서버가 한다). 버튼 `disabled`는 진행 중에만 걸리고 이유 표시가 없었다. 결제 화면의 토스 "결제하기"는 위젯이 준비되지 않으면 비활성이고 이유 안내가 없었다 | 진행 중 · 실패 · 준비 상태가 화면에 없음 |

SDK · 판매 조건은 원인이 아니었다: 결제 설정이 있는 환경에서는 정상 이동했고, 결제 설정이 없는 환경에서는 "결제 연결 전"으로 이유가 보인다(아래).

## 2. 수정

- `components/results/purchase-start-button.tsx`(새) — 구매를 시작하는 **폼 버튼**. 누르면 잠기고 "결제 화면을 준비하고 있어요…"가 보이며, 서버가 이동해도 된다고 확인하면 결제 화면으로 가고, 못 가면 **이유 + 결제가 시작되지 않았고 카드에서 금액이 빠져나가지 않았다는 말 + 이어 갈 링크**를 버튼 아래에 보인다(`role="status"`).
- `startPurchaseAction`(`app/results/[id]/actions.ts`) — 결제 가드(`saleGateCheck` 판매 중지 · 용량 · 예산) · 소유자 확인 · 서버 견적을 **그대로** 쓰고, 막힌 모든 경우에 조용한 redirect 대신 이유를 돌려준다. 이동(redirect)은 결제 주문이 만들어졌을 때 한 곳뿐이다. 결제 가드를 약화하거나 AI 설정을 바꾸지 않는다.
- `lib/commerce/purchase-start.ts` — 결과 분류와 문구(`login` · `payments-not-ready` · `sales-closed` · `already-paid` · `record-deleted` · `report-not-ready` · `options` · `not-found` · `error`).
- 상담방 잠금(`LockedRoom`) · 결과 화면 입구(`TalkEntry`) · 구매 영역(`PurchasePanel`)의 "받기" 버튼을 모두 이 버튼으로 바꿨다. `HashScroll`(새)은 `#r-purchase`로 직접 들어와도 구매 영역까지 한 번 내려가는 보조 장치다(손가락으로 스크롤하면 멈춘다).
- 결제 화면(`TossCheckout`) — "결제하기"를 눌렀는데 **20초 안에 결제 창으로 넘어가지 않으면** 이유를 화면에 알리고 버튼을 다시 열며(`PAY_NO_REDIRECT`) 운영 알림으로 단계를 보고한다. 불러오는 중 · 요청 중 · 오류 상태에 이유 한 줄을 보인다. **실제 토스 위젯에서 이 20초 장치가 필요한 상황이 생기는지는 확인하지 못했다.**
- 홈 · `/compat` · `/pair`의 "지금 이용 가능 / 준비 중"은 이제 **판매 스위치 + 풀이 AI 연결**을 함께 본다(`lib/compat/readiness.ts` · `server/compat-readiness.ts`). 판매는 열려 있어도 AI가 연결돼 있지 않으면 "준비 중"이고 이유("풀이를 쓰는 AI가 아직 연결되지 않아 지금은 받을 수 없어요. 결제는 시작되지 않고…")를 카드에 적는다. **AI를 켜거나 승인 값을 바꾸지 않았다.**

## 3. 확인한 것 (호출 0 · 로컬 가짜 환경)

- 모바일 크기(390×844, 터치) 브라우저 + 로컬 Postgres · 가상 회원 · 가짜 토스 키: 잠긴 방(결혼) · 결과 화면 구매 영역에서 버튼 → 진행 문구 → **결제 화면으로 이동**(주문 생성, 결제 없음).
- 결제 설정을 비운 환경으로 같은 두 버튼: **이동하지 않고** "결제가 아직 준비되지 않았어요. 결제는 시작되지 않았고 카드에서 금액이 빠져나가지 않았어요."가 그 자리에 보임(`data-reason="payments-not-ready"`).
- AI가 꺼진 환경의 홈 · `/pair`: 사주 궁합 · 리포트 궁합이 "준비 중" + AI 안내 문구, 간단 궁합은 "무료"로 열림.
- 단위 시험: `lib/commerce/purchase-start.test.ts` · `lib/compat/readiness.test.ts` · `server/purchase-button-ui.test.ts`(받기 버튼이 링크가 아니라 구매 시작 폼 버튼이고, 서버 동작이 가드를 쓰고 조용한 redirect가 없음).

## 4. 하지 못한 것 · 한계

- **실제 토스 위젯 · 실제 휴대폰 · 실제 결제 승인은 확인하지 못했다**(미통과). 위 모의 검사는 가짜 키로 결제 화면 앞까지다.
- 사용자가 본 "무반응"이 ①(받기 버튼) 한 곳이었는지 ②(토스 결제하기)도 포함했는지는 보고만으로는 가를 수 없다. ①은 재현해 고쳤고 ②는 안전장치만 더했다.
- 서버 오류가 결제 시작 단계에서 나면 "결제를 시작하지 못했어요" + 오류번호가 보인다. 오류의 실제 원인은 운영 기록의 오류번호로 확인한다.

## 5. 추가 확인 후 보완 (2026-10-20 운영자 증거: 배포본의 상담방 받기가 `#r-purchase` 앵커였다)

운영자가 본 화면은 이 수정이 배포되기 전 버전이었다(앵커 · 3문장 요약 · "기질 문항 응답 중 3개" 설명이 그대로). 같은 확인에서 두 가지를 더 찾아 고쳤다.

1. **앵커형 · 조용한 되돌림 버튼이 더 있었다**: 채팅방의 무료 질문 소진 안내창(리포트로 이어 보기 · 9,900원) · MY의 "전체 리포트 구매" · "새 리포트 받기 · 9,900원"(구매한 사람이 한 번 더 받는 폼, 막히면 조용히 되돌아갔다) → 모두 같은 구매 시작 버튼으로 바꿨다(`again` 지원). 가격이 적힌 버튼 아래에는 기본으로 **"누르면 결제 화면으로 이동해요. 이 버튼만으로는 결제되지 않아요."**를 적어, 앵커나 이동 버튼이 결제처럼 읽히지 않게 했다. 같은 화면의 `#compat-paid` 앵커는 "아래 사주 궁합 신청 칸으로 이동"으로 문구를 이동 표현으로 바꿨다. **남은 앵커**: 채팅 답장 칩의 "리포트로 이어 보기 · 9,900원"(구매 영역으로 가는 링크, 결제 아님) — 아래 보조 스크롤로 도착 위치까지 내려가는 것을 확인했다.
2. **저장된 옛 결과에는 옛 문장이 남아 있었다**: 무료 해석 문단(신중 · 익숙함 · 확인한다 3문장)의 글은 **저장할 때 요약(`summary.insight.text`)에 박혀 있어**, 문장을 고쳐도 이미 저장된 결과는 옛 문장 그대로였다. 화면(결과 화면 · 상담방 모델)만 저장된 응답에서 지금의 문장으로 다시 만든다(`withCurrentInsight`, 저장된 데이터는 바꾸지 않는다). 이전 점검 때 새로 저장한 결과만 보고 놓친 부분이다.

확인(모바일 크기 에뮬레이션 · 로컬 가짜 환경, 실제 휴대폰 아님): ① 옛 문장을 저장해 둔 결과가 옛 문장 없이 지금의 문장과 고객용 한 줄로 보인다 ② MY의 구매 버튼 → 결제 화면 이동 ③ `#r-purchase`로 직접 들어오기 · 앱 안에서 이동 둘 다 구매 영역이 화면 안에 들어온다(`top = 80px`). **PC에서 됐다는 것을 모바일 통과로 보지 않는다** — 에뮬레이션도 실제 휴대폰이 아니며 실제 휴대폰 · 실제 토스 위젯은 여전히 미확인이다.

사주에서 읽으면 블록의 일간 · 오행 설명("임수(壬) · 수 기운…")은 이번에 바꾸지 않았다 — 고정 문구(`plain.ts` 등)의 생활 말 정리는 별도 범위이고 운영자 확인 항목이다.
