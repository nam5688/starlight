# ME:U(미유) 상업 출시 점검표

목표: 실제 고객이 카카오로 가입하고, 결제하고, 구매한 사주 · 심리 통합 리포트(AI 해석)를 받는 상업용 서비스. 이 문서가 **유일한 출시 점검표**다 — 안정성 · 비용 · 성능 · 디자인 · 측정 · 운영을 한곳에서 본다.

- 점검일: 2026-10-12 (6차 갱신 — 회원 탈퇴 · 알림 종류 · 글꼴 흔들림 · 자체 문항 설계 · AI 품질 확인 계획 · 무료/유료 샘플 반영)
- **테스트 개수로 출시 가능 여부를 판단하지 않는다.** 아래 "검증됨"은 *어느 환경에서 어떤 상황을 확인했는지*가 적힌 것만 뜻하고, 환경에 적히지 않은 것은 검증된 것이 아니다.
- 공개 배포와 실결제는 아직 하지 않았고, **운영자 확인 전에 진행하지 않는다.**
- **첫 출시 상품은 개인 통합 리포트 하나에 집중한다.** 추가 카테고리 · 커플 비교 · 미유피플 · 제휴는 후속 목록에 보관한다 (`roadmap.md`).
- **지금 막고 있는 것은 "결제·로그인 코드"가 아니라 판매할 내용의 품질과 실제 환경 확인이다.** 다만 코드로 해야 할 일도 남아 있다 — 아래 2장 끝의 "출시 전 남은 개발 작업".

## 1. 읽는 법

| 표기 | 뜻 |

| **구현됨** | 코드가 있고 단위 테스트 또는 화면에서 동작을 확인했다 |
| **검증됨 (환경)** | 아래 환경 중 어디에서, 어떤 상황으로 확인했는지 적었다 |

### 검증 환경

| 환경 | 구성 | 이 환경에서 확인한 것의 의미 |
| --- | --- | --- |
| **개발 클라우드** (Linux · Chromium) | 로컬 Postgres 16 + Supabase Auth + PostgREST, **가짜 카카오 · 가짜 토스 API · 가짜 AI 서버** | 우리 코드의 규칙이 맞게 동작한다. **실제 서비스가 같은 값을 돌려준다는 뜻은 아니다** |
| **운영자 PC** (Windows · 실제 서비스) | 실제 Supabase 프로젝트 · 실제 카카오 로그인 · 토스 공용 예제 키(테스트 결제) | 실제 외부 서비스와 연결된 최소 흐름 (아래 "운영자가 직접 확인한 것") |
| **아직 없음** | 실제 호스팅(Vercel) · 실제 휴대폰(카카오톡 인앱 · iPhone Safari) · 실제 AI 제공사 · 실제 결제(live) | 해당 항목은 모두 미완료로 적었다 |

**운영자가 직접 확인한 것 (운영자 PC, 2026-10-12):** 실제 Supabase 연결 · 실제 카카오 로그인(이메일 없이) · 필수 약관 동의 · 검사 결과 저장 · 로그아웃 후 같은 계정 재로그인으로 같은 결과 확인 · 토스 테스트 결제창 표시 · 테스트 결제 후 리포트 화면 표시. DB 변경은 1 · 2번까지 적용을 확인했다 (3~9번은 아직 — `setup-guide.md`).
**확인하지 못한 것:** 테스트 결제의 서버 승인 기록 · 주문 DB 상태 · 리포트 저장 상태(MY → 결제내역 → 주문 상세에서 확인 예정). 그때 본 리포트는 개발용 임시 내용이다.

## 2. 출시 전 필수 — 하나라도 막히면 공개 판매하지 않는다

| 항목 | 구현됨 | 검증됨 (환경 · 상황) | 미완료 · 위험 |
| --- | --- | --- | --- |
| **결제 정합성** | 금액은 서버 설정값으로 주문 생성, 승인 전 주문 소유자 · 금액 · 상태 확인, 주소의 금액 위조 거부, 승인 요청 멱등키, 같은 검사에 결제 완료 1건 · 대기 1건(DB 고유 조건), 결제사 기록으로 주문을 맞추는 대조(`reconcile`: 화면을 열 때 · 정기 점검), 이중 승인 · 금액 불일치는 자동으로 고치지 않고 운영자에게 알림 | 개발 클라우드 + 가짜 토스: 정상 결제 · 취소 · 카드 거절 · 결제사 응답 유실(결제사는 승인, 우리는 응답 못 받음) · 승인 후 우리 저장 실패 · 결제사 조회 장애 · 두 탭 동시 · 결제창에서 돌아오지 않음 · 중복 승인 · 이탈 후 60분 정리 · 같은 주문 반복 승인 요청. 성공 주소로 이동했다는 이유로 결제 성공 처리하지 않음 | **실제 토스 서버에서의 승인 · 조회 응답 형식은 미확인** (가짜 API가 문서 기준으로 만든 것). 운영자 테스트 결제의 서버 승인 기록 미확인. 웹훅 등록(공개 주소 필요) · 결제사 계약 · 실결제 심사 미완료. 환불은 미유가 실행하지 않고 운영자가 토스 관리자에서 한다(취소 후 미유가 "환불됨"으로 맞춤) |
| **회원별 접근 차단** | 서버 소유자 확인 + DB 접근 정책(RLS, 본인 행 조회만, 직접 쓰기 거부), 유료 내용은 구매 확인 전 브라우저로 보내지 않음, 동의 전 저장 · 결제 차단, 관리자 화면은 `ADMIN_USER_IDS`에 있는 회원만 | 개발 클라우드 + 로컬 DB: 다른 회원이 결과 · 결제 · 리포트 주소를 알아도 '찾을 수 없음', 로그인 전 접근 불가, 일반 회원은 관리자 화면 · 지표 화면 접근 불가, DB에 직접 쓰기 시도 거부(DB 테스트 22) | **실제 Supabase(호스팅)에서 같은 정책이 동작하는지 미확인** — 운영자는 로그인 · 저장 · 재로그인만 확인했다. 공개 전에 계정 2개로 서로의 결과 주소를 열어 보는 확인이 필요 |
| **리포트 생성 실패 복구** | 결제 확인 직후 대기열에만 올리고 응답 뒤 백그라운드 생성, 완성되면 결과 화면 자동 표시, 서버가 멈춰 있으면 이어받기, 실패 시 결제는 그대로 두고 "다시 만들기"(고객 5회) · 운영자 "다시 만들기"(상한 별개), 정기 점검이 멈춘 리포트를 이어서 생성, 30분 넘으면 지연 안내(환불 문의 가능), 생성 시간 제한 240초(초과는 완성으로 저장하지 않음), 이미 결제한 고객의 리포트는 어떤 경우에도 취소하지 않음 | 개발 클라우드 + 가짜 AI: 지연 · 일시 오류 · 형식 오류(고쳐 쓰기) · 시간 초과 · 서버 재시작 중 대기 · 고객이 열지 않아도 정기 점검이 이어서 생성. 완성 리포트는 DB에서 수정 불가, 열 때마다 같은 저장본 | **실제 AI 제공사는 연결하지 않았다** → 실제 응답 지연 · 오류 형태 · 형식 준수율 미확인. 호스팅의 백그라운드 작업 시간 한도 미확인(Vercel 함수 제한). 5회 실패 후 환불 판단은 운영자가 수동으로 한다 |
| **AI 비용 통제** | 호출마다 사용 기록(`ai_usage`: 토큰 · 비용 추정 · 결과), 동시 생성 한도, 대기 한도를 넘으면 **새 구매만** 멈춤(두 단계: 결제 시작 때 · 결제사 승인 직전 더 넉넉한 기준 — 승인 요청을 하지 않으면 청구되지 않음), 하루 예산, 호출 시간 제한 · 취소 신호, 재시도 대기 60초, 검사 하루 10회 제한 | 개발 클라우드 + 가짜 AI(느린 응답): 대기가 밀리면 새 구매자는 결제를 시작하지 못하고 '청구되지 않음' 안내, 이미 결제한 고객은 결제되고 순서 대기 후 모두 완성, 승인 기준까지 차면 카드에서 돈이 빠지지 않음, 사용 기록 · 단가 설정 시 비용 합계, 1,000행 제한을 넘는 합계 | **실제 제공사 단가 · 한도 값은 정하지 않았다**(`AI_*` 환경변수, 제공사 선택 후). 리포트 한 건의 실제 토큰 · 비용은 실측 전. 기본 한도(동시 3 · 대기 10)는 첫 출시 규모 가정이며 실제 응답 시간 측정 뒤 조정 필요 |
| **개인정보 보호** | 비밀키는 서버 환경변수만, 서버 로그 · 운영 기록에서 키 · 토큰 · 이메일 · 전화번호 가림, 고객 고민 · 대화는 어떤 기록에도 넣지 않음, 분석(방문 단계)에는 이름 · 생년월일 · 응답 · 고민 없음(익명 번호 + 출처만), 추적 거부 신호(DNT · GPC) 존중, 비공개 화면은 `no-store` + 검색 제외 헤더, 나를 더 반영하기는 본인만 보기 · 고치기 · 지우기, AI에는 이름 · 생년월일 원문 미전송 | 개발 클라우드: 서버 로그 · 운영 기록에 키 · 토큰이 남지 않음, 방문 기록 열 전체에 개인정보 없음, 비공개 화면 헤더, robots · 사이트맵에서 개인 · 결제 · 관리자 주소 제외. **회원 탈퇴**: 검사 · 리포트 · 고민 · 닉네임 삭제와 주문 · 결제 기록 분리 보관, 진행 중인 결제 · 생성이면 막음, 반복 호출 안전, 다른 회원 영향 없음, 탈퇴 후 같은 카카오로 재가입하면 새 계정 (단위 · DB · 브라우저 8개). **실제 Supabase Auth의 탈퇴 처리는 호스팅 환경에서 확인하지 않았다**. (검색 제외는 비공개 장치가 아니다 — 접근 제어는 로그인 확인 + RLS) | **약관 · 개인정보 처리방침은 초안.** 확정 전에 ① 나를 더 반영하기 입력(고민 · 대화 일부) ② AI 해석 서비스와 국외 이전 가능성 ③ 분석용 익명 쿠키(`meu_aid`) ④ 사업자 · 통신판매업 정보 ⑤ 보관 기간 · 위탁 업체 · 환불 기준을 넣고 `TERMS_VERSION`을 올려 재동의를 받아야 한다. **회원 탈퇴는 구현됐지만(아래 "개인정보 보호" 검증 참고) 정책은 초안이다** — 보관 기간 · 보관 항목 · 만료 기록 파기 작업은 [`withdrawal-policy.md`](./withdrawal-policy.md)에서 정해야 한다. 법률 검토 전 |
| **실제 리포트 품질** | 만세력 엔진(manseryeok, 독립 교차 검증), 근거 목록 안에서만 쓰고 문단마다 근거 ID, 형식 · 표현 검사, 사주 용어 풀이, 무료/유료 범위 표(`REPORT_SCOPE`)와 미리보기 일관성 테스트 | 개발 클라우드: 원국 계산 교차 검증, 모의 모델 문장의 형식 · 근거 ID · 금지 표현 검사 통과, 미리보기의 잠금 질문은 구매 리포트에 실제 답이 있음 | **가장 큰 미완료.** ① 해석 규칙 문구는 모두 **초안 · 전문가 검토 전**(`saju-rules-0.1-draft`) ② 검사 문항은 모두 **개발용 예시**(`dev-example`) — 실제 검사 도구 · 이용 허락 확정 전에는 운영 결과를 낼 수 없다 ③ **실제 AI 문장 품질 미확인**(제공사 선택 · 승인 후 같은 근거로 후보 비교 필요) ④ 지금 구매자가 받는 것은 개발용 임시 리포트다 |
| **백업 · 복구** | `docs/runbook.md`에 논리 백업(`pg_dump`) → 복구 절차 | 개발 클라우드 로컬 DB: 백업 → 복구 후 모든 표의 행 수 일치, 완성 리포트 내용 해시 일치, 고치기 방지 트리거 복원 | **Supabase 호스팅의 자동 백업 · 보관 기간 · 시점 복구(PITR)는 요금제별로 다르며 확인하지 않았다.** 실제 프로젝트에서의 복구 리허설 미실시 |
| **공개 배포 · 실결제** | 실결제는 `PAYMENTS_LIVE_MODE=true` + live 키가 있어야만 켜짐(테스트 키만 허용하는 장치) | 개발 클라우드: 장치 동작 | **운영자 승인 전 하지 않는다.** 호스팅 · 도메인 · 실제 주소로 Supabase · 카카오 · 토스 설정 변경, 결제사 계약 · 심사 |

### 출시 전 남은 개발 작업 (코드로 해야 하는 일)

"운영자 결정만 기다리는 상태"가 아니다. 아래는 개발이 필요한 일이고, 일부는 결정 · 승인 · 환경 연결 뒤에 시작할 수 있다.

| 작업 | 왜 필요한가 | 시작 조건 |
| --- | --- | --- |
| 실제 AI 제공사 연결 코드(`AI_PROVIDER` 선택지)와 비교 실행기 | 지금은 모의 모델만 있다 → 유료 리포트 품질을 확인할 수 없다 | **예산 승인** ([`ai-quality-comparison-plan.md`](./ai-quality-comparison-plan.md) 6장) |

## 5. 성능 측정 기록 (2026-10-12, 글꼴 변경 후 다시 측정)

**조건:** 운영 빌드(`next start`, 프로세스 1개) · Chromium 헤드리스 · 390×844 DPR2 · CPU 4배 느리게 · 서버 · 로컬 DB · 측정 도구가 **같은 기계** · 첫 방문은 캐시 없이 5회 중앙값, 재방문은 3회 중앙값. 절대 수치가 아니라 화면 사이의 상대 비교와 병목 확인용이다. 측정 스크립트는 개발 환경에만 있고 저장소에는 넣지 않았다.

| 화면 | 일반 LTE 첫 방문 LCP | 느린 4G 첫 방문 LCP | 첫 방문 CLS (두 조건 모두) | 첫 방문 전송량 |
| --- | --- | --- | --- | --- |
| 홈 | 0.78s | 1.21s | **0.000** (이전 느린 4G 0.166) | 약 375KB |
| 검사 시작 | 0.57s | 0.96s | 0.000 | 약 361KB |
| 리포트 예시 | 1.00s | 1.52s | 0.000 | 약 378KB |
| 무료 결과(로그인) | 0.92s | 1.40s | 0.000 | 약 338KB |
| 유료 리포트(로그인) | 1.02s | 1.57s | 0.000 | 약 348KB |
| MY(로그인) | 0.52s | 0.98s | 0.000 (이전 느린 4G 0.118) | 약 342KB |

- 재방문(캐시 있음)은 모든 화면에서 LCP 0.2~0.7초, CLS 0.
- **글꼴 흔들림 해결 방식과 대가:** 핵심 글꼴(115KB)을 첫 화면과 함께 미리 받고, 늦게 도착하면 그 화면은 시스템 글꼴 그대로 두어 글자가 바뀌며 화면이 움직이지 않게 했다(`font-display: optional`). 대가: 느린 회선의 **첫 방문 첫 화면은 시스템 글꼴**로 보일 수 있고, 글꼴이 도착한 뒤 다음 화면부터 미유 글꼴로 보인다 (빠른 회선에서는 첫 화면부터 미유 글꼴). 측정 기계의 시스템 글꼴은 실제 휴대폰(Android · iPhone · Windows)과 달라, 실제 기기에서 첫 화면의 모양은 **확인하지 않았다**.
- **동시 접속 부하**(같은 기계, 한 프로세스, 오류 0건): 정적 화면(홈 · 리포트 예시)은 초당 약 350~620건. 로그인 + DB 화면(무료 결과 · 유료 리포트 · MY)은 초당 약 20~29건에서 포화되고, 동시 50개 요청이면 p95 약 3초, 동시 150개 요청이면 p95 약 10~12초. 부하 후 서버 메모리 약 700MB.
  - **이 숫자는 "동시에 쓸 수 있는 사람 수"가 아니다.** "초당 처리한 화면 요청 수"이고, 부하 도구는 쉬지 않고 요청을 보냈다. 실제 사람은 화면을 연 뒤 읽고 생각하는 시간이 길어서 같은 처리량으로 더 많은 사람이 동시에 접속해 있을 수 있다. 하지만 실제로 몇 명을 받을 수 있는지는 **배포 환경(서버 수 · 성능 · DB 요금제)과 사용자 행동(화면 이동 빈도)에 달려 있어, 호스팅에서 측정하기 전에는 사람 수로 말하지 않는다.**
- 유료 리포트 화면은 DOM이 매우 길다(세로 약 14,000 CSS px) — 모바일에서는 목차로 이동하게 했다. 리포트가 길어질수록 첫 표시 속도 · 스크롤 성능을 다시 본다.
- **미실시:** 호스팅(CDN · 서버리스) 환경, 실제 기기 · 실제 회선, 여러 서버 인스턴스.

| 5 | 해석 규칙 · 새 문항 · 개인 종합 리포트 | 근거 규칙 초안 v0 · 리포트 화면 완료 / 새 문항 · 12유형 설계 | — | 운영자 확인 → 문항 확정, 규칙 전문가 검토 |
| 6 | AI 리포트 생성 + 비용 통제 | **완료 (모의 모델)** | 안 함 | AI 제공사 · 모델 · 비용 한도 **승인** 후 실제 제공사 구현체 추가 → 같은 근거로 후보 비교 생성 |
| 7 | 운영 도구 (관리자 · 알림 · 정기 점검 · 지표) | 완료 | 안 함 | **관리자 · 텔레그램은 지금 테스트 환경에서 미리 연결해 확인할 수 있다** ([`update-guide.md`](./update-guide.md) 4장). cron은 호스팅 때 |
| 8 | 탈퇴 · 약관 확정본 | 탈퇴 **구현됨(정책 초안)** / 약관 초안 | — | 사업자 정보 · 보관 기간 · 환불 기준 결정, 법률 검토 ([`withdrawal-policy.md`](./withdrawal-policy.md)) |
| 9 | 공개 배포 | 안내만 있음 | 안 함 | **운영자 승인** 후. 호스팅 · 도메인, 실제 주소로 Supabase · 카카오 · 토스 설정 변경, 백업 확인 |
| 10 | 실제 유료 판매 | 실결제 차단 장치만 있음 | 안 함 | 결제사 계약 · 심사 완료, **운영자 승인** 후 live 키 · `PAYMENTS_LIVE_MODE=true` |

결제 성공 → 구매한 리포트 제공까지 이어져야 출시할 수 있으므로, 5 · 6번(해석 · AI 생성)은 9번(공개 배포) 전에 끝낸다. 지금 테스트 결제로 본 리포트는 개발용 임시 내용이며 상업 출시 완료가 아니다.

## 7. 운영자 결정 — 한꺼번에 하지 않아도 된다

**지금 필요한 것 (다음 단계가 이 둘에 달려 있다)**
1. **AI 비교 생성 예산 승인** — 총 1만 원 한도, 후보 2개 ([`ai-quality-comparison-plan.md`](./ai-quality-comparison-plan.md)).
2. **자체 문항 초안 검토** ([`assessment-design-v1.md`](./assessment-design-v1.md)).

**추천 기본값으로 진행하면 되는 것** ([`operator-decisions.md`](./operator-decisions.md)): 12유형(시범 응답 후 확정) · 자시 기준 · 출생지 보정 · 대운 계산 기준(첫 출시에 "큰 흐름"을 넣을지에 따라).

**공개 전에 필요한 것:** 약관 · 처리방침 확정(사업자 정보 · 보관 기간 · 위탁 · 국외 이전 · 환불 기준), 탈퇴 정책 8가지([`withdrawal-policy.md`](./withdrawal-policy.md) 2장), Supabase 요금제의 백업 주기 확인, 정기 점검(cron) 실행 위치, 카테고리 상품 가격 · 출시 순서(첫 출시 뒤), **공개 배포 · 실결제 전환 시점**(운영자 확인 전 진행하지 않음).
