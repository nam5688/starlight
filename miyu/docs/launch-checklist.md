# ME:U(미유) 상업 출시 점검표

목표: 실제 고객이 카카오로 가입하고, 결제하고, 구매한 사주 · 심리 통합 리포트(AI 해석)를 받는 상업용 서비스.

- 점검일: 2026-10-12 (코드 기준 커밋 `c24561f`)
- **"테스트 통과"와 "실제 연동 완료"는 다르다.** 테스트 통과는 클라우드 개발 환경에서 가짜 카카오 · 가짜 토스 API · 로컬 DB로 확인했다는 뜻이다. 실제 Supabase · 카카오 · 토스 · AI와 연결해 확인한 항목은 아직 없다.
- 상태 표기: **완료**(구현 + 테스트 통과) · **부분** · **미구현** · **결정 필요**(운영자 선택 · 승인이 있어야 진행)

## 1. 핵심 요구사항

| 요구사항 | 상태 | 근거 · 부족한 점 | 실제 연동 |
| --- | --- | --- | --- |
| 실제 AI 연결 | **미구현** | 지금 리포트는 점수와 임시 규칙으로 문장을 조합하는 개발용 생성기(`lib/report/generate-dev-report.ts`, `server/services.ts`의 `reportGenerator`). `AI_API_KEY`는 아직 어디에서도 쓰지 않는다. AI 제공사 · 모델 · 비용 한도는 **결정 필요** | 안 함 |
| └ 사주 원국 계산 | **미구현** | `lib/saju/engine.ts`가 항상 "연결 전". AI가 원국을 지어내지 않게 엔진 결과만 쓰는 구조는 준비됨. 엔진 선택 · 검수 필요(`product-spec.md` 6장) | — |
| └ 검사 문항 | **결정 필요** | 모든 문항이 개발용 예시(`dev-example`). 실제 검사 도구와 이용 허락(MBTI · ECR-R 등) 확정 전에는 운영 결과를 낼 수 없다 | — |
| 서버에서의 결제 검증 | **완료** | 금액은 서버 설정값으로 주문 생성, 승인 전 주문 소유자 · 금액 · 상태 확인(`lib/services/order-service.ts` `confirmPayment`), 주소의 금액 위조 거부, 서버 승인 후에만 구매 권한, `PAYMENTS_LIVE_MODE=true`가 아니면 테스트 키만 허용 | 안 함 (가짜 토스 API로만 확인) |
| 결제 중복 처리 방지 | **완료** | 같은 검사에 결제 완료 주문 1건 · 대기 주문 1건만(DB 고유 조건), 승인 요청 멱등키, 같은 결제키로 다시 오면 그대로 완료, 이미 처리된 결제는 결제사 재조회, 웹훅 반복 수신에도 같은 결과 | 안 함 |
| 결제 후 리포트 생성 실패 복구 | **부분** | 결제 상태와 리포트 상태 분리, 실패하면 "리포트 다시 만들기"(최대 5회), 생성 중 2분 넘게 멈추면 다시 시도 가능, 다시 결제하라고 하지 않음 — 완료. **부족:** 생성이 결제 승인 요청 안에서 끝날 때까지 기다리는 구조(`app/payments/actions.ts`). AI는 수십 초 걸릴 수 있어 시간 초과 위험 → 백그라운드 생성 + "준비 중" 화면 자동 갱신 필요. 5회 실패 후 운영자 알림 · 환불 처리 화면 없음 | 안 함 |
| 구매 결과 재열람 | **완료** | 완성된 리포트는 DB에서 수정 불가, 열 때마다 저장된 같은 버전 표시, 새로고침 · 로그아웃 후 같은 카카오 계정 재로그인 시 MY와 결과 화면에서 확인(브라우저 검사) | 안 함 |
| 회원별 접근 제한 | **완료** | 서버 소유자 확인 + DB 접근 정책(RLS, 본인 행 조회만, 직접 쓰기 거부), 다른 회원의 결과 · 결제 주소 접근 시 '찾을 수 없음', 유료 내용은 구매 확인 전 브라우저로 보내지 않음, 동의 전 저장 · 결제 차단 | 안 함 |

## 2. 출시 전에 더 필요한 것

| 항목 | 상태 | 메모 |
| --- | --- | --- |
| 관리자 화면 (주문 · 생성 실패 · 재처리 · 환불 요청) | 미구현 | 실제 환불 실행은 운영자 승인 |
| 환불 처리 | 부분 | 토스 관리자에서 취소하면 웹훅으로 주문을 "환불됨"으로 맞춤. 미유 안의 환불 요청 · 처리 흐름 없음 |
| 회원 탈퇴 | 미구현 | 약관 · 처리방침에는 적혀 있음. 거래 기록 보관 기간을 정한 뒤 구현 |
| 운영 알림 (텔레그램) | 미구현 | 개인정보 없이, 실패해도 결제 · 리포트에 영향 없게 |
| 약관 · 개인정보 처리방침 확정본 | 부분 | 지금은 초안. 사업자 · 통신판매업 정보, 보관 기간, 위탁 업체, 환불 기준 확정 필요 |
| 결제사 웹훅 등록 | 대기 | 공개 주소가 생긴 뒤 |
| 카카오 비즈 앱 전환 | 결정 필요 | 이메일 동의 항목 때문에 필요할 수 있음 |
| 첫 가입 쿠폰 | 미구현 | 손익 확인 후 (`business-plan.md` 10장) |

## 3. 연동 순서와 현재 위치

| 순서 | 단계 | 코드 | 실제 연동 | 진행 조건 |
| --- | --- | --- | --- | --- |
| 1 | Supabase (회원 · 결과 DB) | 준비됨 | **진행 중** — 프로젝트 생성 · 키 입력 | 운영자 키 입력 → `/setup` "연결됨" → SQL 2개 실행 |
| 2 | 카카오 로그인 | 준비됨 (가짜 카카오로 테스트 통과) | 안 함 | 카카오 앱 생성 · Supabase 설정 |
| 3 | 토스페이먼츠 테스트 결제 | 준비됨 (가짜 토스 API로 테스트 통과) | 안 함 | 테스트 키 입력 |
| 4 | AI 리포트 생성 + 백그라운드 생성 | 미구현 | 안 함 | AI 제공사 · 비용 한도 **승인** |
| 5 | 사주 엔진 · 검사 도구 확정 | 미구현 | — | 엔진 검수, 이용 허락 |
| 6 | 관리자 · 탈퇴 · 약관 확정본 · 알림 | 미구현 / 초안 | — | 사업자 정보 · 보관 기간 결정 |
| 7 | 공개 배포 | 안내만 있음 | 안 함 | **운영자 승인** 후. 호스팅 · 도메인 연결, 실제 주소로 Supabase · 카카오 · 토스 설정 변경 |
| 8 | 실제 유료 판매 | 실결제 차단 장치만 있음 | 안 함 | 결제사 계약 · 심사 완료, **운영자 승인** 후 live 키 · `PAYMENTS_LIVE_MODE=true` |

결제 성공 → 구매한 리포트 제공까지 이어져야 출시할 수 있으므로, 4번(AI 생성)은 7번(공개 배포) 전에 끝낸다.
