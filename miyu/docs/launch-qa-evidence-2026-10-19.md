# 출시 필수 QA — 로컬 실행 증거 (2026-10-19 · 비용 없는 시험만)

운영자 지시(2026-10-19): 궁합 2종 → 결제 · 환불 → 열람 · 공동 열람 권한 → 개인정보 · 약관 → 모바일 순서로, **비용 없는 로컬 · 가짜 서버 시험 · 정적 점검 · 기존 자료 검토부터 실제로 실행하고 증거를 기록**한다. 이 문서는 그 실행 기록이다. 목록과 기대 결과는 `launch-qa-readiness-v1.md`(항목 번호 Q-…), 스테이징 계획은 `staging-test-plan.md`.

> **이 문서의 "통과"는 로컬 임시 환경의 통과다.** 실제 Supabase · 토스 테스트 키 · 실제 AI · 실제 휴대폰에서는 아무것도 확인하지 않았다. 이 문서의 어느 줄도 출시 GO가 아니다. 미실행은 통과로 적지 않았다.

## 0. 먼저: 출시를 막는 오류가 있는지

- **이번 실행으로 새로 확인된 "출시를 막는" 오류는 없다.** 다만 아래 ③ · ⑤ · ⑥은 **실제 환경에서 아직 확인하지 못한 것**이라 출시 판단(스테이징 · 모바일)을 닫지 못한다.
- **고친 것 1건(보안 하드닝, 제품 코드)**: `/pair`(리포트 궁합) · `/compat/report`(사주 궁합 결과)는 로그인한 회원의 결과 화면인데 `next.config.ts`의 "저장 금지 + 검색 제외" 헤더 목록에 빠져 있었다. 실제로는 프레임워크 기본값이 `no-store`를 붙이고 있어 노출은 없었지만(실행으로 확인) **문서화된 규칙(비공개 화면은 헤더를 유지한다)을 설정이 지키지 않고 기본값에 기대고 있었다.** 두 주소를 목록에 더하고 회귀 시험(`server/private-headers.test.ts` 3개 — 옛 설정에서는 실패함을 확인)을 붙였다.
- **알게 된 것(고치지 않음, 운영자 결정/확인 항목)**: ① 공개 이용약관 · 개인정보 처리방침에 **궁합(사주 · 리포트) · 후기 · 추천/초대 · 포인트 · 질문권 · 파기 · 제3자 제공**에 대한 문구가 없다(구현은 돼 있고 판매 스위치만 꺼져 있다 — 켜기 전에 문구가 있어야 한다. 법률 검토 항목, 이 세션은 공개 처리방침을 고치지 않는다). ② 가장 작은 눌리는 영역: 머리글 링크 높이 40px · 푸터 링크 21px · 일부 버튼 24px(아래 모바일 장) — 실제 휴대폰 확인 때 같이 본다.
- **시험 도구의 낡음(제품 오류 아님)**: 이전 세션의 브라우저 시나리오가 성별 필수 입력 · 홈 첫 화면 카드 이름 · 심층 리포트 이름 변경을 반영하지 않아 처음에 2/16으로 실패했다 — 도구를 현재 화면에 맞게 고쳐 다시 돌렸다(아래 4장). 또 배포 빌드가 **빌드 시점의 환경값**으로 로그인 가능 여부(`isAuthConfigured`)를 정적 화면에 굳히므로, 배포 때 환경변수가 빌드 전에 들어 있는지 확인해야 한다(제품 동작은 정상, 배포 점검 항목).

### 0-1. 마무리 갱신 (같은 날 후반 · 이 문서의 5장이 상세)

- **출시를 막는 오류가 있는지 — 이번 마무리에서 새로 확인된 것은 없다.** 마무리에서 다시 돌린 시나리오의 실패는 **전부 시험 도구가 현재 화면 · 흐름을 몰랐거나 내 실행 설정이 틀린 것**으로 가려졌고(4-2장), **제품 코드는 이 마무리 동안 한 줄도 바꾸지 않았다**(바뀐 것은 문서뿐). 보안 · 열람 · 결제 검증은 낮추지 않았다 — 잠긴 내용의 서버 미전송 검사, 남의 결과 · 주문 접근 거절, 결제는 결제사 기록으로만 확정, 환불 뒤 두 사람 열람 차단, 관리자 화면의 개인정보(생년 · MBTI · 이메일 · 응답) 부재는 그대로 통과한다.
- **외부 테스트 DB 적용 사실 (운영자 · root 보고 — 개발 세션은 외부 DB에 접속하지 않았고 이 줄은 개발 세션이 직접 확인한 값이 아니다)**: Supabase `wdvrwwajakjdfrajgxcm`(운영자가 "미유 테스트 전용"으로 확정)에 SQL Editor에서 **23 → 24 → 26번만** 가드 포함 단일 트랜잭션으로 1회 실행해 `Success. No rows returned`를 확인했고, 사후 SELECT 검증 결과는 아래와 같다. **19~22번 · 25번은 적용하지 않았다.**
  - public 표 **22 → 24개**, 모든 표 RLS true. `pairs` · `compat_requests` 존재, 각각 **RLS true · 정책 0 · 행 0**.
  - `pairs.relationship`은 nullable text이고 `lover / engaged / some / married / friend / other` CHECK가 있다. 새 인덱스 4개와 `profiles`의 트리거 2개가 있다.
  - 새 함수 6개는 모두 `security definer` · `search_path=""` · **anon / authenticated 실행 권한 false**. 다만 **`service_role`의 실행 권한은 트리거 함수까지 6개 모두 true**(호스팅 기본 권한 영향)이고, 새 표 두 개에 대해 **anon / authenticated의 표 SELECT 권한도 true**로 나온다 — 그래도 RLS가 켜져 있고 정책이 0이라 **행 접근은 막혀 있다**. 이 권한 수치는 있는 그대로 적고 **기존 DB 권한은 임의로 바꾸지 않았다**(바꾸려면 운영자 승인).
  - 기존 데이터 UPDATE / DELETE 없음, 새 QA 행 없음. **외부 DB에서 통합 QA · 결제 · AI는 실행하지 않았다** — "외부 DB 적용은 완료, 외부 통합 QA는 미실행"이다.
- **확인 항목(제품 결함으로 판정하지 않음 — 요구가 분명하지 않은 UI 차이, 보안 · 열람 · 결제 검증 결과와 구분한다)**:
  1. **저장 전 미리보기(분석 직후 · 로그인 전)에는 개인 유형 카드(`나의 유형`)가 없다.** 저장된 결과 화면 · 심층 리포트 · 대화 카드 · 읽기용 글에는 있다. 유형 표시를 켠 지시(2026-10-19)의 표시 범위에 이 화면이 들어 있는지 문서로 확인하지 못했다 — 의도인지 누락인지는 운영자 결정 항목이다(고치지 않음, 새 기능을 더하지 않는다).
  2. **공개 개인정보 처리방침 문구**: 유료 질문 항목에 "결제 전에 적은 질문 글은 질문을 받을 수 있는지 확인하는 데에만 쓰고 보관하지 않으며"가 남아 있는데, 지금 구매 흐름은 질문을 먼저 적지 않고 구매한 뒤 적는다(결제 전에 적은 질문 글이 없다). 법률 문구라 고치지 않았고 `legal-review-list.md`의 확인 항목으로 둔다.

### 5-3. `pay-question`의 격리 조건 (실제 Anthropic · 외부 AI 연결 금지 지시에 따라)

이 시나리오만 `AI_PROVIDER=anthropic` 코드 경로(승인 가드 · 비용 기록)를 거친다. 그 코드는 `AI_BASE_URL`을 비우면 **기본값이 실제 Anthropic 주소**이므로 아래를 모두 갖춘 앱에서만 돌렸고, 갖춘 것을 매 실행 앞뒤로 확인했다.

- **실제 키 없음**: 앱 프로세스 환경에 `MIYU_ANTHROPIC_KEY`가 없고(0), `ANTHROPIC_API_KEY`는 가짜 문자열(28자, `fake-local-test-…`)이다. 실제 키의 값은 읽거나 출력하지 않았다. 세션이 쓰는 `ANTHROPIC_BASE_URL`도 앱에 넘기지 않았다.
- **목적지 강제**: `AI_BASE_URL=http://127.0.0.1:54600` — 코드(`lib/report/ai/live-config.ts`)가 `127.0.0.1` / `localhost` 주소가 아니면 호출하지 않고 설정 오류로 둔다.
- **외부 소켓 차단(2중)**: 앱 프로세스는 시험용 안전장치(`guard-loopback.cjs`, 저장소에 올리지 않음)로 `127.0.0.1` · `::1` · 유닉스 소켓 밖으로 소켓을 열 수 없다. 자체 시험에서 존재하지 않는 외부 이름이 소켓을 열기 전에 막히고 loopback은 통과함을 확인했다. 두 번의 실행에서 **막은 시도 0건**, 가짜 서버가 받은 요청은 10건씩(두 번째 실행 후 누적 20)이었다.
- 승인 `6/6` · 누적 4,314.89원 · `lib/config/ai-candidates.ts`는 그대로다.

### 5-4. 실행하지 않은 것 (정확히)

- **실제 AI 글**: 개인 심층 · 사주 궁합 · 리포트 궁합 모두 실제 AI 글 품질(Q-CMP-04)은 읽지 못했다.
- **실제 토스 테스트 키 · 결제 위젯 · 카드 인증 · 환불 실행**, **실제 카카오 로그인 복귀**, **실제 메일 발송**.

- **법률 · 개인정보 · 세무 검토** — 공개 약관 · 처리방침 문구 변경은 하지 않았고 법적 충분성은 판단하지 않았다(`legal-review-list.md`).

## 6. 테스트 사이트(miutest) 브라우저 관찰 후속 — MY 카드 제목 (2026-10-19)

- **발견(사용자 · root의 브라우저 관찰)**: MY에서 결제하지 않은 무료 결과 카드까지 제목이 "심층 리포트"로 보여 무료 결과와 구매한 리포트를 구분하기 어려웠다. 원인은 `getMyPage`(`lib/services/my-service.ts`)가 모든 개인 리포트 카드의 `productName`을 `PERSONAL_REPORT.name`으로 고정한 것이다(상태 배지 "무료 결과"는 따로 맞게 나왔다).
- **최소 수정**: 카드 `entitlement`를 먼저 정하고, 무료이면 `REPORT_TIER_NAMES.simple`("무료 리포트"), 구매 · 환불된 카드는 `PERSONAL_REPORT.name`("심층 리포트")을 쓴다. 결제 권한 · 상태 · 주문 이름 · 리포트 내용 · 다른 상품명은 바꾸지 않았다.
