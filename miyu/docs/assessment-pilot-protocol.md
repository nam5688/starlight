# 미유 성향 질문 — 시범 인터뷰 절차 (먼저 할 일)

- 상태: **절차 초안.** 문항 초안 0.2는 최종 검사가 아니라 시범용이다. 가상 응답 점검(`assessment-reliability-sim.md`)은 문항 구조의 한계만 보여 줄 뿐 사람이 질문을 어떻게 이해하는지는 알려 주지 못한다. **그래서 숫자를 더 만들기 전에, 몇 사람이 질문을 직접 풀고 "왜 이 답을 골랐는지" 말해 보는 것이 가장 가치 있는 다음 작업이다.**
- 목적은 정확도를 재는 것이 아니다. 질문이 의도한 뜻으로 읽히는지, 같은 답을 다른 이유로 고르는지, 정답처럼 보이는 선택지가 있는지, 고르고 싶은 답이 없는 문항이 있는지를 본다.
- 쓰는 도구: `docs/assessment-take.html` (채점 방향과 운영자 설명이 없는 풀어보기 화면). 다 풀면 검토 모드에서 문항마다 **질문을 어떻게 이해했는지 · 왜 이 답을 골랐는지 · 같은 행동을 다른 이유로도 할 수 있는지**를 적는 칸이 나온다. 결과(점수 · 유형)는 보여 주지 않는다.

## 1. 누구와 하나

- **5~8명.** 나이 · 하는 일 · 연애/가족 상황이 서로 다른 사람으로 고른다 (같은 모임의 비슷한 사람만 모으지 않는다). 운영자와 가까운 사람은 답이 좋은 쪽으로 기울 수 있으니 그 점을 인터뷰 메모에 적어 둔다.
- 참여는 자유이고 중간에 그만둘 수 있다고 먼저 알린다. 이름 · 연락처 · 직장 이름 · 가족 이야기의 구체적인 내용은 적지 않게 한다 (복사할 글에는 문항 번호와 한 줄 의견만 남는다).
- 이 단계의 응답은 **운영 데이터가 아니다.** 서비스 DB · 분석 도구에 넣지 않는다. 풀어보기 화면은 답을 그 사람의 브라우저에만 저장하고, 복사해서 전달한 글만 모은다.

## 2. 한 사람당 순서 (약 35~45분)

1. **소개 (3분).** "정답이 없고 진단이 아니에요. 질문이 이상한 곳을 찾는 중이에요." 좋아 보이는 답이 아니라 실제로 하는 쪽을 고르게 한다.
2. **풀기 (10분).** 풀어보기 화면에서 30문항을 푼다. 가능하면 곁에서 보되 개입하지 않는다. 오래 멈춘 문항을 메모해 둔다(화면이 문항별 시간을 기록한다).
3. **검토 모드 (10분).** 문항마다 해당하는 것만 표시한다: 정답이 뻔해 보임 · 둘 이상이 다 나 같음 · 뜻을 모르겠음 · 고르고 싶은 답이 없음.
4. **인터뷰 (15~20분).** 아래 질문으로 이야기를 나누고, 세 칸(이해한 방식 · 고른 이유 · 다른 이유)을 같이 채운다.
5. **복사해서 전달.** 복사할 글 탭의 "검토 내용 복사"로 만든 글을 채팅에 붙여넣는다. 응답 코드(내가 고른 답)를 같이 보낼지는 본인이 정한다.

### 꼭 짚어 볼 문항

| 문항 | 왜 짚나 |
| --- | --- |
| Q19 · Q20 | "더 맡는다 · 돕는다"는 같은 행동이 상대 사정을 고려해서인지 거절하기 어려워서인지. 점수에 넣지 않는 선택지(B)를 고른 사람의 설명이 정말 그 이유인지 |
| Q22 | "연락한다"는 행동이 마음이 쓰여서인지 약속 때문인지. 두 이유가 함께였던 사람은 어느 것을 골랐나 |
| Q05 | 낯선 자리 앞의 마음이 "새로움에 끌림"인지 "사교성 · 모임 부담"인지 |
| Q06 | 지적을 받은 날 신경 쓰이는 것이 "주변 반응"인지 "내용"인지 |
| Q14 · Q16 | "바로 한다 / 한 박자 쉰다"가 성향인지 그 상황의 사정(마감, 상사)인지 |
| Q24 · Q29 | 말을 늦게 꺼내는 이유가 정리할 시간인지 분위기가 나빠질까 봐인지 (점수는 속도만 본다) |
| Q23 · Q25 · Q28 | 혼자 시간이 필요한 마음이 "그 사람이 싫어서"로 읽히지 않는지 |

### 인터뷰 질문 (모든 문항에 같은 질문)

1. 이 질문이 무엇을 묻는다고 이해했나요? 내 말로 한 줄로 말해 주세요.
2. 왜 이 선택지를 골랐나요? 최근에 실제로 있었던 일이 있었나요?
3. 같은 행동을 다른 이유로 고르는 사람도 있을 것 같나요? 어떤 이유일까요?
4. 정답처럼 보이는 선택지가 있었나요? 왜 그렇게 보였나요?
5. 고르고 싶은 답이 없었다면, 실제로는 어떻게 했을 것 같나요?
6. 다른 문항과 같은 것을 묻는 것 같은 문항이 있었나요? (같은 성향을 다른 장면에서 묻는 것은 의도한 것이다. 그 느낌이 어땠는지를 듣는다.)

## 3. 무엇을 보고 고치나

인원이 적어서 **통계가 아니라 고칠 단서**로 읽는다. 아래 숫자는 근거가 있는 기준이 아니라 **시범용으로 정한 시작 기준**이다.

| 관찰 | 고치는 방향 |
| --- | --- |
| 한 문항을 2명 이상이 의도와 다르게 이해함 | 질문 문장을 다시 쓴다 |
| 같은 선택지를 다른 이유로 고른 사람이 2명 이상 | 이유를 선택지에 나눠 적고 목표 관점의 이유가 아닌 답은 점수에 넣지 않는 방식을 검토한다 |
| 한 선택지가 "좋은 답"처럼 보였다는 사람이 3명 이상 | 그 선택지(또는 반대쪽)를 고쳐 어느 쪽도 좋아 보이지 않게 한다 |
| "고르고 싶은 답이 없었다"가 2명 이상 | 선택지를 보완한다. 실제로 했을 행동을 그대로 적은 말을 쓴다 |
| 한 사람이 같은 이유로 여러 문항을 고름 | 그 이유가 별도의 관점(예: 갈등을 피하려는 마음)일 수 있다는 단서로 적어 둔다 |
| 장면(연애 · 가족 등) 때문에 답이 달라진다는 말이 반복됨 | 그 관점은 장면에 따라 다르게 읽는다는 뜻이다. 한 점수로 합치지 않고 장면별 응답을 그대로 보여 준다 |

**시뮬레이션 숫자를 올리려고 문항을 고치지 않는다.** 숫자가 좋아지는 방향(예: 선택지를 더 극단으로)이 사람에게는 더 부자연스러울 수 있다. 문항은 사람이 이해한 방식을 근거로만 고친다.

## 4. 고친 뒤

1. 고친 문항만 **다른 2~3명**에게 같은 방식으로 다시 확인한다 (이미 본 문항은 처음 보는 눈이 아니다).
2. 모자란 관점(T2 · T3 · T4 · T5 · C2 · C3 · R3 · R4)의 보강 후보 9문항(`lib/assessment/drafts/reinforcement-candidates.ts`, `assessment-design-v1.md` 11장)은 **이 인터뷰 결과를 보고** 쓸지 · 고칠지 · 바꿀지 정한다. 풀어보기 화면에는 후보가 들어 있지 않으므로, 후보를 직접 시험하려면 후보를 넣은 풀어보기 화면을 따로 요청한다.
3. 다음 단계는 **고친 문항으로 시범 응답**(수십 명)이다: 해당 없음 비율 · 이유 선택지를 고른 비율 · 끝까지 답한 비율 · 관점 간 상관을 본다. 이어서 2주 뒤 같은 사람의 재응답 일치를 본다.
4. 12유형은 이 과정이 끝나고 **별도로 검증하기 전에는** 화면에 연결하지 않는다.

## 5. 하지 않는 것

- 풀기 전에 결과의 점수 방향이나 유형 이름을 알려 주지 않는다.
- 풀고 난 뒤 "당신은 이런 유형"이라고 돌려주지 않는다 (이 단계는 문항 점검이다).
- 인터뷰 내용을 운영 DB · 광고 · 분석 도구에 넣지 않는다. 적은 글의 개인 정보는 전달하기 전에 지운다.
- 이 인터뷰 결과를 "정확도" 또는 "검증 완료"라고 표현하지 않는다.
